# Design

## Context

Мотивация и решения владельца — в `proposal.md`. Здесь то, что определяет подход.

- Набор пар даёт `InstrumentCatalog.Parse` из `GET api/instruments/bybit` сервиса данных: Linear, LinearPerpetual,
  USDT, Trading, не делистингован — 834 пары. `Instrument` — это `(Id, Symbol)`; его читают превью, прогоны, сканер,
  лента `GrpcMarketFeed` (событие `MarketPairs`), страница пары и живая свеча.
- Сервис данных до изменения `add-instrument-symbol-type` типа Bybit не отдаёт. После него у описания инструмента —
  `symbolType`: строка `Stock`, `Etf`, `Commodity`, `Forex`, `XStocks`, `Innovation`, `Adventure` или `null` (тип пуст
  или неизвестен его SDK; Bybit.Net 7.7.0). Числа 2026-11-25 по публичному списку Bybit: среди 834 пар пусто 406,
  `innovation` 110, `stock` 248, `ETF` 62, `commodity` 4, `forex` 4.
- Снимок рынка ведёт `MarketBook` по символу и пишет целиком в `market_pairs` (ключ — `symbol`). Список идей,
  сводка журнала и число идей по стратегиям строят один `WHERE` в `IdeaRepository.Where` и уже соединяют идею с
  `market_pairs m` по символу (для полей рынка сохранённых фильтров). Список пар строит свой `WHERE` в
  `MarketPairRepository.Where`.
- Выборы над таблицами живут в `useState` страниц и сбрасываются при перезагрузке; в браузере помнится только
  выбранный сохранённый фильтр, по месту.
- v2 делал то же («Скрыть акции»): `IsTradFi(symbolType)` = Stock, XStocks, Etf, Commodity, Forex и столбец
  `scanner_pairs.tradfi`.

## Goals / Non-Goals

**Goals:**

- Вид пары — одно правило в домене; его применяют каталог, снимок и все списки.
- Выбор вида проходит через тот же путь, что «ТФ» и «Сторона»: запрос → `IdeaListQuery` / `MarketListQuery` → общий
  `WHERE`. Число идей по стратегиям и сводка журнала получают его без отдельного кода.

**Non-Goals:**

- Спот, срочные контракты и USDC-контракты в наборе пар.
- Вид у идеи в таблице `ideas`: идеи не меняются.
- Поле вида в сохранённых фильтрах и в `GET /api/filters/fields`.

## Decisions

### 1. Два вида: `crypto` и `stock`, правило в домене

`InstrumentKind` — `Crypto` или `Stock`. Правило `InstrumentKinds.Of(symbolType)`: `Stock`, `Etf`, `Commodity`,
`Forex`, `XStocks` → `Stock`, всё остальное, `null` и незнакомая строка → `Crypto`. Сравнение без учёта регистра:
Bybit пишет `ETF`, SDK — `Etf`.

Альтернатива — отдать во все списки сырой тип Bybit и выбор по нему. Отвергнуто: владелец выбрал три значения, а тип
Bybit меняется без нас (появились `ETF`, `forex`); правило в одном месте держит выбор стабильным. Незнакомый тип —
«крипта», как в v2: лучше лишняя пара в крипте, чем пропавшая.

### 2. Вид едет с инструментом

`Instrument` получает третье поле `Kind` со значением по умолчанию `Crypto`, чтобы прежние вызовы и тесты с двумя
полями не менялись. `InstrumentCatalog.Parse` читает `listing.symbolType` и ставит вид по решению 1; отбор 834 пар не
меняется. Набор пар, его обновление раз в час и событие `MarketPairs` остаются как есть — вид приходит в них сам.

Альтернатива — отдельный порт «виды пар» или свой запрос каталога. Отвергнуто: это тот же ответ каталога, который уже
читается, и второй его разбор дал бы два набора пар.

### 3. Вид хранится в снимке рынка

`MarketBook` запоминает вид каждой пары из последнего `MarketPairs`; `MarketPair` получает `Kind`; `market_pairs`
получает столбец `kind text NOT NULL DEFAULT 'crypto'` с проверкой `IN ('crypto', 'stock')`. Снимок пишется целиком раз
в минуту, поэтому значение по умолчанию живёт не дольше первой записи после миграции.

Выбор вида в списке идей — условие `m.kind = @Kind` в `IdeaRepository.Where`, в списке пар — `kind = @Kind` в
`MarketPairRepository.Where`. Идея пары, которой нет в снимке (сняли с торгов), даёт `m.kind IS NULL` и под выбор не
подходит (спец `strategy-ideas`, сценарий «Пары больше нет в наборе»).

Альтернатива — писать вид в каждую идею при рождении. Отвергнуто сейчас: нужна миграция с заполнением 61 тыс. идей
базы `bench_ideas` по текущему снимку, а выигрыш — только журнал снятых пар. Можно добавить позже без смены API.

### 4. Параметр `kind` в API

`kind` — необязательный параметр запроса `GET /api/market/pairs`, `GET /api/ideas`, `GET /api/ideas/summary` и
`GET /api/ideas/strategies` со значениями `crypto` и `stock`; другое значение → `422` с ошибкой `InvalidChoice` у поля
`kind`, как у неизвестной стороны. `GET /api/market/pairs/{symbol}/ideas` параметра не получает (решение владельца о странице пары).
`MarketPairResponse` и строки списка пар получают `kind`. Имена значений — латиницей, как `long`/`short` у стороны;
слова «крипта» и «акции» — только на экране.

### 5. Один выбор на три таблицы, в браузере

Хук `useInstrumentKind()` в `frontend/src/modules` читает и пишет ключ `profit-fox.instrument-kind` в `localStorage`
(значения `crypto`, `stock`, пусто — все), каждый доступ в `try/catch`: без хранилища — «все». Слушает событие
`storage`, чтобы вторая вкладка тоже узнала. «Рынок» и обе вкладки «Идей» берут значение из хука, а не из своих
`useState`; смена вида возвращает таблицу на первую страницу, как другие выборы.

Выпадающий список «Вид» — в `IdeaChoiceRow` для `open` и `closed` (не для `pair`) после «Сторона» и в ряду выборов
`MarketPage`. Подписи: «Вид: все», «крипта», «акции».

Альтернатива — вид в адресе страницы. Отвергнуто: владелец выбрал «помнить», а адреса других выборов в проекте нет.

### 6. Пометка на странице пары

Страница пары показывает рядом с символом «крипта» или «акция» из `kind` ответа `GET /api/market/pairs/{symbol}`,
спокойным серым словом, как подписи под ценой. Таблица идей пары выбор вида не читает.

## Risks / Trade-offs

- [Сервис данных ещё без `symbolType`] → все пары «крипта», выбор «акции» пуст. Порядок выката — сервис данных первым
  (Migration Plan); на dev-стенде проверить, что `GET api/instruments/bybit` отдаёт тип, до проверки экранов.
- [Bybit назовёт новый тип, например `bond`] → он станет «криптой» до правки правила. Тест правила перечисляет все
  известные значения; появление незнакомого типа видно по числу пар вида «акции».
- [Журнал снятых пар пропадает при выборе вида] → принято (решение 3); без выбора они видны.
- [Вид читается каталогом раз в час] → смена типа Bybit доходит до снимка не позже часа; спец требует «вместе с
  каталогом», не сразу.

## Migration Plan

1. Выкатить `add-instrument-symbol-type` в `profit-fox-market-data` и пересинхронизировать каталог Bybit (linear).
2. Выкатить это изменение: миграция добавляет столбец `kind` со значением по умолчанию; первый снимок после старта
   записывает настоящие виды.
3. Откат: старый код не читает `kind`; столбец можно оставить.
