# Tasks

Тесты бэкенда запускаются из `backend/`: `dotnet test ProfitFox.slnx`; фронтенда — из `frontend/`: `npm test`, `npm run
typecheck`, `npm run lint`, `npm run format:check`, `npm run build`. Каждая задача начинается с теста, который без неё
падает, и каждая группа заканчивается зелёным прогоном всех тестов своей части.

Ожидания не правятся ни в одной задаче: `EngineVersionTests` с `Fixtures/EngineVersions.json`, `H0001ParityTests`,
`H0001StrategyParityTests`, `SignalNodeParityTests`, `OutcomeParityTests`, `PreviewParityTests`, `CycleRunTests`,
`PositionRunTests`, `PairPositionTests`, `PairOrdersTests`. `EngineVersion.Number` остаётся `3`. Если задача требует
иного — остановиться и записать это в «Открыто после применения».

Порядок групп — порядок работы. Слои и папки — по README, «Слои». Макеты — `mockups/`; три отличия от них названы в
`proposal.md`.

  «The output of a signal is an event or a boolean.». `Signal.Output` по-прежнему имя выхода (на нём стоит прежний тест
  `GraphReadingTests`); тип несут новые `Signal.OutputType` и `Signal.IsState`. Прежний тест
  `GraphValidationTests.The_output_of_a_signal_is_an_event`, по которому логический выход был ошибкой, противоречил
  изменённому сценарию «Выход сигнала не событие» и переписан на числовой выход. Задача называет `GraphValidatorTests`;
  тесты проверки графа в репозитории — `GraphValidationTests`.
- **3.2, исполнитель сигнала.** `SignalExecutor.Value` даёт значение выхода на свече (у сигнала-события — случилось ли
  событие); `SignalExecutor.Step` у сигнала-состояния даёт событие на переходе выхода в истину. Каждый вызов двигает
  прогон пары на свечу, поэтому у пары зовут что-то одно.
- **3.3, поле `output`.** Тип выхода версии сигнала отдаётся полем `output` (`event`, `boolean`, `null` у ненайденной
  версии) в `SignalUseResponse` (ответы стратегии и проверки) и в строке списка сигналов `SignalListItem`: по нему
  редактор рисует выход `value` и «Создать стратегию» ставит `first-time`. Ожидания трёх прежних тестов записи списка
  сигналов (`SignalInternalConverterTests`, `GetSignalsQueryHandlerTests`, `SignalRepositoryTests`) и одного теста
  страницы (`signals.test.ts`) дополнены новым полем `output = event`; остальное в них не менялось.
- **3.5, объявление выхода.** Тип выхода сигнала выбирается в карточке «Параметры» редактора сигнала (поле «Тип выхода
  сигнала»): отдельной карточки выходов в редакторе нет. Смена типа снимает провод, шедший в выход.

- **4.1, противоречие: «сравнение с ними ложно».** Сценарий spec `strategy-execution` «Свечи названной пары нет»
  говорит: «выходы узла — отсутствующие значения, и сравнение с ними ложно». Выпущенный узел `compare` при отсутствующем
  входе даёт отсутствующее значение, а не ложь (основная spec `strategy-execution`, «Отсутствующие значения»: «Сравнение
  с отсутствующим значением SHALL давать отсутствующее значение»), и выпущенный вид узла менять нельзя. Узел
  `pair-candle` сделан, все четыре сценария проверены (`PairCandleNodeTests`), но тест второго сценария проверяет то,
  что даёт движок: сравнение отсутствует, то есть не истинно, и «впервые» после него события не даёт. Задача 4.1 не
  отмечена: нужно решение — поправить формулировку сценария («сравнение с ними не истинно») или иное.
- **4.1, настройка `symbol`.** Пара пишется заглавными латинскими буквами и цифрами (`BTCUSDT`, `1000PEPEUSDT`); пустая
  или иная строка — `InvalidSetting` по настройке `symbol`, отсутствующая — `MissingSetting`. Название узла — «Свеча
  пары», группа «Данные». Ожидания прежних тестов каталога (`NodeCatalogTests`: перечень видов, пины, свободные

- **7.2, расчёт цикла идеи.** Ход идеи по минутам — `Domain/Services/Ideas/IdeaCycle`: правила минуты те же, что у
  `CycleRun.Simulate` (`CycleRun.MarketFill`, `StopHit`, `TargetHit`, `StopExit`), итог считает сам `CycleRun`
  (`Open`, `Close`, `Outcome`) на пути, где накопленный фандинг идеи лежит одной выплатой. Подачу минут по одной в сам
  `CycleRun` открывать не пришлось. «Сейчас» — итог идеи, закрытой по последней цене минуты, с проскальзыванием и
  комиссией выхода. Идея без единой минуты со сделками до конца срока исключается с причиной «нет сделок» — третья
  причина, кроме двух из spec: так прогон исключает сделку `NoTrade`. Цена выхода хранится до проскальзывания
  (`Idea.ExitRaw`, колонка `exit_price`).
- **7.3, сверка с прогоном.** `IdeaParityTests` сверяет идею с `CycleRun.Simulate` (его зовёт `Cycle.Open` прогона) на
  1017 сделках эталонных путей `Trades/Fixtures/Outcomes` с итогом `Ok`: цена и время входа, время и причина выхода,
  неоднозначность — точно; итог долей — с допуском `1e-15`, в USDT — `1e-13`. Путь прогона считает фандинг разностью
  накопленных сумм с начала своего окна, идея — суммой выплат после входа; при нескольких выплатах они расходятся в
  последнем бите (например `0.054472395105354066` против `…059`). Цены минут переводятся в `double` через их десятичный
  текст, как читает историю прогон: прямое приведение `decimal → double` давало другую цену входа.

- **8.3, правило одной открытой идеи.** Открытая идея стратегии на паре и таймфрейме останавливает заявку, если её выход
  (известный или конец срока) позже закрытия свечи: идея, вышедшая по сроку на этой же свече, новой не мешает («После

## Workflow follow-up

- Коммиты, отправка ветки и PR — по слову владельца на каждый шаг.
- Применение идёт в отдельной облачной сессии; основная сессия проверяет ветку, группу 17 и открывает PR.
- Ветка сливается в `release/0.1.0` после `feat/add-strategy-backtest` (PR #26).
- Архив — после архива `add-strategy-backtest`: дельта `strategy-backtest` меняет требование, которое до него живёт
  только в том изменении. Перед архивом проверить изменение на синхронных спеках: каждое требование блока MODIFIED
  держит все имена сценариев основной спецификации.
