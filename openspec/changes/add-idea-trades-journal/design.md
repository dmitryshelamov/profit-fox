# Design

## Context

Что уже есть после `take-idea-trades` (PR #46):

- **Сделка.** `IdeaTrade` копирует из идеи сетап, ТФ, тип, сторону, стоп и цель. Хранит `IdeaId` без FK: сделка живёт
  дольше идеи. Результат в USDT и R вычисляется в сущности и не хранится. Время первого исполнения входа отдельно не
  хранится: `StatusAt` переписывается при каждой смене статуса.
- **Хранение.** `idea_trades` и её ордера, дети и исполнения. Worker сохраняет сделку одним `UPDATE` всех колонок
  (`IdeaTradeRepositoryQueries.Save`) и узнаёт о запросах владельца по `updated_at` (`GetChanged`).
- **Список.** `GET /api/idea-trades` отдаёт все сделки от новых к старым (`GetAllAsync`), без страниц и фильтров.
- **Расчёт входа.** `IdeaTradeEntryCalculator` берёт идею, последнюю цену Bybit (`IMarketHistoryClient.GetLastPriceAsync`)
  и комиссии по умолчанию. Статистику корзины он не читает. R:R после комиссий есть в `IdeaTradeSize.RiskReward`,
  безубыток — в `IdeaShares.BreakEven`.
- **Корзины.** `IIdeaBucketRepository.GetAsync(version)` и `IdeaView.Of` дают идее статистику 90 и 30 дней и значок, как
  на «Идеях».
- **Живые идеи.** Статусы меняет сканер: `LiveIdeas.RunAsync` → `IdeaRepository.SaveAsync`, одна транзакция на минуту.
  Итог в R у живой идеи не считается, его считает только прогон (`CaseResult.R`). Закрытые идеи удаляются через 7 дней
  (`LiveIdeas.RemoveClosedAsync`, раз в час).
- **Листание.** `Application/Paging` (`PageRequest`, `Page<T>`) — 50/100/200, отбор и срез в памяти, как у «Идей».
  На фронте `Pager`, `pageSizes` и выбор экрана в браузере.

Почему меняем — см. proposal.md. Решения владельца — в `/grill-me` 2026-11-06.

## Goals / Non-Goals

**Goals:**

- Видеть по каждой сделке, что обещала идея при входе, чем закончилась сделка и чем — её идея.
- Итоги по фильтру отвечают на вопросы: зарабатывает ли торговля идеями, сбывается ли обещание и сколько стоит
  исполнение.
- Обещание и исход идеи на сделке не зависят от пересчёта корзин, чистки идей и правок 2.1.

**Non-Goals:**

- Исходы идей, по которым не входили (это «Калибровка»).
- Деление на авто и ручные сделки, кривая капитала, выгрузка.
- Изменение жизни сделки, её ордеров и сверки.

## Decisions

### 1. Обещание — колонки сделки, пишутся при создании

`idea_trades` получает колонки обещания, все `NULL`:

| колонка | что |
|---|---|
| `promised_badge` | `up` / `flat` / `down`, `NULL` при «мало данных» и без корзины |
| `promised_probability` | вероятность корзины 90 дней, `NULL` при «мало данных» |
| `promised_expectancy` | ожидание в R |
| `promised_cases` | N корзины |
| `break_even` | безубыток от цены входа сделки |
| `net_risk_reward` | R:R после комиссий от цены входа сделки |

Домен: value object `IdeaPromise`, у `IdeaTrade` поле `Promise` (`null` у старых сделок). `IdeaTrade.Create` получает
его готовым.

`IdeaTradeEntryCalculator.PrepareAsync` читает корзины текущей версии (`IIdeaBucketRepository`, `IdeasEngineVersion`) и
берёт статистику идеи тем же `IdeaView.Of`, что и `GET /api/ideas`. Поэтому обещание совпадает с тем, что владелец видел
в таблице. Безубыток и R:R считаются от цены входа сделки, а не от цены идеи: у входа по рынку это текущая цена.

Колонки пишет только `INSERT` создания. `UPDATE` Worker'а (`Save`) их не перечисляет, так что обещание не меняется.

Отвергнуто:

- Снимок в jsonb. Фильтр по значку и средние по обещанию проще по колонкам.
- Пересчёт обещания при чтении по корзинам на момент входа. Корзины хранятся только текущие.

### 2. Исход идеи пишет сканер в транзакции минуты

Колонки `idea_status` (`target` / `stop` / `expired`), `idea_status_at`, `idea_result` (R, `NULL` у идеи без входа).
Домен: value object `IdeaOutcome` на сделке.

`IdeaRepository.SaveAsync` в той же транзакции после `UPDATE ideas` выполняет для идей, которые в эту минуту
закрылись:

```sql
UPDATE idea_trades SET idea_status = @Status, idea_status_at = @StatusAt, idea_result = @Result
WHERE idea_id = @IdeaId AND idea_status IS NULL
```

Итог в R считает `LiveIdeas` через `CaseResult.R` с комиссиями категории, как прогон. Сканер пишет в чужую таблицу, но
только в три свои колонки. `updated_at` он не трогает: по нему Worker ищет запросы владельца, и лишняя перечитка сделки
не нужна. Worker эти колонки не пишет.

**Догонка.** При старте сессии сканера один запрос заполняет исход сделкам, у которых его нет, а идея уже закрыта и ещё
хранится. Он берёт идеи из `ideas`, итог считает в C#. Так получают исход сделки, взятые до выкатки, и сделки, чья
минута закрытия упала до записи.

Связь с 2.1. Если 2.1 поменяет срок жизни или статусы идеи, на сделку попадёт тот исход, с которым идея закрылась. Новые
статусы потребуют расширить `idea_status` — это задача 2.1, а не журнала.

Отвергнуто:

- Держать идеи со сделками дольше 7 дней. Тогда пришлось бы менять чистку, а исход идеи зависел бы от того, что 2.1
  сделает с `ideas`.
- Копировать при чистке, раз в час. Исход появлялся бы с опозданием до часа.

### 3. Время открытия

Колонка `opened_at`. Её ставит `IdeaTrade.EntryGrown` при переходе «Ждёт входа» → «Открыта» (это время первого
исполнения), и `Save` её пишет. Миграция заполняет её у старых сделок по самому раннему исполнению ордера входа
(`idea_trade_fills` ⨝ `idea_trade_orders` с ролью входа). Время до исхода = `StatusAt` закрытия − `opened_at`, считается
при чтении.

### 4. Журнал — один запрос, отбор и итоги в памяти

`GET /api/idea-trades` заменяет список. Параметры: `Setup`, `Symbol`, `Side`, `Badge` (`up`/`flat`/`down`/`none`),
`Days` (7/30/90, без него — всё время), `Page`, `PageSize`. Ответ:

```
{ open: [IdeaJournalTrade], closed: { items, page, pageSize, total }, totals: IdeaJournalTotals }
```

Обработчик `GetIdeaJournalQueryHandler` читает все сделки (`GetAllAsync`), отбирает в памяти, сортирует закрытые по
`StatusAt` от новых и режет страницу `PageRequest.Slice`. Сделок по идеям — сотни, не миллионы: это ручные входы с
пределом открытых. Если авто-режим их размножит, отбор переедет в SQL без смены API.

Итоги считает чистая функция домена `IdeaJournalTotals.Compute(trades)` по всем закрытым сделкам фильтра. Интервал —
среднее ± 1,96 · s / √N, как у корзин. При N = 1 интервала нет, при N = 0 нет среднего. Сравнения «обещали → получили» и
«идеи → сделки» считаются в ней же, каждое по своему подмножеству.

«Без значка» отбирает и «мало данных», и сделки без обещания: для владельца это одно — входили не на значок.

Отвергнуто:

- Два запроса, «в работе» и «журнал». Экрану нужно одно обновление раз в 15 секунд, а фильтры общие.
- Итоги в SQL. При отборе в памяти пришлось бы держать две реализации фильтра.

### 5. Текущий результат по последней цене Bybit

Для открытых сделок обработчик спрашивает `GetLastPriceAsync` по каждому их символу, один раз на символ. Открытых
сделок не больше предела «Не больше открытых сделок» (по умолчанию 5), так что при опросе раз в 15 секунд это
единицы запросов в минуту. Ошибка или отсутствие цены дают сделке пустой текущий результат, а не ошибку журнала.

Текущий результат — функция сущности `IdeaTrade.ResultAt(price, takerPercent)`: уже вышедшая часть плюс остаток
(`HeldQuantity`), закрытый по `price` с комиссией taker, минус комиссия входа. R — делённое на риск.

Отвергнуто: цена из снимка рынка сканера. Она отстаёт до минуты, а по сделке с реальными деньгами владелец ждёт
текущую цену.

### 6. Экраны

- `pages/idea-trades/IdeaJournalPage.tsx` на `/idea-trades`. Это фильтры, группа «В работе», итоги и таблица закрытых
  сделок с `Pager`. Номер страницы в `?page=` (`pageOf` в маршруте), выбор экрана — в браузере (ключ
  `profit-fox.idea-journal.choice`), как у «Идей».
- `pages/idea-trades/IdeaTradingSettingsPage.tsx` на `/idea-trades/settings` переиспользует `SettingsPanel`.
- Модуль `idea-trades`: `api.ts` (`ideaJournalQuery`, `keepPreviousData`, 15 с), `model/journal.ts` (подписи итогов,
  времени, обещания), `ui/OpenTradesTable.tsx`, `ui/ClosedTradesTable.tsx`, `ui/JournalTotals.tsx`. `TradesTable`
  уходит. Значок и подписи ожидания берутся из `@/modules/ideas` (`badgeSymbol`, при нужде добавить в `index.ts`).
- Меню: «Сделки» → «Журнал». Окно входа после создания ведёт на `/idea-trades`, как и раньше.

## Risks / Trade-offs

- [Две записи в `idea_trades` из двух процессов] → сканер и Worker пишут разные колонки, сканер не трогает
  `updated_at`. Тест хранения: `Save` Worker'а после записи исхода сканером исход не стирает.
- [Обещание посчитано на корзинах, которых владелец не видел] → корзины пересчитываются раз в 10 минут, окно входа
  открыто секунды. Расхождение возможно на одном пересчёте, это приемлемо.
- [Малые N в итогах] → интервал R показан всегда, при N = 1 его нет. Выводы по журналу в первые недели ненадёжны.
- [Опрос Bybit с API на каждое обновление журнала] → один запрос на символ открытой сделки. Ошибка не ломает журнал.
  Запросы идут через тот же клиент, что и окно входа.
- [Отбор в памяти] → при тысячах сделок ответ растёт линейно. Перенос в SQL — без смены API.
- [Ветка поверх `feat/take-idea-trades`] → после squash-мержа #46 ветку перебазировать на `main` (`git rebase --onto`).

## Migration Plan

1. Мерж PR #46, перебазирование этой ветки на `main`.
2. Миграция `AddIdeaTradeJournal` (номер после `202611070006`): колонки обещания, исхода идеи и `opened_at`, заполнение
   `opened_at` по исполнениям. Обещание у старых сделок остаётся `NULL`.
3. Выкатка обычная (`deploy.yml`, Approve). При старте сканер догоняет исход идеи у старых сделок, чьи идеи ещё
   хранятся.
4. Откат: колонки `NULL`-допустимые, старый код их не читает.
