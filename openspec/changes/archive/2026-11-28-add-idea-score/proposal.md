# Proposal

## Why

Метки уже говорят о состоянии рынка в момент идеи: «↓ BTC 4h», «оборот ↑ 1h», «фандинг ↓» и ещё 47 на проде. Но они
только показываются и отбирают идеи. Владелец хочет сложить их в балл: «давай вводить бальную систему», «пока функция
в продукте», «но потом уже и для автоторговли». Чтобы позже решать, давать ли баллу деньги, с первого дня нужно видеть,
как закрываются идеи с разным баллом.

Проверки баллов на истории 2026-11-27 (вычисленные веса, веса из учебника и подобранные веса на 4h) не прошли. Поэтому
балл здесь — инструмент владельца для просмотра идей, а не обещание прибыли. Денег на нём нет, пока веса не заморожены
и итоги не посчитаны вперёд.

Решения владельца в обсуждении 2026-11-27:

- балл складывается из меток: «Веса на метки»; вес метки один для всех стратегий: «Один для всех»; веса отдельно для
  лонга и для шорта;
- балл считается по текущим весам, а не закрепляется в момент идеи: «По текущим весам»;
- итоги по баллу — сразу, в первой версии: «Да, сразу»;
- отдельная страница: «отдельную страницу со скоринг системой, где у нас будет таблица меток и их значения в скоринг
  системе», итоги по баллу — на ней же: «Да, ставь на страницу «Скоринг»»;
- в «Идеях» колонка балла с сортировкой и фильтром: «Да, с фильтром»;
- узел OI — «давай вместе со скорингом», с метками на `5m`, `15m`, `1h`, `4h`: «а версии для 5m 15m 1h?»;
- объём покупок у свечи — «Да, вместе».

## What Changes

- **Веса меток.** У каждой метки сигнала и у «⚡ всплеск» два целых веса: для лонга и для шорта, от −3 до +3, по
  умолчанию 0. Вес привязан к тексту метки, потому что идея хранит метки текстом. При смене текста метки вес переходит
  на новый текст.
- **Балл идеи** — сумма весов её меток по её стороне, по текущим весам. Смена веса сразу меняет балл всех идей, открытых
  и закрытых.
- **Страница «Скоринг»** — шестой раздел шапки. Таблица меток с таймфреймом и двумя весами, правка веса в строке.
  Ниже — итоги закрытых идей по баллу: балл, число идей, доля в плюс, средний итог после издержек, сумма в USDT, с
  выборами и периодом журнала.
- **Балл в «Идеях».** Колонка «Балл» во вкладках «Открытые» и «Журнал» и в таблице идей пары, сортировка по ней,
  выбор «Балл от» над таблицей. Поле «балл» в сохранённых фильтрах.
- **Узел `open-interest`** — «OI»: открытый интерес пары на последней точке раньше закрытия свечи, как узел фандинга.
  OI получают прогрев и живой сканер, прогон, предпросмотр сигнала и стратегии. История OI читается только для графов,
  в которых есть этот узел.
- **Выход `buyVolume` у узла «свеча»** — объём сделок, начатых покупателем. Свеча без известного объёма покупок хотя
  бы в одной минуте со сделками даёт отсутствующее значение. Живая лента минут начинает нести объём покупок.

Чего в изменении нет:

- самих меток OI и объёма покупок в базе: их создают руками через API после выкладки, как остальные 50;
- заморозки весов, счёта вперёд и автоторговли по баллу;
- весов по стратегиям и дробных весов;
- меток и балла на «Рынке» и на странице пары вне таблицы идей;
- выхода `buyVolume` у узла `pair-candle`.

## Capabilities

### New Capabilities

- `idea-score`: веса меток, балл идеи, страница «Скоринг» с итогами по баллу, балл в списках идей.

### Modified Capabilities

- `strategy-execution`: узел «свеча» выдаёт `buyVolume`; новый узел «OI» и правило, какая точка OI видна на свече.
- `market-history`: стенд читает историю OI потоком `History`.
- `market-live-feed`: минута ленты несёт объём покупок, свеча таймфрейма суммирует его; прогрев берёт и OI.
- `saved-filters`: в перечне полей идеи появляется «балл».
- `bench-ui`: в общей шапке шесть разделов, шестой — «Скоринг».

## Impact

- База: новая таблица весов меток, миграция FluentMigrator; балл считается в SQL при чтении списков, сводки и фильтров.
- API: `GET`/`PUT` весов меток, `GET /api/ideas/scores`, поле `score` в ответе идеи, сортировка `score`, выбор
  `minScore`, поле фильтра `score`, новый узел и новый выход узла в каталоге.
- Движок: `NodeContext` и подписи `Step` исполнителей несут OI; `ClosedCandle` несёт объём покупок. `EngineVersion`
  остаётся `4`: на прежних графах ни одна сделка не меняется.
- Данные: `IHistorySource` и кэш истории получают OI; `IRecentHistory` отдаёт OI прогреву; `MarketBook` хранит точки
  OI за сутки и объём покупок минут.
- Фронтенд: страница и маршрут «Скоринг», колонка и выбор в «Идеях», новые типы из OpenAPI.
- Нагрузка: 18 новых меток на 839 парах в сканере и чтение OI при прогреве пар с такими метками.
