# Proposal

## Why

Боту для живой торговли (изменение 5) нужен аккаунт Bybit, от имени которого он ставит ордера. Сейчас в системе нет
ни ключей биржи, ни понятия аккаунта, и бот ни с каким аккаунтом не связан. Это изменение даёт владельцу хранить
ключи Bybit в зашифрованном виде, проверять их у биржи при добавлении и привязывать к аккаунту бота, чтобы изменение 5
получило готовую связь «бот → аккаунт» и аккаунт testnet для проверки без реальных денег.

## What Changes

- Аккаунт биржи: имя, окружение Bybit (основная сеть или testnet), API key и secret. Список, создание, переименование
  и удаление. API key показывается целиком, secret никогда не возвращается: интерфейс показывает вместо него маску.
  Сменить ключ — значит удалить аккаунт и создать новый.
- Secret хранится в базе зашифрованным AES-256-GCM под мастер-ключом из настроек. Мастер-ключ по умолчанию лежит
  только в `appsettings.Development.json` (и свой — в `appsettings.Testing.json`); в остальных окружениях API без
  мастер-ключа не стартует. На проде мастер-ключ задаётся переменной окружения.
- Проверка ключа у Bybit при создании: ключ, который Bybit не принимает, ключ только для чтения, ключ без права на
  торговлю, ключ с правом на вывод средств и ключ не единого торгового аккаунта (UTA) отклоняются. Сохраняются UID
  аккаунта Bybit и категории рынка, в которых ключ может торговать. Один UID в одном окружении нельзя добавить дважды.
- Баланс аккаунта читается с Bybit по запросу и нигде не хранится.
- Бот получает необязательный аккаунт. Бот с аккаунтом, ключ которого не торгует в категории инструмента бота,
  отклоняется. Аккаунт, к которому привязаны боты, удалить нельзя. Запускать ботов по-прежнему нельзя.
- Интерфейс: раздел «Аккаунты» в шапке (список, форма нового аккаунта, страница аккаунта с балансом, переименованием и
  удалением), поле «Аккаунт» в форме бота, аккаунт и метка testnet на странице и в списке ботов.
- Заглушка Bybit для e2e отвечает на запросы о ключе и балансе.
- Вход и пользователи не добавляются: API остаётся открытым локальной сети, как сейчас. Это решение владельца с
  принятым риском.

Вне изменения: запуск и остановка ботов, ордера, сверка с биржей, другие биржи, режим Demo trading Bybit, ротация
мастер-ключа, замена ключа у существующего аккаунта, вход и пользователи.

## Capabilities

### New Capabilities

- `exchange-accounts`: аккаунты биржи — хранение ключей в зашифрованном виде, проверка ключа у Bybit, чтение,
  переименование и удаление аккаунта, баланс аккаунта, мастер-ключ.
- `exchange-account-interface`: веб-интерфейс аккаунтов — раздел в шапке, список, форма нового аккаунта, страница
  аккаунта с балансом.

### Modified Capabilities

- `bot-management`: у бота появляется необязательный аккаунт биржи; проверка бота учитывает аккаунт; чтение бота и
  списка ботов возвращает аккаунт.
- `bot-interface`: поле «Аккаунт» в форме бота; аккаунт и метка testnet на странице и в списке ботов.

## Impact

- Backend: новая область `ExchangeAccounts` в Domain, Application, Infrastructure (Bybit-адаптер с ключом пользователя
  через `IBybitUserClientProvider` из Bybit.Net, шифрование secret, репозиторий, миграция `exchange_accounts` и колонка
  `bots.exchange_account_id`), новый `ExchangeAccountsController`; правка команд, запросов и контрактов ботов.
- API: новые эндпоинты `/api/exchange-accounts`; в теле и ответах бота новое поле `exchangeAccountId`, в ответах бота —
  сведения об аккаунте. Изменение обратно совместимо: поле необязательное.
- Настройки: новая секция `ExchangeAccounts` с `MasterKey`; на проде владелец добавляет
  `ExchangeAccounts__MasterKey` в окружение API до деплоя, иначе API не стартует.
- Frontend: новый модуль `exchange-accounts`, страницы аккаунтов, правка `BotForm`, страницы и списка ботов,
  перегенерация `schema.d.ts`; заглушка `frontend/e2e/bybit-stub.ts`.
- `CONTEXT.md`: термины «Аккаунт биржи» и «Баланс аккаунта».
