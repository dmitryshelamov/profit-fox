# Spec Delta

## ADDED Requirements

### Requirement: Аккаунт бота

Бот SHALL принимать необязательный идентификатор аккаунта биржи при создании и изменении; без него бот остаётся без
аккаунта. Аккаунт бота SHALL меняться и сниматься изменением бота. Аккаунт не даёт боту торговать: запуск бота вне
этого изменения.

#### Scenario: Бот с аккаунтом

- **WHEN** пользователь создаёт бота с инструментом `spot` / `BTCUSDT` и аккаунтом, ключ которого торгует на споте
- **THEN** система сохраняет бота, и чтение бота возвращает этот аккаунт

#### Scenario: Снять аккаунт

- **WHEN** пользователь изменяет бота с аккаунтом без идентификатора аккаунта
- **THEN** чтение бота возвращает бота без аккаунта

#### Scenario: Бот без аккаунта

- **WHEN** пользователь создаёт бота без идентификатора аккаунта
- **THEN** система сохраняет бота без аккаунта

### Requirement: Проверка аккаунта бота

Бот MUST отклоняться с ошибкой по аккаунту, если аккаунта нет или если ключ аккаунта не торгует в категории инструмента
бота. Удаление аккаунта одновременно с сохранением бота MUST NOT приводить к сохранённому боту с несуществующим
аккаунтом.

#### Scenario: Неизвестный аккаунт

- **WHEN** пользователь создаёт бота с идентификатором аккаунта, которого нет
- **THEN** система отклоняет запрос с ошибкой по аккаунту

#### Scenario: Ключ не торгует в категории бота

- **WHEN** пользователь создаёт бота с инструментом `linear` / `BTCUSDT` и аккаунтом, ключ которого торгует только на
  споте
- **THEN** система отклоняет запрос с ошибкой по аккаунту

## MODIFIED Requirements

### Requirement: Чтение ботов

Система SHALL возвращать бота по идентификатору: имя, стратегию, заданные значения параметров, инструмент, интервал,
баланс и аккаунт биржи, если он задан: идентификатор, имя и окружение. Список ботов SHALL содержать идентификатор, имя,
стратегию, инструмент, интервал, баланс и аккаунт каждого в том же виде, а также его последний бэктест: идентификатор,
статус и прогресс; у бота без бэктестов последнего бэктеста нет. Неизвестный идентификатор SHALL давать ответ «не
найдено».

#### Scenario: Чтение сохранённого бота

- **WHEN** пользователь запрашивает сохранённого бота
- **THEN** система возвращает те же значения параметров, инструмент, интервал и баланс, что были сохранены

#### Scenario: Неизвестный бот

- **WHEN** пользователь запрашивает бота по идентификатору, которого нет
- **THEN** система отвечает «не найдено»

#### Scenario: Последний бэктест в списке

- **WHEN** у бота созданы бэктесты `A`, затем `B`, и `B` посчитал 5 комбинаций из 12
- **THEN** список ботов возвращает у этого бота баланс и последний бэктест `B` в статусе `Running` с прогрессом `5` из
  `12`

#### Scenario: Бот без бэктестов в списке

- **WHEN** у бота нет бэктестов
- **THEN** список ботов возвращает его баланс и не возвращает последний бэктест

#### Scenario: Аккаунт в списке

- **WHEN** у бота аккаунт «Проверка» в окружении `testnet`
- **THEN** список ботов и чтение бота возвращают у него аккаунт «Проверка» с окружением `testnet`

### Requirement: Изменение бота

Система SHALL заменять имя, значения параметров, инструмент, интервал, баланс и аккаунт бота новыми валидными
значениями по тем же правилам, что при создании. Стратегию бота изменить MUST быть нельзя. Изменение с ошибками MUST
отклоняться, и бот MUST оставаться прежним.

#### Scenario: Смена инструмента

- **WHEN** пользователь меняет у бота инструмент с `spot` / `BTCUSDT` на `spot` / `ETHUSDT`
- **THEN** чтение бота возвращает `ETHUSDT`

#### Scenario: Изменение с ошибкой

- **WHEN** пользователь меняет у бота значение `fast` на `1` при минимуме `2`
- **THEN** система отклоняет изменение с ошибкой по `fast`, и бот остаётся прежним

#### Scenario: Смена категории при аккаунте только для спота

- **WHEN** у бота аккаунт, ключ которого торгует только на споте, и пользователь меняет инструмент на `linear` /
  `BTCUSDT`
- **THEN** система отклоняет изменение с ошибкой по аккаунту, и бот остаётся прежним
