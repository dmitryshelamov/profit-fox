# Design

## Context

Мотивация — `proposal.md`; требования — дельты `strategy-library`, `strategy-graph`, `strategy-editor`.

Текущее состояние:

- `BuiltInComposites` (Domain) строит в коде три встроенных узла: `ema-cross`, `ladder`, `dca`. Ladder и DCA — это
  стратегии целиком: вход `in` с параметрами, позиция и ордера. Эталонные фикстуры `ladder.json` и `dca.json` —
  «параметры → составной узел».
- Порядок вычисления узлов (`GraphExpander`): топологический, а при равенстве — по пути узла (ординальное сравнение).
  Внутри составного узла путь — `ladder/<id>`.
- Отпечаток эталонных результатов бэктестов (`EngineVersionTests`, `engine-versions.json`) считается по сеткам
  эталонных стратегий; изменение результатов без новой версии движка роняет тест.
- `StrategyJson.WriteGraph` всегда пишет `layout`, при отсутствии координат — `{}`. Сервер принимает неполную
  раскладку.
- Фронтенд (`modules/graph-editor/model/flow.ts`) ставит узлы без координат сеткой по четыре в ряд; узел шириной
  «не меньше 160 px», высота по числу пинов.
- Решения приняты в грилинге 2026-11-02 и при сравнении с ProfitGraph (`flowchartLayout.ts`, `keepFlowPlaces`,
  `resetFlowLayout`).

## Goals / Non-Goals

**Goals:**

- На холсте видно все решения стратегии; составной узел — только переиспользуемая часть.
- Граф без координат раскладывается детерминированно и читается слева направо.
- Правка не двигает узлы, которых не касалась.

**Non-Goals:**

- Миграция сохранённых стратегий со ссылкой на `ladder` или `dca`.
- Раскладка, учитывающая пересечения проводов (оптимизация порядка внутри столбца), ELK и подобные библиотеки.
- Изменение формата графа.

## Decisions

### 1. Решения из обсуждения с владельцем

- Встроенные Ladder и DCA удаляются, «Пересечение EMA» остаётся. Отклонены: оставить их в библиотеке «для готового
  блока» (стратегия в узле прячет решения) и скрыть их из каталога, сохранив для старых ссылок (лишний режим ради
  данных, которых нет).
- Миграции нет: на production сохранённых стратегий нет. Отклонена миграция, раскрывающая ссылку в граф (код и тесты
  разбора JSON ради пустой базы). Правило изменения 1 «несовместимая правка встроенного узла выходит новым узлом» здесь
  нарушается один раз, осознанно.
- Шаблонов как функции нет: «шаблоны» — эталонные стратегии, Ladder и DCA пересоздаются развёрнутыми.
- Раскладка — модель ProfitGraph: неполные координаты, автораскладка остального, закрепление при первой правке,
  «Выстроить» очищает раскладку. Отклонены: запись координат только при сохранении (граф прыгает во время правки) и
  ручные координаты в эталонах (их пришлось бы поддерживать вручную).

### 2. Развёртывание Ladder и DCA сохраняет id узлов

Эталонные `ladder.json` и `dca.json` получают узлы бывших встроенных графов с теми же id (`position`, `flat`,
`riseFactor`, `sellPrice`, …, `entry`, `sell`, `buy`), кроме входа `in`: его провода `in.<имя>` становятся
`params.<имя>`. Узел `params` уже есть в фикстурах.

- Почему: порядок вычисления при равенстве задаёт путь узла. Внутри узла пути были `ladder/<id>`, теперь `<id>`:
  префикс одинаков у всех внутренних узлов, поэтому их взаимный порядок, а значит и порядок команд в событии, не
  меняется. Ожидание: отпечаток эталонных результатов прежний, версия движка не поднимается.
- Проверка: тест версии движка. Если отпечаток всё же изменится, это означает изменение результатов, и по правилу
  проекта поднимается версия движка с записью в `engine-versions.json`.
- Итог реализации: отпечаток прежний, версия движка не поднималась. Единственное отличие команд — путь узла-ордера в
  `PlaceOrder.NodePath`: `ladder/entry` → `entry`, `dca/buy` → `buy`. Сторона, тип, цена, размер и порядок команд те
  же; в результаты бэктестов путь не входит. Ожидания `ReferenceStrategiesTests` и `EntryMoneyTests` поменялись только
  в пути.

### 3. Удаление встроенных узлов в домене

`BuiltInNode` теряет `Ladder` и `Dca`, `BuiltInComposites.All` — их определения, `StrategyCodes` — коды `ladder` и
`dca`. Ссылка `"ref": "ladder"` после этого — неизвестный составной узел, как любая ошибочная ссылка: проверка графа
сообщает «No such composite node.» Тесты, где Ladder был примером встроенного узла (клонирование, запрет правки,
снимки версий, репозиторий, каталог), переходят на `ema-cross`; тесты на эталонные стратегии продолжают работать с
развёрнутыми фикстурами.

Итог реализации: `ladder` и `dca` больше не коды встроенных узлов, поэтому `StrategyJson` отвергает такую ссылку ещё
при чтении определения (ошибка по пути `ref`, ответ 400), до проверки графа. Сохранённая стратегия с такой ссылкой не
читается, и API не стартует, пока она в базе: загрузка библиотеки при старте (`StrategyVersionsInitializationService`)
падает. На production таких стратегий нет; локальную базу нужно очистить от них до запуска нового API.

### 4. Раскладка по ступеням — чистая функция во фронтенде

`modules/graph-editor/model/layout.ts`: `layoutGraph(definition, catalog) → Record<id, Position>` для всех узлов.
Правила (спека `strategy-editor`, «Раскладка по ступеням»):

- **Столбец** — глубина: 0 у узла без входящих проводов, иначе 1 + наибольшая глубина источников. Граф без циклов,
  глубина определена; для невалидного графа с циклом узлы цикла получают столбец по порядку обхода, без зацикливания.
- **Полоса** — первое по порядку в определении решение (узел без выходящих проводов), достижимое из узла по проводам.
  Решение — само себе полоса. Узел, не ведущий ни к одному решению, попадает в последнюю полосу «прочее».
- **Координаты** — полосы идут сверху вниз; высота полосы — наибольшая по столбцам сумма высот её узлов с зазорами. В
  клетке «полоса × столбец» узлы стоят друг под другом в порядке определения. `x = столбец × (ширина + 80)`, высота
  узла считается по числу строк пинов и строке настроек, без измерения DOM.
- Узел получает фиксированную ширину 200 px (сейчас «не меньше 160»), чтобы раскладка знала её заранее; длинные
  подписи пинов обрезаются с многоточием и полным текстом в `title`.

`toFlow` берёт позицию из `layout`, а если её нет — из `layoutGraph`. Сетка по четыре в ряд удаляется.

Отклонено: ELK (новая внешняя зависимость и асинхронная раскладка ради графов в десятки узлов) и обход дерева, как в
ProfitGraph (у них блок-схема с ветвлениями «да/нет», у нас граф данных с общими источниками).

### 5. Закрепление координат при правке

`useGraphEditing` получает каталог. `setDefinition(next)` перед записью дополняет `next.layout` координатами узлов,
у которых их нет, взятыми из `layoutGraph(текущее определение)` — то есть с мест, где узлы стояли на экране до правки.
Узлы, которых в `next` нет, не добавляются; новый узел из палитры приходит со своей позицией (`addNode`). Отдельный
метод `relayout()` для «Выстроить» записывает пустую раскладку без закрепления.

- Почему в хуке, а не на холсте: правки идут и с холста, и из карточек (узел, параметры, входы и выходы); хук — общее
  место.
- Открытие ничего не пишет: закрепление срабатывает только на правке, черновик и «Сохранить» появляются только после
  неё.
- Сравнение черновика без учёта раскладки (`compareDrafts`) остаётся: закреплённые координаты не делают черновик
  «отличающимся» при следующем открытии, а «Сохранить» после одной лишь раскладки — это `sameEdit` с учётом
  координат, как сейчас.

### 6. «Выстроить»

Кнопка в столбце инструментов (только при правке, не для встроенного узла на чтение) вызывает `relayout()`: раскладка
очищается, граф перерисовывается по ступеням. Это обычная правка: `dirty`, черновик, «Отменить правки» возвращает
прежние координаты. После сохранения у стратегии `"layout": {}` до следующей правки.

### 7. Эталонные фикстуры без координат

У `ema.json`, `ema-short.json`, `ladder.json`, `dca.json` — `"layout": {}`. Так круговые тесты «создать и прочитать без
изменений» остаются точными (сервер пишет `{}`), а в редакторе эталоны открываются по ступеням.

## Risks / Trade-offs

- [Локальные стратегии со ссылкой на `ladder`/`dca` станут невалидными] → пересоздать локальную базу или эти
  стратегии; на production данных нет (решение 1).
- [Отпечаток бэктестов может измениться, если порядок вычисления зависит от пути сильнее, чем ожидается] → тест версии
  движка поймает; тогда версия движка поднимается по правилам проекта, а не замалчивается.
- [Раскладка по ступеням не минимизирует пересечения проводов внутри столбца] → порядок определения и полосы дают
  читаемый результат на эталонах; оптимизацию отложить до реальных больших графов.
- [Фиксированная ширина обрезает длинные имена пинов] → полный текст в подсказке; 200 px вмещают имена эталонов
  (`priceRiseForSell`).

## Migration Plan

Миграций базы нет. Деплой вместе с API и web. Сохранённые стратегии со ссылкой на `ladder`/`dca` (только локальные)
пересоздаются вручную или через API из новых фикстур. Откат — предыдущая версия API и web.
