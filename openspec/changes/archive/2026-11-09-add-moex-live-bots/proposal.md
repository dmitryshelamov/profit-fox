# Proposal

## Why

После change `add-moex-market` (PR #83) акции MOEX есть в модели данных, на графиках и в бэктестах, но запуск бота категории
`moex` отклоняется конфликтом «торговля на MOEX ещё не поддерживается»: у адаптера T-Invest нет заявок, стримов и сверки. Это
второй из четырёх согласованных changes интеграции T-Invest: живые боты на акциях теми же стратегиями, что на Bybit, с
реальными деньгами на брокерском счёте владельца.

## What Changes

- Запуск бота `moex` с аккаунтом T-Invest разрешён: проверяется доступ токена к счёту (открыт, полный доступ), свободные
  рубли на счёте покрывают баланс бота и других работающих ботов аккаунта; конфликт «не поддерживается» снимается.
  Пока в настройках хоста API торговля на MOEX выключена (`TInvest:Trading`, по умолчанию `false`), запуск отклоняется
  конфликтом «торговля на MOEX выключена»; владелец включает её после чек-листа словом «включаем».
- Заявки на T-Invest: лимитные — дневные (`DAY`), рыночные — без цены; количество в лотах; идентификатор клиента бота
  отображается в случайный UUID запроса через таблицу `moex_orders`, записанную до отправки, так что повтор отправки не
  создаёт вторую заявку, а ответы и события биржи находят заявку бота по `order_request_id`.
- Закрытая сессия и ценовой коридор — не отказ: адаптер проверяет кэшированный статус торгов и коридор до отправки, а
  отказы `30098` и `30099` переводит во временный с «не раньше чем»; сессия откладывает отправку до открытия сессии по
  расписанию биржи, а не долбит биржу каждую минуту.
- Истечение дневной заявки в конце торгового дня — обычная отмена биржей: стратегия перевыставляет заявку, и отправка
  ждёт следующей сессии.
- Стримы T-Invest: один стрим состояний заявок на аккаунт (события — сигнал, состояние и комиссия дочитываются
  `GetOrderState`), один стрим закрытых свечей и один стрим текущих свечей на процесс с подпиской на серию; переподключение
  с возрастающей паузой, пинги, сигнал «восстановлено» всем подписчикам. Живая свеча на странице бота `moex` вместо «нет
  данных».
- Сверка с биржей на MOEX: позиция в акциях из `GetPositions`, активные заявки аккаунта по инструменту, заявки бота по
  `order_request_id`; расхождение останавливает ботов, как на Bybit.
- Комиссия заявки берётся из `executed_commission` состояния заявки; ставка для расчёта резерва — пробой `GetOrderPrice`.
- Порты торговли (`IOrderGateway`, `IExchangeLedger`, `IExchangeStreams`, `IFormingCandleStreams`) маршрутизируются по бирже
  ключа и категории, как порты чтения в change 1; `ExchangeKey` несёт биржу.
- Пауза после временного отказа может быть задана биржей («не раньше чем»); для Bybit поведение прежнее.

Вне объёма: заявки и сделки по идеям на MOEX (`add-moex-ideas`, `add-moex-idea-trades`), стоп-заявки брокера, шорты (бот
шорт на `moex` отклоняется при создании), перенос остатка заявки через ночь (ProfitGraph T12b), доказательства отсутствия
заявки по операциям, песочница T-Invest, интервал `D`.

## Capabilities

### New Capabilities

Нет: все изменения — требования существующих возможностей.

### Modified Capabilities

- `live-trading`: запуск бота на `moex` (снятие конфликта, выключатель торговли, условия запуска по счёту T-Invest, деньги в
  рублях); заявки на MOEX (дневные лимитные, лоты, идемпотентность по запросу); отложенная отправка до открытия сессии и из
  коридора; истечение дневной заявки; комиссия заявки на MOEX; стримы T-Invest и их переподключение; сверка на MOEX;
  временный отказ с паузой, названной биржей.
- `bot-chart`: текущая свеча бота `moex` приходит из стрима T-Invest; тишина закрытого рынка показывается как «нет
  данных»; требование о недоступной истории не называет Bybit (текст UI уже «биржа не отвечает»).

## Impact

- Domain: `ValueObjects/LiveTrading`: `ExchangeKey` получает биржу; `LiveOrder.Deferred` принимает «не раньше чем».
- Application: `LiveRequests.KeyAsync` строит ключ по бирже аккаунта (T-Invest: номер счёта + токен); `StartBotCommandHandler`
  проверяет счёт T-Invest через `IBrokerAccountReader` и выключатель; `Ports/LiveTrading/OrderOutcome` получает `RetryAfter`;
  `LiveBotSession.SendAsync` откладывает по нему; `FormingCandleFeeds` перестаёт отвечать `NoData` для T-Invest.
- Infrastructure: `Exchanges/Routing` — маршрутизаторы четырёх портов торговли; `Exchanges/TInvest` — `TInvestOrderGateway`,
  `TInvestLedger`, `TInvestStreams`, `TInvestOrderIds` (таблица `moex_orders`, миграция), `TInvestOrderStates` (маппинг
  состояний), `TInvestTradingStatuses` (кэш статуса, коридора и расписания), `TInvestSettings.Trading`; регистрация keyed по
  `Exchange`; `Tests.Shared/TInvest/MockTInvestApi` учится серверным и дуплексным стримам.
- Persistence: таблица `moex_orders`.
- API: без новых маршрутов; `POST /api/bots/{id}/start` для `moex` отвечает 409 только при выключенной торговле или
  проблеме счёта.
- Frontend: без изменений кода; страница бота `moex` получает живую свечу и действия запуска как есть.
- Настройки: `TInvest:Trading` (API), лимит `Orders` группы уже есть; `.env.prod` не меняется до «включаем».
- Документация: `docs/conventions.md`, чек-лист владельца на реальном счёте (первый бот минимальным лотом) в design.md.
