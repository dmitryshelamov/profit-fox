# Spec Delta

## MODIFIED Requirements

### Requirement: Чтение калибровки

API SHALL отдавать по `GET /api/ideas/calibration` итоги калибровки по параметрам: окно `days` — 90 или 30, по
умолчанию 90, категория `category` — `linear` или `spot`, без неё — все категории, и режим `scope` — `all` или `fresh`
(после изменения правил), по умолчанию `all`. Ответ SHALL содержать время расчёта, число проверенных случаев, число
случаев без статистики корзины, оценку Брайера, оценку без корзин, четыре таблицы калибровки и сравнение старой и новой
модели. Другое окно, категория или режим MUST давать ошибку валидации 400 с именем параметра.

#### Scenario: Калибровка за 30 дней по linear

- **WHEN** экран просит калибровку с `days=30` и `category=linear`
- **THEN** ответ содержит итоги только по случаям `linear`, сработавшим за последние 30 дней

#### Scenario: После изменения правил

- **WHEN** экран просит калибровку с `scope=fresh`
- **THEN** ответ содержит итоги только по случаям, сработавшим после применения правила своего типа × ТФ и начала версии

#### Scenario: Модель с признаками в ответе

- **WHEN** отчёт посчитан с моделью с признаками
- **THEN** в сравнении есть модель с признаками и разница Брайера с интервалом, а у отчёта, посчитанного раньше, их нет

#### Scenario: Ещё не посчитана

- **WHEN** сканер ещё ни разу не посчитал калибровку
- **THEN** ответ без времени расчёта, с нулём проверенных случаев, пустыми таблицами и без сравнения

#### Scenario: Другое окно

- **WHEN** экран просит калибровку с `days=60`
- **THEN** API отвечает ошибкой валидации 400 по параметру `days`

#### Scenario: Другой режим

- **WHEN** экран просит калибровку с `scope=old`
- **THEN** API отвечает ошибкой валидации 400 по параметру `scope`

### Requirement: Экран «Калибровка»

Интерфейс SHALL иметь экран `/ideas/calibration` с путём «Идеи / Калибровка», переключателями окна «Кейсы 90 дн» и «за
30 дн», категории «Все», `linear`, `spot` и режима «Все случаи» и «После изменения правил», числом проверенных случаев и
случаев без статистики корзины и временем расчёта. На экране SHALL быть три плитки: оценка Брайера против оценки без
корзин, средний итог идей со значком ▲, и ожидание «обещали → получили» по всем случаям. Ниже — таблица «Старая модель →
новая» и четыре таблицы калибровки.

#### Scenario: Плитка Брайера

- **WHEN** оценка Брайера 0.207, а без корзин 0.219
- **THEN** плитка показывает 0.207 против 0.219 и что корзины лучше на 5.5 %

#### Scenario: Переключение окна

- **WHEN** владелец выбирает «за 30 дн»
- **THEN** плитки и таблицы показывают итоги по случаям последних 30 дней

#### Scenario: Переключение режима

- **WHEN** владелец выбирает «После изменения правил»
- **THEN** плитки и таблицы показывают итоги только по случаям после изменения правил, а режим остаётся в адресе страницы

#### Scenario: Старая модель против новой

- **WHEN** в сравнении у старой модели ▲ получил −0.074 R, а у новой +0.03 R
- **THEN** таблица «Старая модель → новая» показывает по строке на модель: случаев, Брайер, случаев с ▲, обещали и
  получили с интервалом

#### Scenario: Модель с признаками

- **WHEN** в сравнении есть модель с признаками с Брайером 0.201
- **THEN** таблица «Старая модель → новая» показывает третью строку «С признаками» с её случаями, Брайером, ▲, обещали и
  получили

#### Scenario: Отчёт без модели с признаками

- **WHEN** отчёт посчитан до появления модели с признаками
- **THEN** таблица показывает две строки, старую и новую, без разницы Брайера

#### Scenario: Разница Брайера на экране

- **WHEN** разница Брайера модели с признаками и новой −0.006 с интервалом −0.012…+0.001
- **THEN** под таблицей сравнения строка «С признаками − новая, Брайер: -0.006, интервал 95 % -0.012…+0.001»; без
  интервала — «меньше 30 кейсов»

#### Scenario: Модель с признаками в разбивках на экране

- **WHEN** в строке «1 ч» разбивки по ТФ есть модель с признаками с разницей Брайера −0.005 (−0.011…+0.002)
- **THEN** таблица «По ТФ: старая модель → новая» показывает строку «1 ч · С признаками» с этой разницей в колонке
  «Разница Брайера»
