# Tasks

Новая логика идёт строго по TDD: красный тест, минимальный код, рефакторинг. Ссылки «решение N» — на design.md. Эталонные
числа — в сценариях спеки `trade-ideas`.

## 1. Домен: признаки

- [x] 1.1 `IdeaFeatures.Of(move, volumeRatio)` (решение 1). Готово, когда тесты сценариев «Сильное движение на обычном
  объёме», «Ровно на границе» и «Ниже границ» зелёные.
- [x] 1.2 `IdeaOutcome.Features`, по умолчанию обычное движение и объём.

## 2. Домен: модель с признаками

- [x] 2.1 `BucketModel.Bucket` (решение 2). Готово, когда сценарий «Корзина как родитель подкорзин» даёт −0.15 R с
  интервалом −0.336…+0.044 R, а подкорзина с τ² = 0 — числа модели корзины («Тонкий уровень остаётся с корзиной»).
- [x] 2.2 `CalibrationCalculator`: окна подкорзин, τ² между подкорзинами на начало суток, обещание модели с признаками,
  `CalibrationComparison.Features` (решение 3). Готово, когда тесты видят:
  - сравнение с тремя моделями на эталоне с числами из `BucketModel`;
  - случай, закрытый после срабатывания проверяемого, не входит в окно его подкорзины;
  - обещание с признаками только у случаев сравнения (иначе проход падает на корзине без закрытых случаев);
  - пустое сравнение с тремя пустыми моделями.

## 3. Application

- [x] 3.1 `IdeaOutcomes` передаёт признаки сигнала в случай. Готово, когда тест прохода видит уровень сигнала у случая.

## 4. Хранение и API

- [x] 4.1 `CalibrationComparisonDb.Features` (необязательное), конвертер; интеграционный тест хранилища видит модель с
  признаками после записи и чтения, а отчёт без поля читается с `Features = null`.
- [x] 4.2 `CalibrationComparisonResponse.Features`; тест API видит `comparison.features`.

  с `features`.
