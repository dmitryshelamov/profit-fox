# Конструктор сигналов

## Why

Сейчас сигнал правится сырым JSON на странице предпросмотра: граф не виден, узлы и провода пишутся руками, сохранить
сигнал негде. Это шаг 3 плана «ядро → предпросмотр → конструктор → проверка из конструктора → бот»: собирать сигнал на
холсте, сохранять его и сразу видеть его события на паре. Тот же редактор потом примет стратегии.

## What Changes

- Раздел «Сигналы»: список сохранённых сигналов, где их можно создать, переименовать, скопировать и удалить.
- Редактор сигнала на полноэкранном холсте, как в profit-fox-v2:
  - палитра узлов из каталога;
  - провода между пинами одного типа;
  - карточки узла, параметров графа, ошибок и JSON;
  - значения неподключённых входов прямо на пине.
- Проверка графа на сервере без чтения истории, через 0,4 с после правки. Ошибки показываются на узлах, пинах и
  проводах.
- Сигналы хранятся файлами `bench/signals/<имя>.json` и пишутся API стенда по кнопке «Сохранить». Сохраняется только
  граф без ошибок. Несохранённые правки живут черновиком в браузере, при открытии предлагается восстановить или
  отбросить.
- Расположение узлов на холсте хранится в файле сигнала рядом с графом, а не в нём, и в гипотезу не попадает.
- Гипотезу можно открыть в редакторе только для чтения и скопировать её сигнал в новый сигнал.
- Предпросмотр переезжает в нижнюю сворачиваемую панель редактора и запускается кнопкой «Показать». API держит в памяти
  историю последних 5 пар с таймфреймом, поэтому повторный предпросмотр на той же паре не ходит в сервис данных.
- **BREAKING**: страница предпросмотра с полем JSON удаляется, её место занимает редактор.
- Прогон стенда больше не считает незакоммиченные файлы `bench/signals/` грязным деревом: сигнал в прогоне не
  участвует, гипотеза хранит свою копию графа.

Не входят:
- вставка сигнала узлом в другой граф (шаг 5);
- кнопка «Проверить на стенде» и создание гипотезы из конструктора (шаг 4);
- новые узлы: индикаторы и арифметика выйдут изменением `add-indicator-nodes`;
- стратегии, узлы заявок и позиции, бот;
- база данных, развёртывание на soyo-02, авторизация;
- шаблоны сигналов, предпросмотр по всем парам, отложенный период и исходы сделок.

## Capabilities

### New Capabilities

- `signal-constructor`: библиотека сигналов в `bench/signals` и редактор сигнала на холсте. Покрывает каталог узлов
  для редактора, проверку графа без истории, сохранение, черновики, расположение узлов, гипотезы только для чтения и
  панель предпросмотра.

### Modified Capabilities

- `signal-preview`: требование «Страница предпросмотра» удаляется, предпросмотр показывается панелью редактора. Новое
  требование: повторный предпросмотр той же пары и таймфрейма не читает историю заново.
- `hypothesis-bench`: в требовании «Чистое дерево» к исключениям добавляется папка `bench/signals/`.

## Impact

- **Код бэкенда:**
  - `ProfitFox.Bench.Presentation`: новые контроллеры каталога узлов, проверки графа и сигналов, кэш истории в
    предпросмотре;
  - `ProfitFox.Bench`: чтение и запись файлов сигналов, исключение `bench/signals/` в `GitRepository.Changed`;
  - `ProfitFox.Engine.Strategy`: каталог узлов получает перечисление всех видов для API. Формат графа, расчёт узлов
    и исполнитель не меняются.
- **Код фронтенда:** `frontend/src/preview` заменяется редактором; появляются маршруты `/signals`,
  `/signals/<имя>` и `/hypotheses/<id>`.
- **Зависимости фронтенда:** `@xyflow/react`, `@tanstack/react-router`.
- **Данные:** новая папка `bench/signals/` в репозитории. API пишет в неё файлы, но не коммитит их.
- **Внешние системы:** как раньше, только чтение сервиса данных на soyo-02. Кэш уменьшает число запросов к нему.
