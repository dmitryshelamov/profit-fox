# Spec Delta

## Purpose

Как версия profit-fox попадает на прод soyo-01: образы собираются из `main` вне прода, выкатка ждёт подтверждения
владельца, сервисы обновляются в порядке, при котором миграции применяются до старта фоновых процессов, а секреты и
доступ к проду не выходят за локальную сеть.

## ADDED Requirements

### Requirement: Версия — номер сборки коммита `main`

Прод SHALL запускать только образы, собранные из коммита ветки `main`. Каждая новая сборка коммита `main` SHALL получать
следующий номер версии — целое число на единицу больше наибольшего выданного (первая версия — `1`): коммит помечается
git-тегом `v<N>`, а образы API, Worker'а, сканера и веба публикуются с тегом `<N>`. Коммит MUST NOT получать два
номера. Все сервисы прода SHALL работать на одном номере. Образы MUST NOT собираться на сервере прода.

#### Scenario: Мерж в main

- **WHEN** PR смержен в `main`, для его коммита прошли проверки CI, Frontend и E2E, а наибольшая выданная версия — `6`
- **THEN** вне прода коммит получает тег `v7`, а образы API, Worker'а, сканера и веба публикуются в реестре с тегом `7`

#### Scenario: Пересборка того же коммита

- **WHEN** сборку коммита с тегом `v7` запускают ещё раз
- **THEN** номер остаётся `7`, нового тега не появляется

#### Scenario: Проверки не прошли

- **WHEN** у коммита `main` упала хотя бы одна из проверок CI, Frontend или E2E
- **THEN** образы этого коммита не собираются, и выкатить его нельзя

### Requirement: Выкатка с подтверждения владельца

Выкатка версии на прод SHALL начинаться только после подтверждения владельца в GitHub. Выкатку MUST NOT запускать
workflow из pull request или из ветки, отличной от `main`.

#### Scenario: Образы готовы

- **WHEN** образы коммита собраны
- **THEN** выкатка ждёт подтверждения владельца, а прод продолжает работать на прежней версии

#### Scenario: Workflow из форка

- **WHEN** pull request из форка меняет workflow так, чтобы выполнить шаг выкатки
- **THEN** выкатка не происходит, а workflow из форка не запускается без одобрения владельца

### Requirement: Порядок обновления

При выкатке прод SHALL сначала остановить Worker и сканер, затем обновить API, дождаться, пока API ответит на новой
версии (миграции базы применены), и только потом запустить Worker, сканер и веб той же версии. Если API новой версии не
ответил, выкатка MUST остановиться с ошибкой и MUST NOT запускать Worker и сканер новой версии.

#### Scenario: Обычная выкатка

- **WHEN** владелец подтверждает выкатку версии `7`, и в ней есть новая миграция
- **THEN** миграция применена до старта Worker'а, и после выкатки API, Worker, сканер и веб работают на версии `7`

#### Scenario: API не поднялся

- **WHEN** API новой версии не отвечает за отведённое время
- **THEN** выкатка завершается с ошибкой, Worker и сканер остаются остановленными, и владелец видит ошибку в GitHub

### Requirement: Повторная выкатка и откат

Выкатка версии, которая уже работает, SHALL оставлять прод в том же состоянии. Откат SHALL быть выкаткой ранее
собранной версии: владелец запускает выкатку на её номер вручную. Номер, у которого нет тега `v<N>` на коммите `main`,
MUST отклоняться без изменений на проде.

#### Scenario: Откат

- **WHEN** на проде версия `7`, и владелец запускает выкатку версии `6`
- **THEN** все сервисы прода работают на версии `6`, данные в базе сохранены

#### Scenario: Несуществующая версия

- **WHEN** выкатку запускают на номер `99`, у которого нет тега `v99`
- **THEN** выкатка отклоняется, прод продолжает работать на прежней версии

### Requirement: Секреты прода

Пароль базы, мастер-ключ счетов бирж и прочие секреты прода SHALL храниться только на сервере прода в файле, доступном
только его пользователю. Секреты MUST NOT попадать в репозиторий, в образы, в настройки GitHub и в логи выкатки.

#### Scenario: Лог выкатки

- **WHEN** выкатка прошла
- **THEN** в логе GitHub Actions нет ни пароля базы, ни мастер-ключа

### Requirement: Доступ к проду

Интерфейс и API прода SHALL быть доступны только из локальной сети по адресу soyo-01, порт 80. База прода MUST NOT
публиковать порт за пределы сервера. Доступ выкатки к серверу MUST ограничиваться запуском выкатки заданной версии с
машины выкатки и MUST NOT давать shell.

#### Scenario: Интерфейс из локальной сети

- **WHEN** владелец открывает `http://192.168.8.111/market` с машины локальной сети
- **THEN** открывается раздел «Рынок» прода

#### Scenario: Ключ выкатки

- **WHEN** ключом выкатки пытаются открыть shell на soyo-01 или зайти им не с машины выкатки
- **THEN** сервер отказывает
