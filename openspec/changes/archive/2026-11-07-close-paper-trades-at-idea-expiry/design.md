# Design

## Context

Мотивация — в proposal.md («Why»). Что есть сейчас:

- `PaperFill.Step` шагает учебную сделку по закрытым минутам пары: вход «Отката», выход по цели и стопу; срока
  жизни нет. `LiveAutos.StepAsync` шагает открытые сделки из памяти (`_open`) до `CoveredUntil` пары; пара, снятая с
  торгов, пропускается, и её сделка висит вечно.
- Идея истекает в `IdeaTracker.Exit`: `StatusAt` — конец последней минуты жизни, `ExitPrice` — её закрытие; пара вне
  торгов — `IdeaTracker.Expire(end, lastClose)`. Итог идеи в R (`CaseResult.R`) считается по этой цене с
  проскальзыванием и комиссией taker.
- `LiveIdeas.RunAsync` шагает идеи, собирает `changed`, потом зовёт `autos.RunAsync(end, created, births)` и пишет
  идеи, исходы (`Outcomes(changed)` → `ClosedIdea(IdeaId, TradedIdeaOutcome)`) и `AutoMinute` одной транзакцией.
  Исход попадает на сделку только в хранилище (`WriteOutcomes`); учебная сделка в памяти его не видит, пока не
  перечитана.
- `TradedIdeaOutcome(Status, StatusAt, Result)` — без цены выхода; `IdeaTrade` закрывается ногами `TakeProfit`,
  `StopLoss`, `Manual` (`Settled` выводит статус из ноги); у `idea_paper_trades` нет колонок ноги `Manual`.
- Ограничения: деньги `decimal`, время UTC, red → green → refactor, спеки на русском, код на английском.

## Goals / Non-Goals

**Goals:**

- Учебная сделка заканчивается там же, где идея: после истечения идеи ничего не держит бюджет автомата.
- Итог «по сроку» считается так же, как итог идеи при истечении (та же цена, комиссия и проскальзывание), чтобы
  «идеи X R → сделки Y R» в журнале сравнивало сравнимое.
- Перерыв, перезапуск сканера и уже записанные исходы прода дают тот же результат, что и без них.

**Non-Goals:**

- Реальные сделки по истечении идеи не закрываются (решение владельца о ручном выходе не меняется).
- Статистика идей, калибровка и правила выхода не меняются.
- Срок у «Ждёт входа» не меняется: его уже даёт дедлайн входа идеи.

## Decisions

1. **Цена закрытия «по сроку» = цена выхода идеи.** Учебная сделка закрывается по `TradedIdeaOutcome.ExitPrice`
   с `CaseResult.ExitFill` (проскальзывание) и комиссией taker, как `PaperFill.Leave`, со временем `StatusAt`
   исхода. Альтернатива — закрытие минуты, которую шагает сделка: совпадает с ценой идеи в штатном случае, но после
   перезапуска, когда минута истечения уже пройдена, даёт другую цену; поэтому цена хранится на исходе.
2. **`TradedIdeaOutcome` получает `ExitPrice` (`decimal?`).** Колонка `idea_exit_price numeric NULL` в
   `idea_paper_trades` и `idea_trades` (исход — одна запись для обеих таблиц; у реальной сделки поле пока только
   хранится). `WriteOutcomes` пишет её; миграция дозаписывает уже записанным исходам цену из `ideas.exit_price`
   по `idea_id` — так 18 открытых сделок прода получают цену без отдельного обслуживания. Альтернатива — брать цену из
   `ideas` при каждой загрузке: ломается чисткой идей через 7 дней.
3. **Нога выхода `IdeaTradeLeg.Expiry` и статус `IdeaTradeStatus.ClosedAtExpiry`.** `IdeaTrade` получает
   `LegTotals Expiry` (необязательный параметр в конце, по умолчанию `None`), `Exited` суммирует и её, `Settled`
   даёт `ClosedAtExpiry`; `Result` считает её закрытой. Колонки `expiry_quantity / expiry_value / expiry_fee` только у
   `idea_paper_trades`; конвертер реальных сделок её не пишет и не читает (у реальной сделки нога всегда `None`).
   Альтернатива — класть выход в ногу `Manual` и ставить статус отдельно: пришлось бы добавить колонки `manual_*`
   учебной таблице и называть выход «вручную» там, где руки не было.
4. **Исходы минуты попадают на учебные сделки в памяти до шага.** `LiveIdeas.RunAsync` считает
   `Outcomes(changed)` до `autos.RunAsync` и передаёт список в `LiveAutos.RunAsync(end, created, births, outcomes)`;
   `LiveAutos` кладёт исход на `working` сделки по `IdeaId` (`Trade with { IdeaOutcome }`) и только потом
   `StepAsync`. То, что хранилище и так пишет в `WriteOutcomes`, не меняется. Так сделка закрывается в минуту
   истечения, а после `StartOver` исход приходит из хранилища вместе со сделкой.
5. **Правило шага.** `PaperFill.Step` для «Открыта»: сначала минута по старым правилам (стоп и цель главнее); если
   сделка осталась открыта и у исхода `Status = Expired`, `ExitPrice` есть и `StatusAt <= OpenTime + 1 мин` —
   `PaperFill.Expire`: нога `Expiry` по `ExitFill(ExitPrice)` со временем `StatusAt`. Когда истечение уже позади
   курсора (`StatusAt <= SteppedUntil`: перезапуск, дозаписанный исход прода), `Expire` применяется до минуты.
   Исход без цены (идея истекла без входа) ничего не делает: рыночная идея, не вошедшая из-за открытия за стопом или
   целью, в ту же минуту закрывает сделку по стопу или цели своими правилами, а «Откат» отменяет дедлайн.
6. **Пара вне торгов.** `LiveAutos.StepAsync` для сделки, чьей пары нет в `market` (или без `CoveredUntil`), при
   исходе «Истекла» с ценой применяет `PaperFill.Expire` без минут. Это закрывает и старые зависшие сделки снятых
   пар, как только их идея получает исход.
7. **Журнал.** `IdeaJournalTotals` получает `Expired` (число «по сроку»), `settled` включает `ClosedAtExpiry`;
   ответ `IdeaJournalTotalsResponse` — поле `expired`. Код статуса `closed_at_expiry` в `IdeaTradeCodes`.
   Frontend: `statusLabel` «Закрыта по сроку», строка итогов «… · по сроку N (X %)», `schema.d.ts` через
   `npm run generate:api`.
8. **Миграция одна, forward-only:** колонки, расширение `CK_idea_paper_trades_status`, дозапись `idea_exit_price`
   из `ideas` для обеих таблиц (`WHERE idea_status IS NOT NULL AND idea_exit_price IS NULL`).

## Risks / Trade-offs

- [Итог 18 сделок прода изменится задним числом, журнал «поедет»] → сказано в proposal; владелец знает до выкатки.
- [Цель или стоп паперной сделки чуть отличаются от уровней идеи («Цель 2R» пересчитывает цель от цены входа идеи, а
  сделка входит по закрытию минуты рождения)] → в минуту истечения сделка может закрыться по сроку там, где идея —
  по цели; это уже есть сегодня и остаётся; сравнение «идеи → сделки» в журнале это покажет.
- [Исход записан, а идея уже удалена чисткой (сделки старше 7 дней без цены)] → остаются открытыми, как сейчас;
  на проде таких нет (все идеи моложе суток).
- [Образ до миграции не знает колонки `expiry_*`, `idea_exit_price` и статус] → колонки `NULL`/со значениями по
  умолчанию и добавляются до выкатки кода; откат кода оставляет закрытые «по сроку» сделки с неизвестным образу
  статусом — такие строки старый код не читает (`IdeaTradeCodes.Parse` упадёт на `GetAll`), поэтому откат только
  вместе с ручным переводом этих строк в `closed_manually`.

## Migration Plan

1. Миграция `AddPaperTradeExpiryMigration`: `ALTER TABLE idea_paper_trades ADD expiry_quantity numeric NOT NULL
   DEFAULT 0, expiry_value numeric NOT NULL DEFAULT 0, expiry_fee numeric NOT NULL DEFAULT 0, idea_exit_price numeric
   NULL`; `ALTER TABLE idea_trades ADD idea_exit_price numeric NULL`; новый `CK_idea_paper_trades_status` с
   `closed_at_expiry`; `UPDATE … SET idea_exit_price = ideas.exit_price` для обеих таблиц.
2. Деплой через обычный Deploy с Approve; после выкатки на первой минуте сканера 18 открытых сделок `paper-test`
   закрываются «по сроку», бюджет освобождается, автомат снова берёт идеи.
3. Откат: см. риск выше.
