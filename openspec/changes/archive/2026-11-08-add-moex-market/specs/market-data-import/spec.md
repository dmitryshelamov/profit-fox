# Spec Delta

## ADDED Requirements

### Requirement: Интервалы категории

Каждая категория рынка SHALL иметь свой список интервалов: `spot` и `linear` — интервалы Bybit (`1`, `3`, `5`, `15`,
`30`, `60`, `120`, `240`, `360`, `720`, `D`, `W`, `M`), `moex` — `1`, `3`, `5`, `15`, `30`, `60`, `120`, `240`. Интервал не из
списка своей категории MUST отклоняться с ошибкой по интервалу.

#### Scenario: Дневные свечи MOEX

- **WHEN** пользователь отправляет запрос на загрузку `moex` / `SBER` / `D`
- **THEN** система отклоняет запрос с ошибкой по интервалу, задача не создаётся

#### Scenario: Часовые свечи MOEX

- **WHEN** пользователь отправляет запрос на загрузку `moex` / `SBER` / `60` за прошлый месяц
- **THEN** система создаёт задачу

### Requirement: Граница покрытия серии

Для каждой серии (категория, символ, интервал) система SHALL хранить границу покрытия — момент, до которого хранилище
содержит все свечи, которые биржа отдала; свеча, которой нет до границы, не торговалась. Загрузка и догрузка SHALL
запрашивать у биржи только интервалы за пределами покрытия, а полученный ответ SHALL двигать границу до конца
запрошенного периода, даже если свечей вернулось меньше, чем интервалов. Повторная загрузка периода внутри покрытия
MUST NOT отправлять запросов к бирже.

#### Scenario: Ночь MOEX внутри покрытия

- **WHEN** задача загрузила `moex` / `SBER` / `60` за сутки, в которых ночные часы без свечей, и пользователь загружает
  те же сутки снова
- **THEN** вторая задача завершается `Succeeded` без запросов к T-Invest и без новых свечей

#### Scenario: Период за границей

- **WHEN** покрытие `moex` / `SBER` / `60` заканчивается вчера в `20:00Z`, и задача загружает `[вчера 00:00Z, сегодня 00:00Z)`
- **THEN** система запрашивает у биржи только `[вчера 20:00Z, сегодня 00:00Z)`, и граница становится `сегодня 00:00Z`

#### Scenario: Граница не заходит в будущее

- **WHEN** конец периода задачи позже конца последней закрытой свечи
- **THEN** граница покрытия после загрузки равна концу последней закрытой свечи, а не концу периода

### Requirement: Свечи MOEX

Свеча `moex` SHALL сохраняться с объёмом в акциях (лоты × размер лота) и оборотом, приближённым как объём × типичная
цена `(high + low + close) / 3`. Сохраняться SHALL только свечи биржевой сессии; свечи, которые T-Invest помечает
незавершёнными, MUST отбрасываться.

#### Scenario: Лоты в акции

- **WHEN** T-Invest возвращает свечу `SBER` с объёмом `120` лотов при лоте `10`
- **THEN** сохранённая свеча имеет volume `1200`

## MODIFIED Requirements

### Requirement: Создание задачи загрузки

Система SHALL принимать запрос на загрузку свечей с параметрами: категория рынка (`spot`, `linear` или `moex`), символ,
интервал из списка интервалов категории, начало периода `from` и необязательный конец периода `to`. На корректный
запрос система SHALL создать задачу загрузки в статусе `Pending`, вернуть её идентификатор и выполнять загрузку в фоне.

#### Scenario: Корректный запрос

- **WHEN** пользователь отправляет запрос на загрузку `linear` / `BTCUSDT` / `60` с `from` = `2024-01-01T00:00:00Z` и
  `to` = `2024-02-01T00:00:00Z`
- **THEN** система отвечает, что задача принята, и возвращает идентификатор задачи в статусе `Pending`

#### Scenario: Конец периода не указан

- **WHEN** пользователь отправляет запрос без `to`
- **THEN** система создаёт задачу, в которой конец периода равен моменту создания задачи

### Requirement: Валидация параметров загрузки

Система MUST отклонять запрос до создания задачи, если категория рынка не `spot`, не `linear` и не `moex`, интервал не
входит в список интервалов категории, `from` не меньше `to`, `from` позже текущего момента, обязательный параметр не
указан или пуст, либо время указано без смещения от UTC. Ответ MUST указывать, какой параметр некорректен.

#### Scenario: Неподдерживаемая категория

- **WHEN** пользователь отправляет запрос с категорией `inverse`
- **THEN** система отклоняет запрос с ошибкой валидации по параметру категории, задача не создаётся

#### Scenario: Неподдерживаемый интервал

- **WHEN** пользователь отправляет запрос с интервалом `2`
- **THEN** система отклоняет запрос с ошибкой валидации по параметру интервала, задача не создаётся

#### Scenario: Пустой период

- **WHEN** пользователь отправляет запрос, где `from` равен `to`
- **THEN** система отклоняет запрос с ошибкой валидации по периоду, задача не создаётся

#### Scenario: Время без смещения

- **WHEN** пользователь отправляет `from` = `2024-01-01T00:00:00` без `Z` и без смещения
- **THEN** система отклоняет запрос с ошибкой валидации по параметру `from`, задача не создаётся

#### Scenario: Пропущен обязательный параметр

- **WHEN** пользователь отправляет запрос без символа или с пустым символом
- **THEN** система отклоняет запрос с ошибкой валидации по параметру символа, задача не создаётся

### Requirement: Проверка символа на бирже

Перед созданием задачи система MUST проверить, что символ существует на бирже категории: на Bybit для `spot` и `linear`,
на T-Invest для `moex`. Неизвестный символ MUST отклоняться с ошибкой валидации. Если биржа недоступна для проверки,
система MUST отклонить запрос с ошибкой недоступности внешнего сервиса, не создавая задачу.

#### Scenario: Неизвестный символ

- **WHEN** пользователь отправляет запрос на `spot` / `NOSUCHUSDT`, которого Bybit не знает
- **THEN** система отклоняет запрос с ошибкой валидации по символу, задача не создаётся

#### Scenario: Bybit недоступен при проверке

- **WHEN** пользователь отправляет запрос, а Bybit не отвечает на проверку символа
- **THEN** система отклоняет запрос с ошибкой недоступности внешнего сервиса, задача не создаётся

#### Scenario: Акция не TQBR

- **WHEN** пользователь отправляет запрос на `moex` / `NOPE`, которого нет среди акций TQBR с разрешённой API-торговлей
- **THEN** система отклоняет запрос с ошибкой валидации по символу, задача не создаётся
