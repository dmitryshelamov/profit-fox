# Proposal

## Why

Стратегии и составные узлы сейчас собираются только JSON-запросами через Swagger: граф из десятка узлов и проводов
приходится писать руками, а ошибку проверки искать по пути вида `graph.ladder1/mul2.b`. Роадмап называет следующим
этапом визуальный редактор — первый фронтенд profit-fox, в котором владелец собирает граф мышью в стиле UE Blueprints.
Бэкенд для этого готов: формат графа, проверка, библиотека и CRUD API есть с изменения 1.

## What Changes

- Новое веб-приложение `frontend/` (первый фронтенд). Экраны: список стратегий, список составных узлов, редактор
  стратегии и редактор составного узла. Интерфейс на русском.
- Редактор — холст на весь экран с плавающими панелями, как в ProfitGraph и Miro (макеты согласованы в Penpot):
  - узлы добавляются из палитры, провода соединяют только пины совместимого типа;
  - значение неподключённого входа задаётся на узле, а настройки узла (сторона, размер, операция) — в карточке узла;
  - параметры и направление стратегии, входы и выходы составного узла правятся в боковых карточках;
  - раскладка узлов сохраняется вместе с графом.
- Ошибки проверки показываются на графе почти сразу после правки: на узле, на пине и в списке ошибок. Пока ошибки
  есть, сохранить нельзя.
- Несохранённая правка хранится черновиком в браузере. При открытии редактор предлагает восстановить или отбросить
  черновик; уход со страницы с несохранёнными правками требует подтверждения. Новая стратегия до первого валидного
  сохранения существует только черновиком.
- Ответы сохранения, которые отклоняют правку, показываются понятно: ломающая правка составного узла — места
  использования с ошибками; правка, ломающая бота, — боты с ошибками; конфликт ревизии — сообщение, правки остаются в
  черновике.
- Встроенный составной узел открывается только на чтение, его можно клонировать в свой и править клон.
- Бэкенд: проверка стратегии и составного узла без сохранения — тот же ответ, что дало бы сохранение, но ничего не
  записывается. Каталог узлов описывает настройки простых узлов, чтобы редактор не хранил их у себя.
- Доставка: образ `web` на Caddy отдаёт приложение и проксирует `/api` в API (один адрес, без CORS), пока только HTTP.
  Локально — Vite dev server с прокси на API.
- CI: отдельная проверка фронтенда (lint, format, typecheck, unit-тесты, сборка) и сквозные тесты в браузере против
  настоящего API и Postgres.

Вне изменения: экраны ботов и бэктестов (изменение 3.1), HTTPS и авторизация, деплой на production, просмотр версий
стратегии, undo/redo, копирование и вставка узлов, сворачивание выделенных узлов в составной, список мест
использования составного узла вне ответа сохранения.

## Capabilities

### New Capabilities

- `strategy-editor`: веб-интерфейс библиотеки: списки стратегий и составных узлов, редактирование графа на холсте,
  показ ошибок проверки, черновики в браузере, исходы сохранения, работа со встроенными и пользовательскими
  составными узлами.
- `web-application`: как веб-приложение доступно в браузере: один адрес для интерфейса и API, прямые ссылки на экраны,
  кэширование статики.

### Modified Capabilities

- `strategy-library`: проверка стратегии и составного узла без сохранения; каталог описывает настройки простых узлов.

## Impact

- Новая папка `frontend/` (React, TypeScript, Vite, `@xyflow/react`, TanStack Query и Router, Tailwind,
  openapi-typescript, Vitest, Playwright) и раздел о фронтенде в `docs/conventions.md`.
- `ProfitFox.Application`: запросы проверки стратегии и узла без сохранения; описания настроек простых узлов в
  каталоге.
- `ProfitFox.Presentation`: эндпоинты `POST /api/strategies/validate`, `POST /api/strategies/{id}/validate`,
  `POST /api/strategy-nodes/validate`, `POST /api/strategy-nodes/{id}/validate`; поле `settings` в каталоге.
- Новые файлы доставки: `frontend/Dockerfile`, `frontend/Caddyfile`.
- CI: новые workflow для фронтенда и сквозных тестов рядом с `ci.yml`; pre-commit hook проверяет и `frontend/`.
- Бэкенд-эндпоинты существующих стратегий и узлов, формат графа и хранилище не меняются; миграций нет.
- Production-сервер не затрагивается: подключение образа `web` к production-compose — отдельный деплой владельца.
