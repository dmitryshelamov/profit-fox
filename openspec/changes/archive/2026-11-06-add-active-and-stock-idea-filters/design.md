# Design

## Context

- `GET /api/ideas` → `GetIdeasQueryHandler`: читает идеи, открытые сейчас и закрытые за 24 часа
  (`IIdeaRepository.GetRecentAsync`), фильтрует их в памяти по сетапу, ТФ, типу, стороне и категории, затем по
  ожиданию корзины и сохранённому фильтру, сортирует и режет на страницы. Новые фильтры встают в ту же цепочку.
- Статус идеи уже есть у каждой идеи (`IdeaStatus`: `AwaitingEntry`, `Active`, `Target`, `Stop`, `Expired`).
- Признака «акция» у нас нет нигде. Bybit отдаёт его в `instruments-info` полем `symbolType`, Bybit.Net 7.7.0 —
  `BybitSpotSymbol.SymbolType` и `BybitLinearInverseSymbol.SymbolType` (enum `SymbolType`: `Innovation`,
  `Adventure`, `XStocks`, `Commodity`, `Stock`, `Forex`, `Etf`). Сейчас (2026-11-07) в `linear`: 238 `stock`, 59 `ETF`,
  4 `commodity`, 4 `forex`, 111 `innovation`, 514 без типа; в `spot`: 11 `xstocks`, 3 `adventure`, 507 без типа.
- Список инструментов читает `BybitMarketDataClient.RequestListAsync` → `ListedInstrument`; сканер раз в
  `UniverseRefresh` (и сразу при старте) сводит его с известными парами в `ScannerUniverse.Merge` и сохраняет
  изменившиеся `ScannerPair` в `scanner_pairs`.

## Goals / Non-Goals

**Goals:**

- Два серверных фильтра в `GET /api/ideas` и два переключателя на экране «Идеи», запоминаемые в выборе экрана.
- Признак некриптовой пары хранится у пары сканера и обновляется вместе со списком.

**Non-Goals:**

- Экран «Рынок», страница пары, сохранённые фильтры и их редактор — без нового условия.
- Сканер по-прежнему ведёт некриптовые пары и создаёт по ним идеи; фильтр только скрывает их в списке.
- Калибровка, корзины и прогон идей не меняются.
- E2E-заглушка Bybit не получает некриптовую пару: фильтр проверяется юнит- и интеграционными тестами, а лишняя пара
  в заглушке сдвинула бы счётчики в других e2e-сценариях.

## Decisions

### 1. «Только активные» — статусы «Ждёт входа» и «Активна»

Решение владельца: «активные» — это идеи, по которым ещё можно войти или которые идут, то есть все незакрытые.
Параметр `ActiveOnly` (bool); `true` оставляет `AwaitingEntry` и `Active`. Альтернатива — фильтр по любому набору
статусов (`Status=...`) — гибче, но экран просит один переключатель, а лишний параметр не требует ни один тест.

### 2. «Скрыть акции» скрывает всё некриптовое

Решение владельца: скрываются не только акции компаний, но и ETF, сырьё и форекс — в списке остаётся только крипта.
Некриптовые типы: `Stock`, `XStocks`, `Etf`, `Commodity`, `Forex`. Криптовые — `Innovation`, `Adventure`, тип не задан,
и любой тип, который Bybit.Net не узнал: новая зона Bybit скорее окажется зоной монет, а ошибка в эту сторону лишь
оставит пару в списке. Подпись переключателя — «Скрыть акции», как просил владелец; подсказка
(`title`) перечисляет: «акции, xStocks, ETF, сырьё и форекс».

### 3. Признак — `bool TradFi` у пары, а не тип инструмента целиком

`ListedInstrument` и `ScannerPair` получают `TradFi` (по умолчанию `false`), `scanner_pairs` — колонку
`tradfi boolean NOT NULL DEFAULT false`. Перевод `SymbolType` → `TradFi` — в `BybitMarketDataClient`, рядом с
остальным разбором ответа Bybit; домен о типах Bybit не знает. Альтернатива — хранить сырой `symbol_type` или свой enum
класса актива: позволило бы позже отдельный фильтр по ETF, но сегодня этого не просит ни один сценарий, а значения без
теста — код вне обратной связи. Перейти на enum позже — одна миграция.

В глоссарий `CONTEXT.md` — термин «Некриптовая пара (TradFi)».

### 4. Обновление признака в `ScannerUniverse.Merge`

Известная пара, которая есть в списке, получает `TradFi` из списка, как сейчас `TickSize`; если признак изменился, пара
попадает в изменившиеся и сохраняется. Новая пара берёт признак из списка. Пара, ушедшая из списка, сохраняет
последний известный признак. Так после выкладки все пары получают признак на первом же перечитывании — при старте
сканера, — без отдельного шага миграции данных.

### 5. Фильтр в `GetIdeasQueryHandler` через пары сканера

`GetIdeasQuery` получает `ActiveOnly` и `HideTradFi`; `IdeasQueryParameters` — `ActiveOnly` и `HideStocks` (имя для
API — как на экране). Статус проверяется в той же лямбде, что сетап и сторона. Для `HideTradFi` обработчик читает
`IScannerPairRepository.GetAllAsync` (около 1,5 тыс. строк, раз в 15 секунд на открытый экран) и собирает множество
некриптовых инструментов; читает только когда флаг включён. Идея по паре, которой нет в `scanner_pairs`, считается
криптовой (по правилу «список ещё не прочитан»). Альтернативы: хранить признак в `ideas` — пришлось бы переписывать
идеи и прогон при смене типа; брать из снимка рынка — снимок не знает пар, ушедших с торгов, а закрытые идеи по ним
ещё видны 24 часа.

### 6. Экран и выбор

`IdeaFilters` получает `activeOnly` и `hideStocks` (по умолчанию `false`), `ideasQuery` передаёт их как
`ActiveOnly` / `HideStocks` только когда они `true`, как `NonNegativeExpectancy`. Два чекбокса — рядом с
«Ожидание ≥ 0 R», той же разметки; смена возвращает на первую страницу через уже существующий `set`.
`loadIdeasChoice` читает оба флага как `=== true`, так что выбор, сохранённый до изменения, даёт `false`.

## Risks / Trade-offs

- [Bybit.Net не узнаёт пустую строку или новый `symbolType` и падает при разборе] → пустая строка уже приходит сейчас у
  большинства инструментов, и текущий код читает список без ошибок; юнит-тест разбора ответа с `""`, `stock`,
  `xstocks`, `ETF`, `commodity`, `forex`, `innovation` закрепляет перевод.
- [Между выкладкой и первым перечитыванием списка «Скрыть акции» ничего не скрывает] → перечитывание идёт при старте
  сканера, окно — минуты; в спеке это правило «список ещё не прочитан».
- [Лишнее чтение `scanner_pairs` на каждый запрос с флагом] → одна таблица в полторы тысячи строк, чтение только при
  включённом флаге; кэш не нужен, пока список идей не тормозит из-за него (сейчас страница ~0,5 с из-за идей, не пар).

## Migration Plan

- FluentMigrator `ForwardOnlyMigration`: `ALTER TABLE scanner_pairs ADD COLUMN tradfi boolean NOT NULL DEFAULT false`.
  Значение по умолчанию остаётся: пара без прочитанного списка — криптовая.
- Выкладка обычная; повторный прогон идей не нужен. Откат кода совместим со схемой: старый код колонку не читает.
