**Расхождение 7.2: «Свободно» показывает 0 в режиме изолированной маржи.** Аккаунт владельца — единый торговый, режим
маржи — изолированная. По документации Bybit `/v5/account/wallet-balance` общие поля аккаунта (`totalAvailableBalance`
и другие) к изолированной марже неприменимы и приходят пустыми, а свободное по монете там считается как
`walletBalance - totalPositionIM - totalOrderIM - locked - bonus`. `BybitAccountClient.FreeAsync` читает
`TotalAvailableBalance ?? 0m` и показывает пустоту нулём. Решение 7 design рассчитано только на общий доступный остаток.
Исправлено по слову владельца «Да, исправить» задачей 4.4: `FreeAsync` берёт `totalAvailableBalance`, когда Bybit его
прислал, а при изолированной марже считает свободные USDT единого кошелька по формуле Bybit; USDT без чисел для расчёта —
`502` «Bybit не прислал свободные деньги аккаунта», пустота нулём не показывается. `Bybit.Net` 7.9.0 читает пустую строку
числа как `null` — ошибки разбора нет. Порт, контроллер и страница не менялись: `502` строка таблицы уже показывает
причиной. Design (решение 7) и spec («Баланс по запросу», сценарии «Изолированная маржа» и «Bybit не прислал число»)
дополнены. Стенд 7.2 поднят заново на чистой `bench_accounts` с новым одноразовым мастер-ключом: прежняя строка аккаунта
была зашифрована прежним ключом.
