# Design

## Context

Мотивация — `proposal.md`; требования — `specs/bot-interface`, `specs/backtest-interface`,
`specs/instrument-search` и дельты `bot-management`, `backtest-runs`, `backtest-results`. Термины — в `CONTEXT.md`
(«Бот», «Баланс бота», «Бэктест», «Результат бэктеста», «Версия движка», «Сравнение»).

Текущее состояние:

- API ботов и бэктестов есть с изменения 2: CRUD `/api/bots`, `POST/GET /api/bots/{botId}/backtests`,
  `GET /api/backtests/{id}`, `POST .../cancel`, `GET .../results?sort&order&offset&limit` (сортировка по любой
  метрике на сервере), `GET .../results/{combination}/details`. Ошибки проверки — `ValidationProblemDetails` с
  ключами `name`, `strategyId`, `category`, `symbol`, `balance`, `parameterValues.<имя>` у бота и ключами полей у
  бэктеста; недоступность биржи — `ProblemDetails` 503; детали другой версии движка — 409 с обеими версиями.
- Элемент списка ботов (`BotSummaryResponse`) — id, имя, стратегия, инструмент, интервал. Элемент списка бэктестов
  (`BacktestSummaryResponse`) — id, версия стратегии, период, статус, прогресс (в том числе `TotalCombinations`),
  время создания. «Бот изменился» считается только при чтении одного бэктеста (`GetBacktestQueryHandler`).
- Кривая капитала в деталях считается в `DetailsObserver`: закрытия свечей делятся на равные группы до 5000 точек,
  точка — время конца, капитал на конце, минимальный капитал. Свеча в `BarClosed` уже доступна.
- Клиент Bybit (`BybitMarketDataClient` на CryptoExchange.Net) регистрируется `services.AddBybit()` без настроек и
  всегда ходит на живой Bybit. `instruments-info` он уже читает для проверки символа и правил инструмента.
- Фронтенд из изменения 3: React 19, TanStack Router и Query, `openapi-fetch`, Tailwind, Vitest с `fakeApi`,
  Playwright через образ `web` на Caddy без Worker'а и без биржи. Раскладка — `docs/conventions.md`, раздел Frontend.
- Длительность в API — строка `TimeSpan` вида `01:00:00`, числа и деньги — десятичные строки.
- Образец — ProfitGraph (`~/RiderProjects/ProfitGraph/frontend`): `PriceEquityChart`, `modules/comparison`,
  `ComparePage`, `e2e/bybit-stub.ts`, `BybitRestClientFactory`.
- Макеты согласованы с владельцем в Penpot: файл «New File 1», страница «Макеты ботов и бэктестов», 8 экранов.

## Goals / Non-Goals

**Goals:**

- Логика, в которой можно ошибиться, — чистые функции TypeScript, проверенные unit-тестами по TDD: число значений
  диапазона и комбинаций, граница периода по умолчанию, привязка исполнений к точкам графика, разбор и запись набора
  сравнения, раскладка ошибок сервера по полям. Компоненты тонкие.
- Точные значения (деньги, цены, метрики) на странице берутся из десятичных строк API. В числа JavaScript строки
  превращаются только для отрисовки графика.
- Правила проверки бота и бэктеста остаются в домене; фронтенд показывает ответы сервера.

**Non-Goals:**

- Server-sent events и веб-сокеты для прогресса: хватает опроса раз в 2 секунды.
- Лимит комбинаций до запуска (решение 9) и значения комиссий по умолчанию в форме: фронтенд их не знает.
- Мобильная вёрстка: экраны рассчитаны на ноутбук и больше, как редактор.

## Decisions

### 1. Решения из обсуждения с владельцем

Зафиксированы в интервью 2026-11-02 и при согласовании макетов:

- **Детали результата** — один график за весь период, как `PriceEquityChart` в ProfitGraph: свечи на правой шкале,
  капитал на левой, метки входов и выходов, под графиком таблицы сделок и исполнений. Отклонены «только кривая
  капитала» (не видно, где стратегия входила) и окно свечей вокруг выбранной сделки (нет общей картины). Цену группы
  отдаёт бэкенд в точке кривой (решение 4), а не отдельный endpoint с фоновым сжатием, как в ProfitGraph.
- **Сравнение** в этом изменении, как `modules/comparison` и `/compare` в ProfitGraph (решение 7). Отклонено «только
  таблица с сортировкой»: результаты сетки с близкими метриками различаются формой кривой. Тепловая карта метрики по
  двум параметрам — идея на будущее.
- **Подсказки символа** из поиска инструментов биржи, как в ProfitGraph (`/api/market-data/instruments` и
  `<datalist>`). Отклонён свободный текст без подсказок: ошибка символа видна только после сохранения, и у баланса
  нет валюты.
- **Расширенные списки**: элемент списка ботов получает баланс и последний бэктест, элемент списка бэктестов —
  параметры, причину ошибки и «бот изменился» (решение 5). Отклонено «убрать колонки из макетов».
- **Сквозные тесты на заглушке Bybit** (решение 10), временно: владелец попросил пересмотреть это решение позже.
  Отклонены «без биржи в e2e» (создание бота и бэктеста не проверялось бы на настоящем API) и живой Bybit (тест
  недетерминирован и зависит от сети).
- **Один результат — отдельным endpoint** (решение 11), выбор владельца после ревью реализации. Отклонена проверка
  номера на фронтенде: часть посчитанных результатов нельзя было бы открыть.
- **Мелкие решения, принятые владельцем:** раздел «Боты» в шапке; бэктесты вложены в бота; бота можно создать из
  списка ботов и из списка стратегий; опрос раз в 2 секунды; период по умолчанию — 30 дней до последней закрытой
  свечи; переключатель «значение / диапазон» у каждого параметра; настройки симуляции свёрнуты; таблица результатов
  по доходности по убыванию, сортировка по клику на колонку.

### 2. Экраны и адреса

| Адрес | Страница | Что на ней |
| --- | --- | --- |
| `/bots` | `pages/bots` | список ботов |
| `/bots/new?strategyId=` | `pages/bot-editor` | новый бот; `strategyId` из списка стратегий |
| `/bots/$botId/edit` | `pages/bot-editor` | правка бота |
| `/bots/$botId` | `pages/bot` | бот и его бэктесты |
| `/bots/$botId/backtests/new` | `pages/backtest-setup` | форма бэктеста |
| `/backtests/$backtestId` | `pages/backtest` | ход и результаты |
| `/backtests/$backtestId/results/$combination` | `pages/backtest-result` | детали результата |
| `/compare?items=` | `pages/compare` | сравнение |

Бэктест адресуется своим id, как в API: его страница не зависит от того, как на неё пришли, а путь к боту строится
по `botId` из ответа. Модули: `bots` (запросы, форма, раскладка ошибок), `backtests` (запросы, диапазоны, период,
таблица результатов), `market-data` (поиск инструментов, интервалы), `market-chart` (графики), `comparison` (набор и
панель). `AppShell` получает пункт «Боты» и панель сравнения; `StrategyActions` — действие «Создать бота».

### 3. Опрос незавершённых бэктестов

Запрос бэктеста и списка бэктестов бота ставит `refetchInterval` 2000 мс, пока статус не `Succeeded`, `Failed` или
`Cancelled`. На странице бэктеста вместе с ним обновляется текущая страница результатов. Когда бэктест завершился,
запросы перестают опрашиваться, а список ботов и список бэктестов бота помечаются устаревшими. SSE отклонены: опрос
укладывается в существующий API, а нагрузка от одного владельца ничтожна.

### 4. OHLC в точке кривой капитала

`DetailsObserver.BarClosed` уже получает свечу. Вместо пары «время и капитал» он хранит закрытие целиком (свеча и
капитал), а `Curve()` для каждой группы дополнительно берёт open time и open первой свечи, наибольший high,
наименьший low и close последней. `EquityPoint` и `EquityPointResponse` получают поля `openTime`, `open`, `high`,
`low`, `close`; существующие поля не меняются. Детали и так пересчитываются по свечам, поэтому ни нового запроса к
базе, ни нового endpoint не нужно.

Отклонены: отдельный endpoint графика с фоновым сжатием, как в ProfitGraph (новая таблица и фоновая работа ради
данных, которые уже есть при пересчёте), и чтение свечей фронтендом через `/api/market-data/candles` (там максимум
5000 свечей за запрос и нет агрегации).

### 5. Расширенные элементы списков

- **Список ботов.** Последний бэктест каждого бота читается одним запросом к `backtests` с
  `DISTINCT ON (bot_id) ... ORDER BY bot_id, created_at DESC`, не запросом на бота. `BotSummaryResponse` получает
  `balance` (десятичная строка) и `lastBacktest` (`id`, `status`, `progress`) или `null`.
- **Список бэктестов бота.** `GetBotBacktestsQuery` уже читает бота; обработчик один раз читает номер последней
  версии стратегии и считает `BotChanged` для каждого бэктеста той же функцией, что и чтение одного бэктеста.
  `BacktestSummaryResponse` получает `parameters` (тот же JSON значений и диапазонов, что у `BacktestResponse`),
  `error` и `botChanged`. Число комбинаций фронтенд берёт из `progress.totalCombinations`.

Поля только добавляются, поэтому существующие клиенты и тесты контрактов не ломаются.

### 6. Поиск инструментов

- **Application.** Порт `IInstrumentCatalog.ListAsync(category)` возвращает все инструменты категории (символ, базовая
  монета, монета котировки). Запрос `SearchInstrumentsQuery(category, query, limit)` фильтрует их по подстроке без
  учёта регистра и упорядочивает: сначала символы, начинающиеся с запроса, затем остальные, внутри — по символу
  ординально. Фильтр и порядок — чистая функция с unit-тестами.
- **Infrastructure.** `BybitMarketDataClient` реализует порт: `GetSpotSymbolsAsync()` и
  `GetLinearInverseSymbolsAsync(linear)` без символа, с переходом по курсору, если Bybit отдаёт список страницами.
  Ошибки идут через тот же `ExchangeResilienceExecutor`, что у проверки символа. Над ним — кэш в памяти на категорию
  на 5 минут (`TimeProvider`, чтобы тест управлял временем): форма бота запрашивает поиск на каждое нажатие клавиши,
  а список инструментов меняется редко.
- **Presentation.** `GET /api/market-data/instruments?category&query&limit` → массив `{ category, symbol, baseCoin,
  quoteCoin }`. Ошибки полей — `ValidationProblemDetails`, недоступность биржи — 503, как при создании бэктеста.

Валюту баланса фронтенд получает поиском по точному символу: `query = symbol`, берётся инструмент с тем же символом.
Отклонено поле валюты котировки в ответе бота: его пришлось бы хранить или запрашивать у биржи при каждом чтении.

### 7. Набор для сравнения

- Элемент набора — пара «id бэктеста, номер комбинации». Набор хранится в `sessionStorage` вкладки (ключ
  `profit-fox-comparison`), а страница сравнения получает его из адреса `?items=<id>:<номер>,<id>:<номер>`. Ссылкой
  можно поделиться; открытая ссылка заменяет набор вкладки.
- Хранилище — маленький модуль на `useSyncExternalStore` поверх `sessionStorage`, без новой зависимости (в ProfitGraph
  это `zustand`). Разбор и запись адреса, добавление с лимитом 6, снятие и очистка — чистые функции с тестами.
  Ошибочные элементы адреса пропускаются, лишние после шестого отбрасываются.
- Страница запрашивает бэктест и его результат для таблицы; результат читается через
  `GET /api/backtests/{id}/results/{combination}` (решение 11). Кривые берутся из деталей, по одному запросу на
  результат, параллельно; таблица видна сразу.
  404 убирает элемент из набора с сообщением, 409 оставляет его без кривой.
- Строки параметров — объединение имён параметров всех результатов в порядке первого появления; «—», где параметра нет.
  Цвет результата — по позиции в наборе, из шести токенов темы.

### 8. Графики

`lightweight-charts` — как в ProfitGraph: свечи и линии, две ценовые шкалы, метки серии (`createSeriesMarkers`), без
canvas-кода у нас. Модуль `market-chart`:

- `drawable(points)` — единственное место, где десятичные строки становятся числами; повторное или неупорядоченное
  время отбрасывается, потому что библиотеке нужны строго возрастающие времена.
- `markersOf(points, fills)` — для каждого исполнения находит точку, у которой `openTime ≤ at`, а у следующей точки
  `openTime > at`; несколько исполнений одной стороны в одной точке дают одну метку с числом. Чистая функция с тестами,
  включая исполнение на границе групп.
- Время — UTC: метки времени передаются в секундах UTC, ось подписывается в UTC.
- Число свечей в точке фронтенд выводит из интервала бэктеста и расстояния между `openTime` соседних точек.

В jsdom canvas нет, поэтому в Vitest библиотека подменяется в `test/setup.ts`, как в ProfitGraph. Видимую часть
графика проверяют сквозные тесты.

### 9. Форма бэктеста: период и счётчик комбинаций

- **Граница последней закрытой свечи** — функция от текущего времени и интервала: для минутных интервалов — начало
  текущего интервала от полуночи UTC, для `D` — полночь UTC, для `W` — понедельник 00:00 UTC (недели Bybit начинаются
  с понедельника), для `M` — первое число месяца. Период по умолчанию — 30 дней до этой границы; «90 дней» и «год»
  считаются от неё же. Это подсказка в форме: сервер всё равно проверяет, что последняя свеча закрыта.
- **Число значений диапазона** считается точно: десятичные строки переводятся в целые `BigInt` с общим масштабом,
  длительности — в секунды. Диапазон не раскладывается, если шаг не больше нуля, `min > max` или `max − min` не
  делится на шаг. Остальные правила (целые числа, ограничения параметра) проверяет только сервер. Число комбинаций —
  произведение, тоже в `BigInt`, чтобы большие сетки не теряли точность.
- **Лимит комбинаций** фронтенд не знает: он задаётся в настройках сервиса (`Backtests:MaxCombinations`). Счётчик
  показывает число, а превышение лимита приходит ошибкой сервера с числом комбинаций и лимитом и показывается у
  счётчика. Это отступление от принятого «счётчик с лимитом»: отдавать настройки сервиса ради одной подписи не стоит.
  Так же значения комиссий по умолчанию показываются уже на странице созданного бэктеста, а форма подписывает их
  «по умолчанию сервиса».

### 10. Сквозные тесты на заглушке Bybit (временно, пересмотреть)

- **Настройка адреса.** Секция `Bybit` с полем `RestAddress` (`BybitSettings` в Infrastructure: настройка нужна только
  ей). Без значения клиент ходит на живой Bybit, как сейчас. Со значением `AddBybit` получает
  `BybitEnvironment.CreateCustom("profit-fox", address, BybitEnvironment.Live.SocketBaseAddress)` — так же, как
  `BybitRestClientFactory` в ProfitGraph, где адрес вида `http://127.0.0.1:5296` работает без TLS. Настройка
  описывается в `docs/conventions.md`, раздел Settings.
- **Заглушка.** `frontend/e2e/bybit-stub.ts` на `node:http`: `/v5/market/instruments-info` (spot и linear, с фильтрами
  цены и лота), `/v5/market/kline` (детерминированные свечи от фиксированной даты листинга, новые первыми, `limit`),
  `/v5/market/time`, `/health`. Любой другой путь отвечает 404 «Not stubbed», чтобы ничего не ушло на настоящую биржу.
  Формат ответов повторяет `FakeBybitHandler` из интеграционных тестов.
- **Процессы.** В `webServer` добавляются заглушка и Worker (`dotnet run` проекта `ProfitFox.Worker` с той же базой и
  `Bybit__RestAddress`, стартует после ответа API). API тоже получает `Bybit__RestAddress`. Веб по-прежнему из образа
  Caddy.
- **Тесты** — только критерии приёмки: создание бота с подсказкой символа и ошибкой поля; бэктест с диапазонами до
  `Succeeded` с точными метриками лучшей комбинации на свечах заглушки; сортировка; детали с графиком и метками;
  сравнение двух результатов по ссылке; отмена.

Решение временное по просьбе владельца: см. Open Questions.

### 11. Чтение одного результата

Сохранённые результаты идут с пропусками номеров, пока бэктест считается, а также после отмены или ошибки: Worker'ы
берут куски независимо и внутри куска сдают результаты пачками вразнобой. Поэтому страница результатов с
`sort=combination` и `offset=<номер>` не адресует комбинацию: при пропуске раньше номера она вернёт другую
комбинацию, при пропуске на месте номера — пустую страницу.

`GET /api/backtests/{id}/results/{combination}` читает результат из тех же результатов с фильтром по номеру и отвечает
тем же `BacktestResultResponse`, что элемент списка; неизвестный бэктест или комбинация без сохранённого результата —
404. Страница результата и сравнение читают результат только так.

Отклонены: проверка номера найденной строки на фронтенде (результат после пропуска нельзя было бы открыть и сравнить,
хотя он посчитан) и параметр `combination=` у списка результатов (смешивает поиск одного результата со страницами).

## Risks / Trade-offs

- [Детали пересчитываются на каждый запрос, и сравнение шести результатов за длинный период на минутках
  открывается секунды] → таблица видна сразу, кривые загружаются параллельно и появляются по одной; детали кэшируются
  в TanStack Query, пока открыта вкладка.
- [Опрос раз в 2 секунды при нескольких открытых вкладках умножает запросы] → один владелец и лёгкие запросы чтения;
  опрос останавливается, когда бэктест завершён, и не идёт в фоновой вкладке (`refetchIntervalInBackground: false`).
- [Метки исполнений на сжатом графике сливаются] → метка показывает число исполнений в точке; точные значения — в
  таблицах сделок и исполнений.
- [Список инструментов Bybit в кэше устаревает до 5 минут] → это только подсказки; символ при сохранении бота
  проверяет сервер напрямую у биржи.
- [Набор сравнения ссылается на результаты, которые удалили вместе с ботом] → такой элемент убирается с сообщением.
- [Заглушка Bybit расходится с настоящим форматом ответов] → она повторяет ответы `FakeBybitHandler`, которые
  интеграционные тесты уже сверяют с клиентом; живой Bybit в CI не вызывается.
- [`lightweight-charts` рисует на canvas, а в jsdom его нет] → в unit-тестах библиотека подменяется, логика графика —
  в чистых функциях, а отрисовку проверяют сквозные тесты.

## Migration Plan

Миграций базы нет: новые поля читаются из существующих таблиц. Поля API только добавляются. Настройка
`Bybit:RestAddress` в production не задаётся, клиент ведёт себя как сейчас. Фронтенд выкатывается вместе с API тем же
деплоем владельца, что и редактор. Откат — предыдущие образы `web`, API и Worker.
