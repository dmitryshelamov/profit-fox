# Spec Delta

## MODIFIED Requirements

### Requirement: Чтение стратегий

Система SHALL возвращать стратегию по идентификатору: имя, определение графа, направление, поддерживаемые категории
рынка и номер последней версии. Список стратегий SHALL содержать идентификатор, имя и направление каждой. Неизвестный
идентификатор SHALL давать ответ «не найдено».

#### Scenario: Чтение сохранённой стратегии

- **WHEN** пользователь запрашивает сохранённую стратегию по идентификатору
- **THEN** система возвращает то же определение графа, что было сохранено

#### Scenario: Неизвестная стратегия

- **WHEN** пользователь запрашивает стратегию по идентификатору, которого нет
- **THEN** система отвечает «не найдено»

#### Scenario: Номер версии

- **WHEN** стратегию создали и затем один раз изменили её граф
- **THEN** чтение стратегии возвращает номер последней версии `2`

### Requirement: Изменение и удаление стратегии

Система SHALL заменять имя и определение стратегии новым валидным определением. Изменение с ошибками проверки MUST
отклоняться, а сохранённая стратегия MUST оставаться прежней. Система SHALL удалять стратегию по идентификатору вместе
с её версиями. Стратегию, у которой есть хотя бы один бот, MUST NOT удаляться: ответ — конфликт со списком ботов.

#### Scenario: Изменение с ошибками

- **WHEN** пользователь изменяет стратегию так, что в графе появляется цикл
- **THEN** система отклоняет изменение с ошибкой цикла, и чтение стратегии возвращает прежнее определение

#### Scenario: Удаление стратегии

- **WHEN** пользователь удаляет стратегию без ботов
- **THEN** чтение этой стратегии отвечает «не найдено»

#### Scenario: Удаление стратегии с ботами

- **WHEN** пользователь удаляет стратегию EMA, на которой создан бот «EMA BTC»
- **THEN** система отвечает конфликтом, перечисляя бота «EMA BTC», и стратегия остаётся

## ADDED Requirements

### Requirement: Версии стратегии

Каждая стратегия SHALL иметь версии с номерами от `1`. Версия SHALL хранить определение стратегии вместе с
определениями всех составных узлов, которые она использует напрямую или через другие узлы, включая встроенные, и
MUST NOT меняться после создания. Создание стратегии SHALL создавать версию `1`.

#### Scenario: Первая версия

- **WHEN** пользователь создаёт стратегию Ladder
- **THEN** у стратегии есть версия `1` с её графом и определением встроенного узла `Ladder`

### Requirement: Новая версия при изменении

Сохранение стратегии SHALL создавать версию со следующим номером, если изменилось что-либо, влияющее на исполнение:
параметры, направление, узлы, провода, значения входов. Изменение только имени или координат узлов MUST NOT создавать
версию.

#### Scenario: Изменён граф

- **WHEN** у стратегии версии `1` пользователь меняет значение на входе узла и сохраняет
- **THEN** у стратегии появляется версия `2`

#### Scenario: Изменены только координаты

- **WHEN** пользователь сохраняет стратегию, переместив только узлы на холсте
- **THEN** номер последней версии не меняется

### Requirement: Версии при правке составного узла

Совместимая правка пользовательского составного узла SHALL создавать новую версию каждой стратегии, которая использует
его напрямую или через другие составные узлы. Прежние версии MUST оставаться неизменными.

#### Scenario: Правка узла создаёт версию стратегии

- **WHEN** стратегия версии `3` использует узел «Моя лесенка», внутри которого стоит «Моё пересечение», и пользователь
  совместимо правит «Моё пересечение»
- **THEN** у стратегии появляется версия `4` с новым «Моим пересечением», а версия `3` исполняется по-прежнему

### Requirement: Чтение версии

Система SHALL возвращать версию стратегии по идентификатору стратегии и номеру: номер, время создания, определение
стратегии и определения использованных составных узлов. Неизвестная стратегия или номер SHALL давать ответ «не
найдено».

#### Scenario: Чтение старой версии

- **WHEN** у стратегии версии `1` и `2`, и пользователь запрашивает версию `1`
- **THEN** система возвращает граф стратегии, каким он был в версии `1`

### Requirement: Правка стратегии, ломающая бота

Изменение стратегии, после которого настройки хотя бы одного её бота стали бы невалидными (нет параметра, которому бот
задал значение; значение бота нарушает новые ограничения; категория инструмента бота не поддерживается новым
направлением), MUST отклоняться со списком таких ботов и их ошибок. Стратегия MUST оставаться прежней.

#### Scenario: Удалён параметр со значением у бота

- **WHEN** бот «EMA BTC» задаёт `fast` = `10`, и пользователь удаляет параметр `fast` из стратегии EMA
- **THEN** система отклоняет изменение, перечисляя бота «EMA BTC» и ошибку по `fast`, и стратегия не меняется

#### Scenario: Смена направления

- **WHEN** у лонг-стратегии есть бот на `spot`, и пользователь меняет направление стратегии на шорт
- **THEN** система отклоняет изменение, перечисляя этого бота и ошибку по категории инструмента

#### Scenario: Совместимое изменение

- **WHEN** у стратегии EMA есть бот, и пользователь добавляет в граф узел, не трогая параметры и направление
- **THEN** изменение сохраняется, и бот использует новую версию
