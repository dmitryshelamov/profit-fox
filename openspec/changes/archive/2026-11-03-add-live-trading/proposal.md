# Proposal

## Why

Бот сейчас только проходит бэктесты: у него есть стратегия, инструмент, баланс и аккаунт биржи, но торговать он не
может. Это изменение — безопасное ядро живой торговли (изменение 5 дорожной карты): бот торгует на Bybit реальными
деньгами, не теряет и не дублирует ордера после рестарта или обрыва связи и останавливается, когда его позиция
расходится с биржей. Удобство (ручное вмешательство на бирже, уведомления, живой график, подхват правок стратегии без
перезапуска) уходит в изменение 5.1.

## What Changes

- Запуск бота: бот с аккаунтом биржи запускается на последней версии своей стратегии и последних значениях
  параметров, которые фиксируются до следующего запуска. При запуске проверяется, что свободных денег аккаунта хватает
  на баланс бота вместе с балансами других запущенных ботов этого аккаунта.
- Действия с ботом: «Запустить», «Пауза» (стратегия не реагирует, ордера и позиция остаются, учёт исполнений и
  правила позиции работают), «Остановить» (активные ордера бота отменяются, позиция остаётся) и «Закрыть позицию»
  (продажа по рынку у остановленного бота). Статусы бота: остановлен, запущен, пауза, ошибка с причиной.
- Торгующий Worker: бота ведёт Worker с включённой торговлей и мастер-ключом. Бот берётся под аренду с ограждающим
  номером, в каждый момент его ведёт ровно один Worker; один Worker ведёт много ботов. Worker'ы без торговли ключа не
  получают, как раньше.
- События с биржи по WebSocket: закрытые свечи — из публичного потока, ордера и исполнения — из приватного потока
  аккаунта. После каждого переподключения и после рестарта пропущенное догружается по REST.
- Ордера уходят на биржу через outbox: команда стратегии сначала записывается в базу в одной транзакции с позицией,
  затем отправляется. Каждый ордер несёт детерминированный `orderLinkId`, поэтому повтор отправки не создаёт второй
  ордер.
- Позиции, ордера и исполнения живого бота хранятся в базе; после рестарта бот восстанавливается из базы, прогревает
  индикаторы по последним закрытым свечам и сверяется с биржей.
- Сверка: позиция на бирже (`linear`) или монеты на аккаунте (`spot`) сравниваются с суммой позиций запущенных ботов
  этого аккаунта и инструмента. Расхождение останавливает всех этих ботов с причиной.
- Несколько запущенных ботов могут делить один аккаунт и один инструмент: исполнения относятся к ботам по
  `orderLinkId`.
- Отказы биржи: временные (лимит запросов, сбой Bybit, таймаут) повторяются с паузой, постоянные (нет денег, правила
  инструмента, неверный параметр) останавливают бота с причиной.
- `hold-limit` после частичного исполнения: ордер с исполнением не перевыставляется из-за размера, только из-за цены
  или ложного «когда». Бэктест от этого не меняется.
- Запущенный бот и бот на паузе не правятся и не удаляются; аккаунт и инструмент меняются только при пустой позиции.
- **BREAKING**: окружение testnet убирается из продукта. Аккаунт биржи — только основная сеть Bybit; поле окружения,
  выбор окружения в форме и метка «Testnet» удаляются из API и интерфейса.
- Страница бота показывает статус, действия, текущую позицию с ордерами и исполнениями и закрытые позиции; список
  ботов — статус.
- Заглушка Bybit для e2e получает WebSocket: свечи, ордера, исполнения и обрыв соединения.
- Входа и пользователей по-прежнему нет: API открыт локальной сети. Решение владельца, к нему вернуться до первого
  запуска на mainnet.

Вне изменения: ручное вмешательство на бирже (чужие ордера, ручное закрытие позиции на бирже), уведомления, живой
график, подхват правок стратегии запущенным ботом, вход и пользователи, testnet, другие биржи, режим hedge в `linear`,
плечо больше 1x, funding.

## Capabilities

### New Capabilities

- `live-trading`: живая торговля бота — запуск, пауза, остановка и закрытие позиции, ведение бота Worker'ом под
  арендой, события с биржи, отправка ордеров через outbox, хранение позиций, восстановление после рестарта, сверка с
  биржей и обработка отказов.
- `live-trading-interface`: веб-интерфейс живой торговли — статус бота в списке и на странице, действия с ботом,
  текущая и закрытые позиции живого бота.

### Modified Capabilities

- `strategy-execution`: «держать лимитку» не перевыставляет частично исполненный ордер из-за размера.
- `background-workers`: Worker может вести ботов; торговлю включает настройка, мастер-ключ нужен только такому
  Worker'у; аренда бота с ограждающим номером.
- `exchange-accounts`: окружение testnet убирается; аккаунт — только основная сеть, UID уникален без окружения.
- `exchange-account-interface`: выбор окружения и метка «Testnet» убираются.
- `bot-management`: аккаунт бота без окружения; запущенный бот и бот на паузе не правятся и не удаляются; аккаунт и
  инструмент меняются только при пустой позиции; чтение бота возвращает его статус.
- `bot-interface`: метка «Testnet» на странице и в списке ботов убирается; правка и удаление недоступны у запущенного
  бота.

## Impact

- Backend: новая область живой торговли в Domain, Application и Infrastructure (рантайм бота в Worker'е, клиенты
  WebSocket и REST Bybit с ключом аккаунта, unit of work и outbox, репозитории позиций, ордеров и исполнений, аренда
  бота), миграции новых таблиц и удаление окружения у `exchange_accounts`; новые эндпоинты действий с ботом; правка
  `StrategyRun` для частичных исполнений и восстановления из сохранённой позиции.
- API: `POST /api/bots/{id}/start|pause|resume|stop|close-position`, статус и позиции живого бота в ответах; поле
  `environment` аккаунта удаляется из запросов и ответов (**BREAKING** для клиента, клиент один — наш frontend).
- Worker: настройки `Trading` (включение, мастер-ключ); прод-Worker на `soyo-01` получает их при деплое — правка
  `docker-compose.prod.yml` и `.env.prod*` только с разрешения владельца.
- Frontend: статус и действия на странице и в списке ботов, позиции живого бота, удаление окружения из модуля
  `exchange-accounts`, перегенерация `schema.d.ts`; WebSocket в `frontend/e2e/bybit-stub.ts`.
- `CONTEXT.md`: термины «Запущенный бот», «Пауза», «Остановка», «Сверка», «Аренда бота»; правка «Аккаунт биржи» без
  окружения.
- Риск: тестов против настоящего Bybit нет, первый контакт с реальным поведением биржи — первый запуск на mainnet.
