# Стенд гипотез: ядро графа и прогон без интерфейса

## Why

Сигналы, стратегии бота и стенд гипотез должны считать одно и то же одним кодом: сигнал собирается в конструкторе как
граф, стенд проверяет его против случайных входов, бот ставит прошедший сигнал в стратегию как есть. Прошлая попытка
(удалённые PR #3 и #5) не проверялась на реальных данных и разошлась с Python-стендом. Поэтому первый шаг — один
сквозной прогон H0001 на реальной истории, совпадающий с Python-стендом, без интерфейса.

## What Changes

- Формат графа стратегии (формат v2: `formatVersion` 1, входы и выходы, узлы, провода) с новым типом пина «событие» и
  трёхзначной логикой для отсутствующих значений.
- Исполнитель графа по закрытым свечам таймфрейма и узлы, нужные H0001: параметры, свеча, фандинг, сравнение,
  предыдущее, «и», «или», «не», «впервые», выход «событие».
- «План сделки» (сторона, срок, по желанию стоп и цель) и исход сделки по минутам после комиссий, проскальзывания и
  фандинга — по правилам Python-стенда. В файле гипотезы план лежит рядом с сигналом; узлом на холсте он станет вместе с
  конструктором.
- Чтение истории из сервиса `profit-fox-market-data` потоком gRPC `History` (свечи и выплаты фандинга) на каждом
  прогоне, без своей копии истории.
- Гипотеза — папка с `hypothesis.json`: утверждение, параметры проверки, граф сигнала и план сделки. Файл
  замораживается хэшем.
- Прогон: периоды по фиксированным датам, случайные входы, вердикт по средним за блоки с порогом t по числу попыток и
  мощностью вслепую, журнал прогонов только на дописывание, отчёт в markdown, команда `bench run`.
- Сверка с Python-стендом `profit-fox-bench` на тех же реальных данных: события, исходы сделок и вердикт.
- Без интерфейса, без бота, без узлов заявок и позиции, без узлов по всему рынку.

## Capabilities

### New Capabilities

- `strategy-graph`: формат графа, типы пинов (в том числе «событие»), проверка графа, сигнал как составной узел с одним
  выходом «событие».
- `strategy-execution`: исполнение графа по закрытым свечам, отсутствующие значения, узлы данных и логики, узел
  «впервые».
- `trade-plan-outcome`: план сделки и правила исхода сделки по минутному пути с издержками.
- `market-history`: чтение свечей и фандинга из потока `History`, покрытие, хэш прочитанного, границы
  периода.
- `hypothesis-bench`: файл гипотезы и его заморозка, периоды, случайные входы, вердикт, журнал прогонов, отчёт и
  команда прогона.

### Modified Capabilities

Нет: в репозитории ещё нет спецификаций.

## Impact

- Код: `ProfitFox.Engine.Strategy` (граф, исполнитель, узлы), `ProfitFox.Engine.Simulation` (исход плана сделки),
  `ProfitFox.Bench` (история, гипотезы, прогон, вердикт, журнал, отчёт), `ProfitFox.Bench.Cli` (команды), тесты в
  `ProfitFox.Tests.Unit` и `ProfitFox.Tests.Integration`.
- Файлы в репозитории: `bench/hypotheses/`, `bench/ledger.jsonl`, `bench/reports/`, `bench/parity/`.
- Зависимости: `Grpc.Net.Client`, `Google.Protobuf`, `Grpc.Tools` (клиент по копиям `candle_feed.proto` и
  `funding_payment_feed.proto` из `profit-fox-market-data`).
- Внешние системы: gRPC `History` и REST `api/instruments` сервиса данных на soyo-02 (`192.168.8.213`, порты 5237 и
  5236) — только чтение. Для сверки нужен локальный Python-стенд `../profit-fox-bench`.
