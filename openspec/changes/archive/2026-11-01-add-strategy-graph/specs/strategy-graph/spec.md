# Spec Delta

## Purpose

Формат графа стратегии и составного узла и правила его корректности, чтобы стратегию можно было собрать из узлов
библиотеки, проверить до сохранения и однозначно исполнить в бэктесте и в боте.

## ADDED Requirements

### Requirement: Версия формата

Определение стратегии и составного узла SHALL содержать `formatVersion`. Система SHALL принимать только версию `1` и
MUST отклонять определение с другой или отсутствующей версией.

#### Scenario: Неизвестная версия формата

- **WHEN** пользователь сохраняет стратегию с `formatVersion` = `2`
- **THEN** система отклоняет сохранение с ошибкой по `formatVersion`, стратегия не сохраняется

### Requirement: Узлы графа

Граф SHALL состоять из узлов с идентификатором, уникальным в пределах графа, и видом узла из библиотеки: простым узлом
или ссылкой на составной узел. Узел с повторяющимся идентификатором или неизвестным видом MUST делать граф невалидным.

#### Scenario: Повторяющийся идентификатор узла

- **WHEN** в графе два узла с идентификатором `ema1`
- **THEN** проверка сообщает об ошибке повторяющегося идентификатора `ema1`

#### Scenario: Неизвестный вид узла

- **WHEN** в графе есть узел вида `rsi`, которого нет в библиотеке
- **THEN** проверка сообщает об ошибке неизвестного вида узла с идентификатором этого узла

#### Scenario: Ссылка на несуществующий составной узел

- **WHEN** узел графа ссылается на пользовательский составной узел, которого нет в библиотеке
- **THEN** проверка сообщает об ошибке неизвестного составного узла

### Requirement: Типы пинов

Каждый вход и выход узла SHALL иметь один тип из списка: число, логическое значение, длительность. Числа SHALL
представляться десятичными значениями без потери точности.

#### Scenario: Точность числа

- **WHEN** на вход узла подано значение `0.1` и граф сохранён и прочитан обратно
- **THEN** значение входа равно ровно `0.1`

### Requirement: Провода данных

Провод SHALL соединять выход одного узла со входом другого узла того же типа. Вход SHALL принимать не больше одного
провода. Провод к несуществующему узлу или пину, провод между пинами разных типов и второй провод на вход MUST делать
граф невалидным.

#### Scenario: Несовместимые типы

- **WHEN** логический выход узла соединён с числовым входом
- **THEN** проверка сообщает об ошибке несовместимых типов с указанием обоих пинов

#### Scenario: Два провода на один вход

- **WHEN** на вход `a` узла `mul1` приходят два провода
- **THEN** проверка сообщает об ошибке по входу `a` узла `mul1`

#### Scenario: Провод к несуществующему пину

- **WHEN** провод ведёт к входу `c` узла, у которого нет входа `c`
- **THEN** проверка сообщает об ошибке неизвестного пина

### Requirement: Значение неподключённого входа

Вход без провода SHALL брать значение, заданное прямо на входе, того же типа, что и вход. Вход без провода и без
значения MUST делать граф невалидным.

#### Scenario: Значение на входе

- **WHEN** вход `period` узла EMA не подключён и на нём задано значение `20`
- **THEN** граф валиден, и EMA считается с периодом `20`

#### Scenario: Вход без провода и без значения

- **WHEN** вход `period` узла EMA не подключён и значения на нём нет
- **THEN** проверка сообщает об ошибке незаданного входа `period`

### Requirement: Граф без циклов

Провода данных MUST NOT образовывать цикл. Граф, в котором значение узла зависит от самого себя через провода, MUST
быть невалидным.

#### Scenario: Цикл через два узла

- **WHEN** выход узла `add1` подключён ко входу `mul1`, а выход `mul1` — ко входу `add1`
- **THEN** проверка сообщает об ошибке цикла с перечислением узлов цикла

### Requirement: Параметры стратегии

Стратегия SHALL объявлять параметры: имя, уникальное в стратегии, тип (число или длительность), значение по умолчанию и
необязательные минимум, максимум и признак целого числа. Значение по умолчанию MUST удовлетворять этим ограничениям.
Узлы графа SHALL получать значения параметров через узел параметров.

#### Scenario: Повторяющееся имя параметра

- **WHEN** стратегия объявляет два параметра `fast`
- **THEN** проверка сообщает об ошибке повторяющегося параметра `fast`

#### Scenario: Значение по умолчанию вне ограничений

- **WHEN** параметр `fast` объявлен с минимумом `2`, максимумом `200` и значением по умолчанию `1`
- **THEN** проверка сообщает об ошибке значения по умолчанию параметра `fast`

#### Scenario: Дробное значение целого параметра

- **WHEN** параметр `slow` объявлен целым со значением по умолчанию `20.5`
- **THEN** проверка сообщает об ошибке значения по умолчанию параметра `slow`

#### Scenario: Ссылка на необъявленный параметр

- **WHEN** узел параметров выдаёт параметр `amount`, который стратегия не объявляет
- **THEN** проверка сообщает об ошибке неизвестного параметра `amount`

### Requirement: Направление стратегии

Стратегия SHALL объявлять направление: лонг или шорт. Лонг-стратегия SHALL поддерживать категории рынка `spot` и
`linear`, шорт-стратегия — только `linear`. Поддерживаемые категории SHALL возвращаться вместе со стратегией.

#### Scenario: Шорт-стратегия

- **WHEN** пользователь читает сохранённую стратегию с направлением «шорт»
- **THEN** её поддерживаемые категории — только `linear`

#### Scenario: Лонг-стратегия

- **WHEN** пользователь читает сохранённую стратегию с направлением «лонг»
- **THEN** её поддерживаемые категории — `spot` и `linear`

### Requirement: Входы и выходы составного узла

Составной узел SHALL объявлять входы и выходы с именами и типами. Внутри графа составного узла SHALL быть узел входов,
выдающий объявленные входы, и узел выходов, принимающий объявленные выходы. Объявленный выход без провода внутри MUST
делать составной узел невалидным.

#### Scenario: Выход без источника

- **WHEN** составной узел объявляет выход `down`, а внутри к нему не подключён ни один провод
- **THEN** проверка сообщает об ошибке неподключённого выхода `down`

#### Scenario: Пины составного узла снаружи

- **WHEN** составной узел с входами `fast`, `slow` и выходами `up`, `down` поставлен в стратегию
- **THEN** в стратегии у этого узла входы `fast`, `slow` и выходы `up`, `down` с объявленными типами

### Requirement: Раскрытие составных узлов

Перед проверкой и исполнением составные узлы SHALL раскрываться в простые узлы, в том числе вложенные составные узлы.
Ошибка внутри составного узла SHALL указывать путь от узла стратегии до узла и пина, где она найдена.

#### Scenario: Ошибка внутри вложенного узла

- **WHEN** в стратегии узел `ladder1` — составной узел, внутри которого у узла `mul2` не задан вход `b`
- **THEN** проверка сообщает об ошибке по пути `ladder1/mul2`, вход `b`

### Requirement: Вложенность без рекурсии

Составной узел MUST NOT содержать сам себя ни напрямую, ни через другие составные узлы. Такая вложенность MUST делать
составной узел невалидным.

#### Scenario: Косвенная рекурсия

- **WHEN** составной узел `A` содержит `B`, а пользователь сохраняет `B`, добавив в него `A`
- **THEN** система отклоняет сохранение `B` с ошибкой рекурсии `B → A → B`

### Requirement: Отчёт об ошибках проверки

Проверка SHALL возвращать все найденные ошибки сразу, а не только первую. Каждая ошибка SHALL содержать путь к узлу,
пин или параметр, если он есть, и причину.

#### Scenario: Несколько ошибок

- **WHEN** в графе одновременно есть несовместимый провод и вход без значения
- **THEN** проверка возвращает обе ошибки, каждую со своим узлом и пином

### Requirement: Раскладка на холсте

Определение SHALL хранить координаты узлов на холсте. Координаты MUST NOT влиять на проверку и исполнение графа.

#### Scenario: Перемещение узла

- **WHEN** пользователь сохраняет стратегию, изменив только координаты узлов
- **THEN** сохранение проходит, а исполнение стратегии на тех же событиях даёт те же команды
