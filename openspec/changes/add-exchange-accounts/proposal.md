# Proposal

## Why

Стенд показывает идеи и считает их итог, но войти в идею деньгами нельзя: у него нет ни ключей биржи, ни одного
запроса к Bybit от имени владельца. Это изменение — первая половина торговли реальными деньгами: аккаунты биржи.
Вторая половина, `take-idea-trades`, ставит по ним заявки.

Решения владельца в разборе 2026-11-28:

- что торгует — «Вход в идею по клику»; автоматы и бот по стратегии — не сейчас;
- где лежит ключ — «В интерфейсе, как в v2»: экран «Аккаунты», секрет в базе зашифрован, аккаунтов может быть
  несколько;
- защита сайта — «Без защиты»: входа по паролю нет, сайт открыт в локальной сети, как сейчас;
- первая встреча с биржей — «Сразу реальные деньги»: только реальные аккаунты, без демо-торговли и testnet.

## What Changes

- **Раздел «Аккаунты».** Новая страница со списком аккаунтов Bybit: имя, UID, ключ API, права ключа, когда добавлен.
  Аккаунт добавляют в диалоге «Новый аккаунт»: имя, ключ API и секрет. Аккаунт можно переименовать и удалить; сменить
  ключ — удалить аккаунт и добавить заново.
- **Проверка ключа у Bybit.** При сохранении стенд спрашивает у Bybit права ключа. Принимается только ключ единого
  торгового аккаунта с правом торговли бессрочными контрактами, без права вывода и не «только чтение». Причина отказа
  показана у поля ключа. UID аккаунта запоминается; тот же UID второй раз не добавить.
- **Хранение секрета.** Секрет шифруется мастер-ключом из настроек сервера и лежит в базе только зашифрованным. API
  его не отдаёт никогда; ключ API показан целиком. Без мастер-ключа API не стартует.
- **Баланс по кнопке.** «Показать» в строке аккаунта читает у Bybit свободные деньги единого аккаунта. Баланс не
  хранится.
- **Шапка.** **BREAKING** для правила шапки: разделов семь, добавлен «Аккаунты».
- **Первый клиент Bybit.** В стенде появляется подписанный запрос к Bybit. До этого он ходил только в сервис данных.

Чего в изменении нет: заявок, сделок и риск-модуля (`take-idea-trades`); входа по паролю и проверки Origin; демо-торговли
и testnet; спота и других бирж; ротации мастер-ключа; запрета удалять аккаунт со сделками (появится вместе со
сделками).

Мои решения, владельцем по отдельности не подтверждённые: принимается только единый торговый аккаунт (UTA); ключ
«только чтение» отклоняется; «Свободно» — это доступный остаток единого аккаунта по версии Bybit, в долларах;
мастер-ключ получает только API, Worker'ы в этом изменении его не получают.

Макет экрана — `mockups/15-accounts.png` (Penpot, файл `profit-fox`, страница «Экраны», доска «15 Аккаунты»). В шапке
макета уже стоят разделы «Сделки» и «Риск», а под таблицей — строка про открытые сделки: это состояние после
`take-idea-trades`, здесь их нет.

## Capabilities

### New Capabilities

- `exchange-accounts`: аккаунты биржи — список, добавление с проверкой ключа у Bybit, хранение секрета под
  мастер-ключом, переименование, удаление, баланс по запросу и раздел «Аккаунты».

### Modified Capabilities

- `bench-ui`: требование «Общая шапка» — разделов семь, добавлен «Аккаунты».

## Impact

- **Бэкенд.** Новые сущность и репозиторий аккаунта, команды и запросы MediatR, контроллер `api/accounts`, миграция
  таблицы `exchange_accounts`. Новые порты: шифрование секрета и чтение Bybit (права ключа, баланс).
- **Зависимости.** Пакет `Bybit.Net` в `Directory.Packages.props` — первый клиент биржи в репозитории.
- **Настройки.** `ExchangeAccounts:MasterKey` (base64, 32 байта): в `appsettings.Development.json` — ключ разработки,
  в production — переменная окружения из `.env.prod`. `Bybit:RestAddress` — адрес Bybit, в тестах подменяется.
- **Деплой.** `docker-compose.prod.yml` и `deploy/deploy.sh`: API получает `ExchangeAccounts__MasterKey`. Перед
  выкладкой владелец один раз кладёт мастер-ключ в `~/profit-fox/.env.prod` на firebat-01; без него новый API не
  поднимется.
- **Фронтенд.** Страница `/accounts`, раздел в шапке, `src/api/accounts.ts`, пересобранный `schema.d.ts`.
- **Безопасность.** Сайт без пароля в локальной сети теперь хранит ключи с правом торговли. Вывод денег этими ключами
  невозможен: ключ с правом вывода не принимается.
