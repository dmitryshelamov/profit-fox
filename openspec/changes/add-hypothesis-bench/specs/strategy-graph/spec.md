# Spec Delta

## Purpose

Формат графа стратегии и его проверка: из чего состоит граф, какие у пинов типы и какой граф считается сигналом. Один
формат читают стенд гипотез, а позже конструктор и бот.

## ADDED Requirements

### Requirement: Состав графа

Граф SHALL храниться в JSON с полями `formatVersion` = 1, `parameters`, `outputs` (имя и тип), `nodes` и `wires`. Узел SHALL иметь `id`,
уникальный в графе, и `kind` из каталога узлов; по желанию `settings` и `inputs` — значения неподключённых входов.
Провод SHALL иметь вид `{ "from": "узел.пин", "to": "узел.пин" }`. Граф другой версии формата MUST отклоняться.

#### Scenario: Неизвестная версия формата

- **WHEN** читают граф с `formatVersion` = 2
- **THEN** чтение отклоняется с ошибкой версии формата

#### Scenario: Неизвестный вид узла

- **WHEN** в графе есть узел с `kind` = `macd`, которого нет в каталоге
- **THEN** проверка сообщает об ошибке по этому узлу

#### Scenario: Повтор идентификатора

- **WHEN** в графе два узла с `id` = `rate`
- **THEN** проверка сообщает об ошибке повторного идентификатора `rate`

### Requirement: Типы пинов

Каждый вход и выход узла SHALL иметь один тип: число, логическое значение, длительность или событие. Число SHALL
храниться и читаться десятичным без потери точности. Событие — значение, которое истинно только в момент, когда оно
произошло.

#### Scenario: Число без потери точности

- **WHEN** на вход узла подано значение `0.0005`, и граф сохранён и прочитан обратно
- **THEN** значение входа равно ровно `0.0005`

### Requirement: Провода

Провод SHALL соединять выход одного узла со входом другого узла того же типа. Вход SHALL принимать не больше одного
провода. Провод к несуществующему узлу или пину, провод между пинами разных типов и второй провод на вход MUST давать
ошибку проверки.

#### Scenario: Условие на вход события

- **WHEN** логический выход узла сравнения подключён к выходу `entry` сигнала, объявленному событием
- **THEN** проверка сообщает об ошибке типа по этому проводу

#### Scenario: Два провода на один вход

- **WHEN** на вход `a` узла `first` приходят два провода
- **THEN** проверка сообщает об ошибке по входу `a` узла `first`

### Requirement: Значение неподключённого входа

Вход без провода SHALL брать значение, заданное в `inputs` узла, того же типа, что и вход. Вход без провода и без
значения, вход с проводом и значением сразу MUST давать ошибку проверки. Входу типа «событие» значение задать нельзя.

#### Scenario: Порог на входе

- **WHEN** вход `b` узла сравнения не подключён и в `inputs` задано `0.0005`
- **THEN** узел получает `b` = `0.0005` на каждой свече

#### Scenario: Вход без провода и без значения

- **WHEN** вход `b` узла сравнения не подключён и значения в `inputs` нет
- **THEN** проверка сообщает об ошибке незаданного входа `b`

#### Scenario: Провод и значение на одном входе

- **WHEN** на вход `b` узла сравнения приходит провод, и в `inputs` задано `0.0005`
- **THEN** проверка сообщает об ошибке по входу `b`: непонятно, что из двух брать

### Requirement: Без циклов

Граф MUST NOT содержать циклов по проводам. Значение прошлой свечи берётся узлом «предыдущее», а не проводом назад.

#### Scenario: Цикл

- **WHEN** выход узла `a` подключён ко входу `b`, а выход `b` — ко входу `a`
- **THEN** проверка сообщает об ошибке цикла с узлами `a` и `b`

### Requirement: Параметры графа

Граф SHALL объявлять параметры в `parameters`: имя, тип, значение и по желанию минимум и максимум. Узел «параметры»
SHALL выдавать каждый параметр выходом с его именем и типом. Значение вне минимума или максимума MUST давать ошибку
проверки.

#### Scenario: Параметр на выходе узла

- **WHEN** в графе объявлен параметр `threshold` типа число со значением `0.0005`
- **THEN** у узла «параметры» есть выход `threshold`, выдающий `0.0005`

#### Scenario: Значение вне границ

- **WHEN** у параметра `threshold` минимум `0` и значение `-0.1`
- **THEN** проверка сообщает об ошибке по параметру `threshold`

### Requirement: Сигнал

Сигнал SHALL быть графом с одним объявленным выходом типа «событие», который принимает узел выхода. Граф сигнала MUST
NOT содержать узлов заявок и позиции: сигнал читает только рынок.

#### Scenario: Сигнал с двумя выходами

- **WHEN** у графа сигнала объявлены выходы `entry` и `exit`
- **THEN** проверка сообщает, что у сигнала должен быть ровно один выход

#### Scenario: Выход сигнала не событие

- **WHEN** у сигнала объявлен выход `entry` логического типа
- **THEN** проверка сообщает, что выход сигнала должен быть событием

### Requirement: Все ошибки сразу

Проверка графа SHALL сообщать все найденные ошибки за один раз; каждая ошибка SHALL называть узел, пин или провод, к
которому относится.

#### Scenario: Две ошибки в одном графе

- **WHEN** в графе одновременно есть провод между пинами разных типов и вход без значения
- **THEN** проверка сообщает обе ошибки
