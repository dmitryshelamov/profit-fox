# Spec Delta

## MODIFIED Requirements

### Requirement: Каталог библиотеки

Система SHALL возвращать каталог библиотеки: простые узлы, встроенные составные узлы и пользовательские составные узлы.
Для каждого узла каталог SHALL содержать идентификатор вида, название, признак «простой», «встроенный» или
«пользовательский», входы и выходы с типами. Для простого узла с настройками каталог SHALL перечислять каждую
настройку: имя, допустимые значения и значение по умолчанию, а для настройки, задающей тип входов, — эти входы.

#### Scenario: Каталог содержит все три группы

- **WHEN** пользователь сохранил один свой составной узел и запрашивает каталог
- **THEN** каталог содержит простые узлы, встроенные составные узлы и этот пользовательский узел с его входами и выходами

#### Scenario: Настройки рыночного ордера

- **WHEN** пользователь запрашивает каталог
- **THEN** у узла `market-order` есть настройка `side` со значениями `buy`, `sell` и настройка `size` со значениями
  `quantity`, `amount`

#### Scenario: Настройка, задающая тип входов

- **WHEN** пользователь запрашивает каталог
- **THEN** у узла `compare` есть настройка `type` со значениями `number`, `duration`, и она задаёт тип входов `a` и `b`

## ADDED Requirements

### Requirement: Проверка стратегии без сохранения

Система SHALL проверять стратегию из имени и определения так же, как её сохранение, и возвращать все ошибки, которые
дало бы сохранение: ошибки графа и имени, а для существующей стратегии — ботов, которых сломала бы правка. Проверка MUST
NOT ничего сохранять и MUST NOT создавать версий.

#### Scenario: Валидная новая стратегия

- **WHEN** пользователь проверяет стратегию EMA с валидным графом, которой ещё нет
- **THEN** проверка не возвращает ошибок, и стратегия не появляется в списке

#### Scenario: Ошибка графа

- **WHEN** пользователь проверяет стратегию, в которой вход `buy.when` не подключён и не задан
- **THEN** проверка возвращает ошибку `graph.buy.when`, и сохранённая стратегия не меняется

#### Scenario: Правка ломает бота

- **WHEN** бот «EMA BTC» задаёт `fast` = `10`, и пользователь проверяет EMA без параметра `fast`
- **THEN** проверка возвращает бота «EMA BTC» с ошибкой по `fast`, стратегия и бот не меняются

#### Scenario: Неизвестная стратегия

- **WHEN** пользователь проверяет правку стратегии по идентификатору, которого нет
- **THEN** система отвечает «не найдено»

### Requirement: Проверка составного узла без сохранения

Система SHALL проверять пользовательский составной узел из имени и определения так же, как его сохранение, и
возвращать ошибки его графа, а для существующего узла — места использования, которые сломала бы правка, с их
ошибками. Проверка MUST NOT ничего сохранять. Проверка правки встроенного узла SHALL отвечать конфликтом, как его
изменение.

#### Scenario: Ломающая правка

- **WHEN** в стратегии EMA подключён выход `down` узла «Моё пересечение», и пользователь проверяет узел без выхода
  `down`
- **THEN** проверка возвращает стратегию EMA с ошибкой провода к несуществующему выходу `down`, и узел не меняется

#### Scenario: Валидный новый узел

- **WHEN** пользователь проверяет новый составной узел с валидным внутренним графом
- **THEN** проверка не возвращает ошибок, и узел не появляется в каталоге
