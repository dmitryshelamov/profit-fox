# Spec Delta

## ADDED Requirements

### Requirement: Порядок идей минуты

Автомат SHALL рассматривать подходящие ему идеи минуты в порядке обещания: по матожиданию корзины от большего к
меньшему, при равенстве — по чистому R:R от большего; идеи без корзины — последними, между собой по чистому R:R. Заявки
автомата с деньгами SHALL уходить Worker'у в этом порядке.

#### Scenario: Лучшая идея первой

- **WHEN** у автомата бюджет на одну сделку, и в минуту рождаются две подходящие идеи: с матожиданием −0.10 R и +0.05 R
- **THEN** учебная сделка открывается по идее с +0.05 R, а идею с −0.10 R автомат не трогает

#### Scenario: Идея без корзины последней

- **WHEN** в минуту рождаются идея без корзины с R:R 3 и идея корзины с матожиданием −0.20 R
- **THEN** первой рассматривается идея корзины

### Requirement: Лимит новых сделок стороны за минуту

Если у автомата задан лимит новых сделок одной стороны за минуту, он MUST NOT открывать в минуту больше учебных сделок
или писать больше заявок этой стороны, чем лимит. Идеи сверх лимита автомат не берёт и SHALL писать по ним один отказ на
автомат, сторону и минуту: причина «Лимит за минуту», идея — первая пропущенная, подробность — число пропущенных и лимит.
Без лимита поведение прежнее.

#### Scenario: Тридцать лонгов

- **WHEN** у автомата лимит 2, и в минуту рождаются 30 подходящих лонгов и 3 шорта
- **THEN** автомат открывает два лучших лонга и три шорта и пишет один отказ «Лимит за минуту» с «пропущено 28 при
  лимите 2»

#### Scenario: Лимит не достигнут

- **WHEN** у автомата лимит 2, и в минуту рождается один подходящий лонг
- **THEN** сделка открывается, отказа нет

### Requirement: Лимит открытых сделок стороны

Если у автомата задан лимит открытых сделок одной стороны, он MUST NOT открывать учебную сделку или писать заявку этой
стороны, пока его открытых сделок этой стороны, учебных и реальных, столько или больше. Сделки другой стороны лимит
MUST NOT трогать. Пропущенные идеи SHALL давать один отказ на автомат, сторону и минуту с причиной «Лимит на сторону» и
числом пропущенных.

#### Scenario: Четвёртый лонг

- **WHEN** у автомата лимит 3, открыты 3 его лонга, и рождаются 2 подходящих лонга и шорт
- **THEN** шорт берётся, лонги нет, и в отказах одна строка «Лимит на сторону» с «пропущено 2 при лимите 3»

#### Scenario: Лонг закрылся

- **WHEN** у автомата лимит 3, один из трёх его лонгов закрылся, и рождается подходящий лонг
- **THEN** лонг берётся

## MODIFIED Requirements

### Requirement: Автомат

API SHALL хранить список автоматов: `GET`, `POST /api/idea-autos`, `GET`, `PUT`, `DELETE /api/idea-autos/{id}`.
У автомата SHALL быть:

- название;
- аккаунт биржи;
- сумма на сделку в USDT;
- бюджет автомата в USDT или его отсутствие;
- режим: «Выкл», «Без денег» или «С деньгами»;
- условия;
- лимит новых сделок одной стороны за минуту или его отсутствие;
- лимит открытых сделок одной стороны или его отсутствие;
- место в списке.

Новый автомат SHALL вставать в конец списка в режиме «Выкл». Числа API SHALL передавать десятичными строками. Автоматы,
сохранённые до появления бюджета, SHALL оставаться без бюджета; сохранённые до лимитов — без лимитов.

#### Scenario: Новый автомат

- **WHEN** владелец создаёт автомат «Импульс лонг» с аккаунтом, суммой 300 и условиями, а в списке уже два автомата
- **THEN** API отвечает 201 с id, и автомат третий в списке, в режиме «Выкл»

#### Scenario: Чтение автомата

- **WHEN** владелец читает автомат по id
- **THEN** ответ содержит название, аккаунт, сумму, бюджет, режим, все условия и место в списке

#### Scenario: Автомат без бюджета

- **WHEN** владелец сохраняет автомат с пустым бюджетом
- **THEN** API отдаёт бюджет пустым, и бюджет автомата не останавливает его входов

#### Scenario: Автомат до лимитов

- **WHEN** автомат сохранён до появления лимитов
- **THEN** у него нет ни одного лимита, и он берёт идеи как раньше

### Requirement: Проверка автомата

Сохранение автомата MUST давать ошибку валидации 400 по полю, если:

- название пустое, длиннее 60 знаков или совпадает с названием другого неудалённого автомата;
- аккаунта нет;
- сумма не больше нуля или больше «Не больше суммы на сделку» из настроек;
- бюджет задан и меньше суммы автомата;
- не выбран ни один сетап, тип идеи или ТФ;
- среди типов есть «Стоп-вход»;
- минимальный R:R меньше нуля или минимум N меньше нуля;
- лимит задан и меньше 1.

#### Scenario: Сумма выше предела

- **WHEN** «Не больше суммы на сделку» 500, а владелец сохраняет автомат с суммой 600
- **THEN** API отвечает 400 по полю суммы, и автомат не меняется

#### Scenario: Стоп-вход в типах

- **WHEN** владелец сохраняет автомат с типом «Стоп-вход»
- **THEN** API отвечает 400 по полю типов

#### Scenario: Имя занято

- **WHEN** автомат «Пробои 5м» уже есть, и владелец создаёт ещё один с тем же названием
- **THEN** API отвечает 400 по полю названия

#### Scenario: Бюджет меньше суммы

- **WHEN** владелец сохраняет автомат с суммой 50 и бюджетом 40
- **THEN** API отвечает 400 по полю бюджета, и автомат не меняется

#### Scenario: Бюджет равен сумме

- **WHEN** владелец сохраняет автомат с суммой 50 и бюджетом 50
- **THEN** автомат сохраняется, и у него одна открытая сделка за раз

#### Scenario: Лимит ноль

- **WHEN** владелец сохраняет автомат с лимитом открытых сделок стороны 0
- **THEN** API отвечает 400 по полю этого лимита

### Requirement: Условия автомата

Идея SHALL подходить автомату, только если совпадает по всем условиям сразу. Внутри одного условия хватает любого из
отмеченных значений. Условия:

- сетап и тип идеи;
- ТФ: 5 мин, 15 мин, 1 ч или 4 ч;
- сторона: лонг, шорт или обе;
- рынок: `linear`, `spot` или оба;
- значок корзины;
- минимум N корзины за 90 дней; у идеи без корзины N равен 0;
- по каждому из четырёх признаков идеи — «любой», «только с признаком» или «только без».

Идея, не подошедшая по условиям, MUST NOT давать отказа.

#### Scenario: Не тот ТФ

- **WHEN** у автомата отмечены 15 мин и 1 ч, и рождается идея на 5 мин
- **THEN** автомат её не берёт и отказа не пишет

#### Scenario: Мало случаев

- **WHEN** у автомата минимум N 100, а у корзины идеи N 64
- **THEN** автомат её не берёт и отказа не пишет

#### Scenario: Только после падения пары

- **WHEN** у автомата «падение пары за сутки» — «только с признаком», и рождается идея без него
- **THEN** автомат её не берёт и отказа не пишет

#### Scenario: Только без высокого funding

- **WHEN** у автомата «высокий funding» — «только без», и рождается идея с ним
- **THEN** автомат её не берёт и отказа не пишет

#### Scenario: Признак любой

- **WHEN** у автомата все три признака «любой»
- **THEN** признаки идеи на выбор не влияют

#### Scenario: Только без всплеска

- **WHEN** у автомата «всплеск» — «только без», и в минуту на 1 ч сработали лонги по 9 парам
- **THEN** ни одну из этих идей автомат не берёт и отказа не пишет

### Requirement: Бюджет автомата при одновременных идеях

Идеи одного автомата SHALL проверяться по бюджету по очереди в порядке идей минуты, и каждая SHALL видеть сделки,
взятые до неё:

- учебные — сделки, открытые этим автоматом в той же минуте сканера;
- реальные — сделки, созданные торговым Worker'ом по прежним заявкам, под теми же блокировками, что остальные проверки
  автомата.

Две идеи одного автомата MUST NOT вместе выйти за его бюджет.

#### Scenario: Две учебные идеи в одной минуте

- **WHEN** у автомата «Без денег» бюджет 50 и сумма 30, и в одну минуту рождаются две подходящие ему идеи разных пар
- **THEN** первая становится учебной сделкой, а вторую автомат не трогает: ни сделки, ни отказа

#### Scenario: Две заявки с деньгами

- **WHEN** у автомата «С деньгами» бюджет 50 и сумма 30, и Worker берёт две его заявки по идеям разных пар одной минуты
- **THEN** по первой создаётся сделка, а вторая получает отказ «Бюджет автомата занят»
