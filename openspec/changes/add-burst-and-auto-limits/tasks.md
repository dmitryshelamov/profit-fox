# Tasks

Новая логика идёт строго по TDD: красный тест, минимальный код, рефакторинг. Ссылки «решение N» — на design.md,
сценарии — на дельты спек этого изменения. Деньги и цены — `decimal`, время — UTC.

## 1. Домен: признак всплеска

- [ ] 1.1 `IdeaFeatures.Burst`, `IdeaFeatures.BurstThreshold(Interval)` (5m 60, 15m 25, 1h 8, 4h 4) и `Of(…, int? burstPairs,
  Interval)` (решение 1); `IdeaFeature.Burst` с кодом `burst` в `IdeaCodes`. Тесты: порог каждого ТФ ровно на границе и
  на единицу ниже, `null` → нет; `Has(Burst)`; уровень со всплеском отличается от уровня без признаков (сценарий «Уровень
  со всплеском»); эталонные числа тестов подкорзин калибровки прежние.
- [ ] 1.2 `Idea.BurstPairs` (`int?`) и `Idea.Features` с ним; `IdeaTrade.Features` копирует четвёртый флаг. Тесты сущностей.

## 2. Живые идеи и статистика

- [ ] 2.1 `LiveIdeas.Minute` считает число разных инструментов на (сторона, ТФ) по `created` и кладёт `BurstPairs` в идеи
  минуты до автоматов и записи (решение 2). Тесты: сценарии «Всплеск на часе», «Без всплеска», «Один сетап по многим
  типам» на идеях одной минуты.
- [ ] 2.2 `IIdeaSignalRepository.CountPairsByMinuteAsync(version, from)`; `IdeaStatistics.WalkAsync` читает словарь и
  передаёт `IdeaOutcomes.WalkAsync` функцию всплеска сигнала; `IdeaOutcome.Features` с ним (решение 2). Unit-тест прохода:
  кейс получает всплеск по словарю (сценарий «Прогон пополняет минуту»: 6 пар — нет, 9 — есть); интеграционный тест
  запроса: `count(distinct symbol)` по минуте, стороне и ТФ, типы одной пары не умножают.
- [ ] 2.3 `CalibrationCalculator`: строки «всплеск · есть / нет» (сценарий «Строка всплеска»); пояснение на «Калибровке»
  — задача 7.3.

## 4. Автоматы: порядок и лимиты

- [ ] 4.1 `IdeaAuto.MaxPerMinutePerSide` / `MaxOpenPerSide`, `IdeaAutoConditions.Burst`, `AutoConditions.Match` по нему
  (сценарий «Только без всплеска»); `IdeaTradeRefusal.MinuteLimit` / `SideLimit` с кодами `minute_limit` / `side_limit`.
- [ ] 4.2 `Services/IdeaAutos/AutoMinutePlan` (решение 3): порядок по матожиданию, затем чистому R:R, без корзины
  последними; взять / пропустить с причиной по двум лимитам, счётчики минуты и открытых стороны. Тесты сценариев
  «Лучшая идея первой», «Идея без корзины последней», «Тридцать лонгов», «Лимит не достигнут», «Четвёртый лонг», «Лонг
  закрылся»; без лимитов — порядок тот же, пропусков нет.
- [ ] 4.3 `LiveAutos.TakeAsync` идёт по плану, нумерует заявки по нему и пишет один агрегированный отказ на автомат,
  сторону и минуту с `Numbers(пропущено, лимит)` и первой пропущенной идеей (решение 4). Тесты `LiveAutosTests`: сценарии
  «Тридцать лонгов» (две учебные сделки и один отказ «пропущено 28 при лимите 2»), «Четвёртый лонг» с открытыми учебными
  лонгами, заявки «С деньгами» в порядке плана, прежнее поведение без лимитов.
- [ ] 4.4 `IdeaAutoInput`, `IdeaAutoValidation` (лимит < 1 — ошибка поля), `IdeaAutoBody` / `IdeaAutoResponse`: `burst`,
  `maxPerMinutePerSide`, `maxOpenPerSide` (сценарии «Лимиты в теле», «Ноль в лимите», «Условие всплеска в теле»); тесты API.
