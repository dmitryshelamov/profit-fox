# Proposal

## Why

Бэктест с сеткой упирается в процессор: сейчас он считается внутри процесса API на одном сервере, примерно на трёх
потоках, отнимает процессор у API и прерывается каждым деплоем API. У владельца есть ещё шесть машин (4 × Intel N150,
2 × Firebat R2), и вместе они дают в несколько раз больше потоков. Изменение 2.1 выносит фоновую работу из API в
отдельный процесс Worker, который запускается на любом числе машин и делит одну сетку между ними.

## What Changes

- Новый процесс `ProfitFox.Worker`. Он считает бэктесты и выполняет задачи загрузки свечей; одна и та же сборка
  запускается на одной или нескольких машинах и работает с общей базой Postgres по локальной сети.
- **BREAKING** API больше не выполняет фоновую работу: он создаёт, отменяет и читает бэктесты и задачи загрузки. Без
  запущенного Worker'а бэктест остаётся `Pending`, задача загрузки — `Pending`.
- Бэктест после догрузки свечей делится на куски — диапазоны номеров комбинаций. Worker берёт кусок под аренду,
  продлевает её, пока считает, и сдаёт результаты; истёкшую аренду перехватывает любой Worker. Бэктест завершается
  `Succeeded`, когда сданы все куски.
- Worker берёт работу самого старого бэктеста, у которого она есть: пока все куски старого заняты, свободный Worker
  начинает следующий бэктест. Требование «бэктесты по одному» заменяется.
- Задача загрузки тоже выполняется под арендой. Одновременно выполняется не больше одной загрузки на все Worker'ы.
- **BREAKING** Продолжение после перезапуска сервиса заменяется перехватом истёкшей аренды: при запуске ничего заново
  в очередь не ставится. Правило «три прерывания подряд без продвижения — `Failed`» считает потерянные аренды куска или
  задачи загрузки.
- Версия движка — номер правил расчёта стратегии, симулятора и метрик. Бэктест запоминает версию движка при создании;
  Worker берёт только работу своей версии; Worker более новой версии переводит незавершённый бэктест старой версии в
  `Failed` с причиной «сменилась версия движка». Тест на эталонных наборах падает, если результаты расчёта изменились,
  а версия движка нет.
- Детали результата бэктеста другой версии движка не пересчитываются: запрос отклоняется как конфликт.
- Прогресс и скорость бэктеста складываются по всем кускам и Worker'ам.
- Образ Worker'а и compose-файл для машины с Worker'ом; секция настроек `Worker` (интервал опроса, длительность и
  продление аренды, размер куска).

Вне изменения: heartbeat и список Worker'ов, раскатка на машины и настройка Postgres на проде (делает владелец),
приоритеты между бэктестами, запись сборки в результатах, вынос движка в отдельный проект, живой бот и outbox.

## Capabilities

### New Capabilities

- `background-workers`: процесс Worker и распределение фоновой работы между Worker'ами: опрос базы, аренда, продление
  и перехват, работа без Worker'а, настройки и запуск на нескольких машинах.

### Modified Capabilities

- `backtest-runs`: порядок выполнения бэктестов, куски, продолжение после сбоя вместо перезапуска сервиса, версия
  движка, прогресс и скорость по кускам, версия движка в чтении бэктеста.
- `backtest-results`: детали результата бэктеста другой версии движка отклоняются.
- `market-data-import`: выполнение задач Worker'ом под арендой, одна загрузка одновременно на все Worker'ы, прерванные
  задачи — по потерянной аренде вместо перезапуска сервиса.
- `service-logging`: Worker пишет лог по тем же правилам, что API.

## Impact

- Новый проект `backend/src/ProfitFox.Worker` (generic host), его `Dockerfile` и `docker-compose.worker.yml`.
- `ProfitFox.Infrastructure`: фоновые сервисы переезжают в регистрацию Worker'а; очереди в памяти (`CandleImportQueue`,
  `BacktestQueue`) и сервисы повторной постановки при старте удаляются; новые запросы захвата и продления аренды.
- `ProfitFox.Application`: порты `ICandleImportQueue` и `IBacktestQueue` и команды `RequeueInterrupted*` удаляются;
  `RunBacktestCommand` и `RunCandleImportCommand` переписываются под куски и аренду; новые настройки `WorkerSettings`.
- `ProfitFox.Domain`: версия движка, куски бэктеста, счётчик потерянных аренд вместо счётчика перезапусков.
- База: миграция таблиц `backtests`, `candle_import_jobs` (аренда, версия движка) и новая таблица кусков.
- API: поле версии движка в чтении бэктеста, `409` для деталей результата другой версии движка.
- Тесты: интеграционные тесты запускают хост Worker'а рядом с API; сценарии с двумя Worker'ами в одном тестовом
  процессе.
- Эксплуатация: Postgres на `soyo-01` слушает LAN-интерфейс, `pg_hba` пускает только `192.168.8.0/24`, пароль из
  переменной окружения; API мигрирует базу и деплоится раньше Worker'ов. Часы машин синхронизированы по NTP.
