# Spec Delta

## MODIFIED Requirements

### Requirement: Жизненный цикл задачи загрузки

Задача загрузки SHALL проходить статусы `Pending` → `Running` → `Succeeded` или `Failed`. Задача `Running`, аренда
которой истекла, остаётся `Running`, пока её не возьмёт другой Worker; задача `Failed` возвращается в `Pending` при
ручном повторе. Пользователь SHALL иметь возможность получить по идентификатору статус задачи, её параметры, число
сохранённых свечей и, для `Failed`, причину ошибки.

#### Scenario: Успешное завершение

- **WHEN** задача загрузила все свечи периода
- **THEN** её статус `Succeeded`, а число сохранённых свечей равно числу закрытых свечей периода, полученных с Bybit,
  которых не было в хранилище

#### Scenario: Ошибка биржи

- **WHEN** Bybit возвращает ошибку, которая не исчезает после повторных попыток
- **THEN** задача получает статус `Failed` с причиной ошибки; свечи, сохранённые до ошибки, остаются в хранилище

#### Scenario: Неизвестная задача

- **WHEN** пользователь запрашивает статус по несуществующему идентификатору
- **THEN** система отвечает, что задача не найдена

## ADDED Requirements

### Requirement: Одна загрузка одновременно

Задачи загрузки SHALL выполняться по одной на все Worker'ы вместе, в порядке создания: Worker MUST NOT брать задачу,
пока у другой задачи есть действующая аренда. Задача `Running` с истёкшей арендой SHALL браться раньше задач,
созданных позже неё.

#### Scenario: Две задачи и два Worker'а

- **WHEN** работают два Worker'а, и в очереди две задачи загрузки
- **THEN** в каждый момент выполняется не больше одной задачи, и задача, созданная раньше, начинается первой

#### Scenario: Порядок после сбоя

- **WHEN** задача `A`, созданная раньше, в статусе `Pending`, а задача `B`, созданная позже, в статусе `Running` с
  истёкшей арендой
- **THEN** Worker сначала выполняет `A`, затем `B`

### Requirement: Прерванные задачи после сбоя Worker'а

Задачу `Running`, аренда которой истекла, SHALL брать любой Worker; она загружает только недостающие свечи. Задачу,
аренда которой истекает третий раз подряд без сохранённой между истечениями свечи, система MUST перевести в `Failed` с
причиной «задача трижды прервана без продвижения». Ручной повтор начинает отсчёт заново.

#### Scenario: Worker упал во время загрузки

- **WHEN** Worker останавливается, пока задача в статусе `Running`, и её аренда истекает
- **THEN** другой Worker продолжает задачу, загружает только недостающие свечи периода, и она завершается `Succeeded`

#### Scenario: Задача без продвижения

- **WHEN** аренда задачи истекает три раза подряд, и ни разу между истечениями не сохранена свеча
- **THEN** задача имеет статус `Failed` с причиной «задача трижды прервана без продвижения» и не выполняется

#### Scenario: Задача с продвижением

- **WHEN** аренда задачи истекает больше трёх раз, но между каждыми двумя истечениями сохраняется хотя бы одна свеча
- **THEN** задача каждый раз продолжается

#### Scenario: Ручной повтор сбрасывает отсчёт

- **WHEN** аренда задачи дважды истекла без сохранённых свечей, затем задача упала с ошибкой биржи и повторена
  вручную, а после повтора её аренда снова истекает без сохранённых свечей
- **THEN** задача продолжается, а не переводится в `Failed`

## REMOVED Requirements

### Requirement: Прерванные задачи

**Reason**: При запуске ничего заново в очередь не ставится, а задача `Running` не возвращается в `Pending`: работа
упавшего или остановленного Worker'а продолжается перехватом истёкшей аренды, а счётчик прерываний считает потерянные
аренды задачи, а не перезапуски сервиса.

**Migration**: См. требования «Прерванные задачи после сбоя Worker'а» и «Одна загрузка одновременно». Незавершённые
задачи на момент деплоя продолжает первый запущенный Worker.
