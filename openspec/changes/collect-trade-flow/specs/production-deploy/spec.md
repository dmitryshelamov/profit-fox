# Spec Delta

## MODIFIED Requirements

### Requirement: Версия — номер сборки коммита `main`

Прод SHALL запускать только образы, собранные из коммита ветки `main`. Каждая новая сборка коммита `main` SHALL получать
следующий номер версии — целое число на единицу больше наибольшего выданного (первая версия — `1`): коммит помечается
git-тегом `v<N>`, а образы API, Worker'а, сканера, сборщика потока сделок и веба публикуются с тегом `<N>`. Коммит MUST
NOT получать два номера. Все сервисы прода SHALL работать на одном номере. Образы MUST NOT собираться на сервере прода.

#### Scenario: Мерж в main

- **WHEN** PR смержен в `main`, для его коммита прошли проверки CI, Frontend и E2E, а наибольшая выданная версия — `6`
- **THEN** вне прода коммит получает тег `v7`, а образы API, Worker'а, сканера, сборщика потока сделок и веба
  публикуются в реестре с тегом `7`

#### Scenario: Пересборка того же коммита

- **WHEN** сборку коммита с тегом `v7` запускают ещё раз
- **THEN** номер остаётся `7`, нового тега не появляется

#### Scenario: Проверки не прошли

- **WHEN** у коммита `main` упала хотя бы одна из проверок CI, Frontend или E2E
- **THEN** образы этого коммита не собираются, и выкатить его нельзя

### Requirement: Порядок обновления

При выкатке прод SHALL сначала остановить Worker, сканер и сборщик потока сделок, затем обновить API, дождаться, пока
API ответит на новой версии (миграции базы применены), и только потом запустить Worker, сканер, сборщик и веб той же
версии. Если API новой версии не ответил, выкатка MUST остановиться с ошибкой и MUST NOT запускать Worker, сканер и
сборщик новой версии. Версия, в которой нет образа сборщика, SHALL оставлять сборщик остановленным.

#### Scenario: Обычная выкатка

- **WHEN** владелец подтверждает выкатку версии `7`, и в ней есть новая миграция
- **THEN** миграция применена до старта Worker'а, и после выкатки API, Worker, сканер, сборщик и веб работают на версии
  `7`

#### Scenario: API не поднялся

- **WHEN** API новой версии не отвечает за отведённое время
- **THEN** выкатка завершается с ошибкой, Worker, сканер и сборщик остаются остановленными, и владелец видит ошибку в
  GitHub

#### Scenario: Откат на версию без сборщика

- **WHEN** на проде версия со сборщиком, и владелец выкатывает более раннюю версию, в которой образа сборщика нет
- **THEN** API, Worker, сканер и веб работают на ранней версии, а сборщик остановлен, и его данные в базе сохранены
