# Design

## Context

Экраны из `add-trade-ideas` (архив `2026-11-05-add-trade-ideas`) работают на проде с v6:

- `IdeasTable` показывает идеи в порядке ответа API, то есть по ожиданию.
- `PairIdeasList` показывает в карточке только R.
- Страница пары меняет `?idea=` и `?interval=` через `navigate` роутера TanStack. Роутер при каждой навигации сбрасывает
  прокрутку наверх.
- Цены приходят десятичными строками как есть. Лимит «Отката» округлён по шагу и несёт его знаки (`197.00`). Вход по
  рынку — это open свечи, у которого знаков столько, сколько дала биржа (`184.7`).
- Шаг цены хранится в `ideas.tick` (идея) и `scanner_pairs.tick_size` (пара), но в ответах API его нет.

## Goals / Non-Goals

**Goals:**

- четыре правки из proposal без изменения расчёта идей.

**Non-Goals:**

- сортировка на стороне API и сортировка в адресе страницы;
- деньги в блоке своей идеи;
- смена версии движка идей.

## Decisions

### 1. Сортировка в браузере

Список «Идеи» — это открытые идеи и закрытые за сутки, сотни строк, и все они уже в браузере. Поэтому сортировка идёт по
загруженному списку, функцией модели `sortIdeas(ideas, column, direction)` с unit-тестами. Выбранная колонка хранится в
состоянии страницы. По умолчанию — «Ожидание» по убыванию: это совпадает с порядком API.

- Пустые значения (нет корзины, «мало данных») — внизу при любом направлении. Иначе при сортировке по возрастанию верх
  списка займут идеи без данных.
- Сравнение десятичных строк — через `compareDecimals`, не через `Number`: точность цен и долей сохраняется.
- Сортировка устойчива: равные значения идут в порядке API.

Отклонено:

- **Сортировка в API.** Нужен ещё один параметр запроса и его валидация. При этом список и так целиком у браузера.
- **Колонка в адресе.** Владелец не просил делиться ссылкой на сортировку. Добавить можно потом.

### 2. Деньги в карточке — от того же риска

Карточка берёт «Риск на идею» из того же хранилища браузера (`riskStorage`), что и «Идеи». Расчёт — существующий
`riskOutcome` и новое ожидание в USDT (ожидание в R × риск, по `multiplyDecimals`). Поля риска на странице пары нет:
риск меняют на «Идеях».

Отклонено: **своё поле риска на странице пары.** Тогда два места хранят одно число, и их легко рассинхронизировать.

### 3. Прокрутка остаётся на месте

Навигация выбора идеи, «Снять выбор» и переключения ТФ передаёт роутеру `resetScroll: false`. Переход с «Идей» на
страницу пары — это переход на другую страницу, он по-прежнему открывает её сверху.

### 4. Шаг цены в ответе и формат по нему

- `IdeaResponse` получает `tick` из `ideas.tick`.
- Ответ своей идеи получает `tick` из шага цены пары, который API уже использует для округления.
- Интерфейс форматирует вход, стоп и цель функцией «знаков как у шага». Шаг `0.01` даёт 2 знака, `0.5` — 1, `1` — 0.

Отклонено: **нормализовать знаки в API.** Тогда строка цены перестаёт совпадать с тем, что лежит в базе и уходит в
расчёты. Формат — забота экрана.

## Risks / Trade-offs

- Сортировка по показанному тексту для «Сетапа», «Типа» и «Стороны» зависит от русских подписей. Это ожидаемо:
  владелец видит именно их.
- У идей, созданных до появления шага цены, `tick` может быть пустым. Тогда цена показывается как есть, без
  дополнения знаков.

### 5. Уточнения при реализации

- **Направление первого клика.** Клик по заголовку другой колонки всегда сортирует по убыванию (наибольшее или самое
  позднее наверху), повторный клик — по возрастанию. Так читается сценарий «Сортировка по R:R»; для текстовых колонок
  отдельного правила нет, чтобы не плодить исключения.
- **«Прибыль / убыток» сортируется по R:R.** Прибыль — это R:R × единый риск на идею, поэтому порядок по прибыли и по R:R
  совпадает при любом положительном риске. `sortIdeas` риска не знает.
- **Ключи сортировки.** «Вероятность» — доля корзины, если у неё хватает данных (`enoughData`), иначе пусто;
  «Ожидание» — ожидание корзины, пусто без корзины; «ТФ» — как число; «Найдена» — по времени; статус — по ходу идеи.
- **Риск в карточке пары.** `PairIdeasList` читает риск из `riskStorage` один раз при показе списка. Страница пары риск не
  меняет, так что синхронизировать два места не нужно.
- **Ожидание в USDT** показывается со знаком и одним знаком после запятой, как прибыль и убыток (`-0.5`, `+3.8`); знак
  минус — обычный дефис, как у ожидания в R рядом.
- **Пустой `tick`.** У идеи, созданной до появления шага цены, `tick` в ответе `null`, и цена показывается как есть.
  Шаг цены, у которого после точки больше знаков, чем у цены, дополняет цену нулями; цена, у которой знаков больше шага,
  округляется до числа знаков шага (в данных Bybit такого нет).
- **Тест прокрутки в jsdom** считает вызовы `window.scrollTo`: роутер зовёт его при каждой навигации, если не передан
  `resetScroll: false`.
