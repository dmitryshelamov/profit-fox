# Tasks

Новая логика идёт строго по TDD: красный тест, минимальный код, рефакторинг. Ссылки «решение N» — на design.md,
сценарии — на дельты спек этого изменения. Время — UTC. Отпечаток референсных кейсов (`IdeasEngineVersionTests`) и
`IdeasEngineVersion.Current = 7` не меняются ни в одной задаче; тест гоняется после каждой задачи групп 1–3.

## 1. Замер

- [x] 1.1 `IScannerJournal.Replayed(instrument, days, engine, reads, writes)` и запись в `LoggingScannerJournal` одной
  строкой уровня Information (решение 1); `IdeasReplay.ReplayAsync` меряет секундомером время шагов движка и `Advance`,
  чтений (минуты пары, BTC, funding) и записей (сигналы, курсор) и зовёт журнал в конце хода. Тест `IdeasReplayTests`:
  ход по 2 дням пишет в журнал пару, `2` дня и неотрицательные времена (сценарий «Ход в логе»).
- [x] 1.2 `[Explicit]` профиль-тест в `Tests.Unit`: детерминированный генератор минут пары на 90 дней со seed, дающий
  срабатывания всех сетапов, репозитории в памяти, прогон через `IdeasReplay` с печатью таймингов и числа открытых путей
  по дням; сохраняет сигналы прогона в снимок для сравнения в 2.1. Проверка: тест запускается явно и печатает
  тайминги; в обычном прогоне `dotnet test` его нет.
- [x] 1.3 Профиль под 1.2 (`dotnet-trace` или профилировщик по месту): записать в design.md под «Решение 1» долю движка,
  чтений и записей и три верхних метода по времени. Проверка: абзац «Измерено при реализации» в design.md с числами.

## 2. Оптимизация движка по профилю

- [ ] 2.1 Горячий участок из 1.3 по кандидатам решения 1 (в первую очередь `Advance` / `SignalPathTracker.Step` без
  аллокаций на неизменившийся путь, затем детектор только на закрытии свечи интервала, кольцевой буфер минут), строго по
  одному кандидату за задачу с замером до и после. Проверка каждого шага: отпечаток референсных кейсов прежний; сигналы
  синтетической истории из 1.2 равны снимку до оптимизации; тайминг профиль-теста записан в design.md.
- [ ] 2.2 Если по 1.3 чтения или записи базы заметны (≥ 25 % хода): минуты пары блоком в несколько дней и/или запись
  закончившихся сигналов раз в несколько дней перед курсором (решение 1). Тесты `IdeasReplayTests`: сигналы и курсоры те
  же, что при записи по дням; рестарт между днями блока повторяет только дни блока. Если доля меньше — задача
  закрывается записью «не требуется» в design.md.

## 3. Параллельные ходы и рынок дня

- [ ] 3.1 `IdeasSettings.ReplayTurns` (по умолчанию 2) и привязка секции в `appsettings` сканера; `IdeasReplay.StartAsync`
  выбирает самую отстающую пару среди не идущих, держит набор идущих пар и словарь курсоров под блокировкой (решение 2).
  Тесты: два вызова подряд дают разные пары (сценарий «Два хода одновременно»); пара в ходу не выдаётся второй раз;
  после конца хода пара снова доступна, если отстаёт.
- [ ] 3.2 Полоса `IdeasAsync` в `ScannerSession`: прогревы первыми, затем запуск ходов до `ReplayTurns`, ожидание минуты
  или конца любого хода, падение хода — `journal.Failed("ideas", …)` без остановки остальных (решение 2). Тесты
  `ScannerSessionTests`: при двух ходах оба идут одновременно; упавший ход не роняет второй и полосу; прогревы читаются,
  пока ходы идут.
- [ ] 3.3 Пауза по темпу держит все ходы: тест `IdeasReplayTests` с `ScannerPace` опозданием 3 с — ни один из двух ходов
  не начинает следующий день, после возврата в срок оба продолжают (сценарий «Минутный цикл опоздал»).
- [ ] 3.4 Кэш закрытий BTC по дню на все ходы (не больше 16 дней) и funding пары одним чтением на ход с лимитом
  `3 × (дни + 8)` (решение 3). Тесты: два хода по одному дню читают BTC один раз; ход по 5 дням читает funding один раз;
  признаки сигналов (BTC, funding) те же, что при чтении по дням.
- [ ] 3.5 Сценарий «Те же сигналы»: тест, который прогоняет одну историю одним ходом и в два хода с другой парой и
  сравнивает сигналы, пути и курсоры.

## 4. Прогресс прогона

- [ ] 4.1 `IdeaReplayProgress(Done, Total, Slowest, EngineVersion)` в домене; `IIdeaReplayRepository.ProgressAsync(version)`
  одним запросом по `scanner_pairs` и `idea_replay` (решение 4). Интеграционный тест на Testcontainers: пара с курсором на
  дне покрытия — готова, с отстающим — нет и даёт `slowest`, без курсора — не готова, пара без `tick_size` не в `total`;
  пустая база — `0 из 0` без дня (сценарии «Прогон идёт», «Прогон догнал все пары», «Прогон ещё не начинался»).
- [ ] 4.2 `ScannerState.Replay`, `GetMarketQueryHandler` читает прогресс с `IdeasEngineVersion.Current`;
  `MarketResponse.Replay` (`done`, `total`, `slowest`, `engineVersion`), OpenAPI и `npm run generate` типов (сценарий «Ход
  прогона в ответе»). Тесты: обработчик отдаёт прогресс; тест контракта ответа.
- [ ] 4.3 `ScannerBanners`: баннер «Прогон идей: N из M инструментов» тона `run` с версией правил и местной датой
  отстающего дня, пока `done < total`; нет при `done == total`, в том числе `0 из 0` (сценарии «Прогон идёт», «Прогон
  закончен»). Тесты компонента на три состояния; `npm run lint`, `format:check`, `typecheck`, `test`, `build`.

## Workflow follow-up

- Архивировать изменение после проверки владельцем, затем PR; выкатка не требует прогона и миграций.
- После выкатки прочитать строки `Replayed` в логе сканера на проде (с одобрения владельца) и записать доли движка,
  чтений и записей — это вход для грилинга «прогон на других машинах».
