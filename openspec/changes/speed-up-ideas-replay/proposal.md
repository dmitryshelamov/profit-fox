# Proposal

## Why

Прогон идей по истории идёт строго последовательно в процессе сканера: одна пара, в ней день за днём, около 1,3 с на
пару-день, и каждая новая версия правил занимает 1,5–2 суток на 1 211 пар. Из-за этого выкатка любого изменения правил
(например, «Накопление / распределение») откладывается, а ход прогона виден только запросом в базу. Замер на проде
2026-11-08: сканер держит ровно одно ядро на 100 %, база 1,16 ядра, машина загружена на 3,7 из 4 ядер — прогон упирается
в вычисления движка, а не в ожидание базы.

## What Changes

- Тайминги хода прогона в логе сканера: пара, число дней, миллисекунды движка, чтений и записей базы.
- Профиль дня прогона с реалистичным числом открытых путей и устранение горячего участка движка и запросов без
  изменения сигналов: отпечаток референсных кейсов и версия правил остаются прежними, новый прогон не нужен.
- Параллельные ходы прогона: сканер ведёт несколько пар одновременно (число в настройках, по умолчанию 2), берёт самые
  отстающие разные пары; проверка темпа минутного цикла ставит на паузу все ходы.
- Рынок дня один на все ходы: закрытия BTC одного дня читаются один раз и переиспользуются, funding пары читается один
  раз на ход, а не на каждый день.
- Прогресс прогона в состоянии сканера и на экране «Рынок»: число пар, прогнанных до их покрытия, из числа пар к
  прогону, самый отстающий день и версия правил; баннер исчезает, когда прогон догнал все пары.

Не входит: сокращение окна 90 дней; прогон на других машинах (роль прогона в Worker с арендой пары — отдельное
изменение после этого, когда известна доля базы и Postgres слушает локальную сеть); больше двух ходов по умолчанию на
soyo-01; метрика прогресса в Prometheus.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `market-scanner`: требование «Прогон идей в фоне сканера» — несколько ходов одновременно по настройке, общая пауза
  по темпу, тайминги хода в логе; требование «Состояние сканера» — ход прогона идей (пар прогнано из пар к прогону,
  самый отстающий день, версия правил).
- `market-interface`: требование «Чтение снимка рынка» — состояние сканера в ответе `GET /api/market` несёт ход прогона;
  новое требование «Прогон идей на экране» — баннер с прогрессом прогона рядом с баннером загрузки истории.

Требования `trade-ideas` о прогоне (те же сигналы, без заглядывания вперёд, повторный прогон при смене правил) не
меняются: ускорение не меняет ни одного сигнала, что и проверяет референсный тест отпечатка.

## Impact

- `backend/src/ProfitFox.Application/Scanner/Ideas/IdeasReplay.cs`: выбор нескольких ходов, кэш рынка дня, тайминги;
  `IdeaEngine` / `SignalPathTracker` / `IdeaSeries` — горячий участок по результату профиля, без изменения результата;
  `ScannerSession.IdeasAsync` — запуск ходов параллельно; `IScannerJournal` — запись тайминга хода.
- Настройки сканера: новый параметр числа параллельных ходов прогона в секции `Ideas`.
- `ScannerState` / `GET /api/market` / `MarketResponse`: поля хода прогона, вычисляемые при чтении из `idea_replay` и
  `scanner_pairs`; схема OpenAPI и сгенерированные типы фронтенда.
- Фронтенд: `ScannerBanners` на «Рынке» — баннер прогресса прогона; e2e-сид состояния сканера.
- Тесты: референсный тест отпечатка версии остаётся зелёным; тесты `IdeasReplayTests` на выбор ходов, паузу и кэш;
  интеграционный тест состояния сканера с прогрессом; тест баннера.
- Без миграций базы и без смены версии правил; выкатка не требует прогона.
