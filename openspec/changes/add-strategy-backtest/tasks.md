# Tasks

Тесты бэкенда запускаются из `backend/`: `dotnet test ProfitFox.slnx`; фронтенда — из `frontend/`: `npm test`, `npm run
typecheck`, `npm run lint`, `npm run format:check`, `npm run build`. Каждая задача начинается с теста, который без неё
падает, и каждая группа заканчивается зелёным прогоном всех тестов своей части.

Ожидания не правятся ни в одной задаче: `TradeSimulatorTests`, `TradeExitTests`, `OutcomeParityTests`, `CycleRunTests`,
`PositionRunTests`, `PairPositionTests`, `PairOrdersTests`, `H0001ParityTests`, `SignalNodeParityTests`. До задачи 8.1
не правятся и `EngineVersionTests`, `HypothesisRunTests`, `OverlapRunTests`, `ParityThroughWorkerTests`,
`PairEvaluationTests`: отпечатки версии движка 2 обязаны держаться, пока прежний прогон в дереве. Если задача требует
иного — остановиться и записать это в «Открыто после применения».

Порядок групп — порядок работы: прежний прогон гипотез остаётся рабочим до группы 8 и служит образцом для сверки.

## Открыто после применения

Сюда записывается всё, что при применении разошлось с design.md.

- **1.1, проверка OpenSpec.** CLI `openspec` 2.1.1 (последний в npm на день применения) в режиме `--strict` не
  пропускает изменение: предупреждение «Requirement text is very long (>500 characters)» у требования «Создание,
  переименование, копирование и удаление стратегии» в дельте `strategy-constructor` (текст требования 520 знаков, а
  `--strict` считает предупреждение ошибкой). На CLI 2.0.0 и 2.1.0 проверка проходит без замечаний. Текст требования —
  артефакт владельца, при применении он не правился; проверки этого изменения идут на CLI 2.1.0. Предложение: разбить
  требование на два («Создание стратегии» и «Переименование, копирование и удаление») либо закрепить версию CLI.
