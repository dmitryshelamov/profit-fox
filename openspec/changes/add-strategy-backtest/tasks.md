# Tasks

Тесты бэкенда запускаются из `backend/`: `dotnet test ProfitFox.slnx`; фронтенда — из `frontend/`: `npm test`, `npm run
typecheck`, `npm run lint`, `npm run format:check`, `npm run build`. Каждая задача начинается с теста, который без неё
падает, и каждая группа заканчивается зелёным прогоном всех тестов своей части.

Ожидания не правятся ни в одной задаче: `TradeSimulatorTests`, `TradeExitTests`, `OutcomeParityTests`, `CycleRunTests`,
`PositionRunTests`, `PairPositionTests`, `PairOrdersTests`, `H0001ParityTests`, `SignalNodeParityTests`. До задачи 8.1
не правятся и `EngineVersionTests`, `HypothesisRunTests`, `OverlapRunTests`, `ParityThroughWorkerTests`,
`PairEvaluationTests`: отпечатки версии движка 2 обязаны держаться, пока прежний прогон в дереве. Если задача требует
иного — остановиться и записать это в «Открыто после применения».

Порядок групп — порядок работы: прежний прогон гипотез остаётся рабочим до группы 8 и служит образцом для сверки.

## Открыто после применения

Сюда записывается всё, что при применении разошлось с design.md.

- **1.1, проверка OpenSpec.** CLI `openspec` 2.1.1 (последний в npm на день применения) в режиме `--strict` не
  пропускает изменение: предупреждение «Requirement text is very long (>500 characters)» у требования «Создание,
  переименование, копирование и удаление стратегии» в дельте `strategy-constructor` (текст требования 520 знаков, а
  `--strict` считает предупреждение ошибкой). На CLI 2.0.0 и 2.1.0 проверка проходит без замечаний. Текст требования —
  артефакт владельца, при применении он не правился; проверки этого изменения идут на CLI 2.1.0. Предложение: разбить
  требование на два («Создание стратегии» и «Переименование, копирование и удаление») либо закрепить версию CLI.
- **2.2, вид без поля в запросе.** design.md, решение 1, говорит, что вид задаётся при создании, но не говорит, что
  делать с запросом `POST /api/strategies` без `kind`. Сделано так: без поля стратегия получает вид своего графа по тому
  же правилу, что прежние стратегии (`StrategyKindRules.Of`: «категория идей», если граф — стратегия по плану, иначе
  «для бота»), и этот вид пишется в колонку. `PUT` без `kind` сохраняет вид стратегии; `PUT` с другим видом отклоняется
  с ошибкой поля `kind` и в обработчике, и в репозитории (строка блокируется `FOR UPDATE`). Фронтенд передаёт вид
  всегда.
- **2.3, проверка графа без вида.** `POST /api/strategies/validate` без `kind` проверяет по правилам стратегии «для
  бота» (только общие правила стратегии), как до изменения; предпросмотр стратегии вид не принимает и тоже проверяет по
  общим правилам. Тест `StrategyCommandHandlerTests.No_close_after_node` теперь ждёт две ошибки: стратегия создана без
  вида, получила вид «категория идей» по графу, и у графа без `close-after` нарушено ещё и правило срока этого вида.

- **3.1–3.3, сетка и настройки.** Номер набора считается с 1. Повтор таймфрейма в запросе отбрасывается, повтор
  значения параметра — нет: он даёт свой набор. Без таймфреймов в запросе прогон считает `4h`
  (`BacktestRules.DefaultTimeframe`): spec называет таймфреймы необязательными, а значения по умолчанию не даёт; `4h` —
  таймфрейм H0001 и сценария CLI `bench run funding-short --wait`. Даты принимаются как `2026-06-01` или момент ISO 8601
  в полночь UTC; другое — ошибка `InvalidDate`. Значение, которое не читается ни как число JSON, ни как `true`/`false`,
  ни как срок, даёт `ParameterTypeMismatch`, как и значение другого типа; неизвестное имя — новый код
  `UnknownParameter`. Тексты ошибок настроек — по-русски: их показывает форма запуска.

- **4.1, перевод прежнего прогона.** `RunDesign` остаётся до задачи 8.3 и переводится в `BacktestDesign` методом
  `ToBacktest()`: у `PairEvaluation` и `RandomEntries` есть конструкторы и с прежним `RunDesign`, поэтому
  `PairEvaluationTests` и прежний `ExecuteRunCommandHandler` не правились. До 8.3 у `BacktestDesign` есть ещё поле
  `Measure` (у гипотезы с мерой `R` прежний прогон не меняется); у прогона стратегии мера всегда `net`.
- **4.1, срок без значения.** `BacktestDesign.Fits` считает отсутствующий срок нулевым: такая заявка входит в историю,
  если её момент не позже конца, и отказывает с причиной `plan`, а не `period`; случайный вход — по тому же правилу.
- **4.3, окно недели.** «Наибольший срок шагов этой недели» — наибольший срок шагов недели и шага, действующего на её
  начало (`PairSteps.Longest`): у случайного входа срок той свечи, что закрылась к его моменту, и она может быть из
  прошлой недели. Окно чтения минут — объединение окон наборов с заявками в этой неделе.
- **4.2, t разницы.** Кроме недель меньше двух, t нет и при нулевом разбросе недельных средних: деление на ноль дало бы
  бесконечность, которую JSON не передаёт.

- **6.1–6.2, хранение.** Сверх таблицы решения 2 у `backtests` есть колонка `sets` (число наборов: список прогонов
  его показывает, не читая наборов); числа набора и пары лежат в `jsonb` своего вида, а не колонками. Наборы пишутся при
  постановке с пустыми числами, числа и пары — в транзакции окончания `done`, пока Worker держит строку `FOR UPDATE`.
  Ждущий прогон при отмене удаляется вместе с наборами. `Backtest.MaxLostLeases = 3` повторяет `Run.MaxLostLeases`.

- **7.1–7.5, API и Worker.** До задачи 8.3 Worker берёт сначала прогон стратегии, а при пустой очереди прогонов — прогон
  гипотезы из прежней очереди: так `WorkerTests` и `ParityThroughWorkerTests` остаются зелёными без правки. Набор на
  остатке истории ставится только у прогона в состоянии `done` (иначе `422` с кодом `NotDone`); граф берётся из
  исходного прогона, а не из стратегии, поэтому остаток считается и у удалённой стратегии. «Время чтения» — время внутри
  запросов к сервису данных, «время расчёта» — всё остальное время прогона. Законченный прогон пишет число пройденных
  пар в `pairs_done` и `pairs_total`: продление аренды, которое пишет ход, могло не успеть после последней пары. Отказ
  сервиса данных пишется причиной «история недоступна: …». `GET /api/backtests/{id}/sets/{n}` отдаёт набор вместе с
  парами.
