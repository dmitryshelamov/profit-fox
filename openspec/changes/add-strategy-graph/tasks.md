# Tasks

Тесты бэкенда запускаются из `backend/`: `dotnet test ProfitFox.slnx`. Каждая группа заканчивается зелёным прогоном
всех тестов; ожидания тестов `TradeSimulatorTests`, `OutcomeParityTests`, `ExecutionTests` и `H0001ParityTests` в этом
изменении не правятся.

## 1. Граф стратегии

- [ ] 1.1 Четыре вида узлов в `NodeCatalog`: `enter` (вход `when`, настройка `side`), `stop-loss` и `take-profit`
  (вход `distance`), `close-after` (вход `after`), без выходов (design.md, решение 2). У вида узла — признак «допустим
  в сигнале»; у новых видов он ложен. Проверить unit-тестами каталога: пины, настройки и признак каждого нового вида;
  прежние десять видов допустимы в сигнале.
- [ ] 1.2 Проверка стратегии и чтение стратегии в `StrategyGraph` и `GraphValidator` с новыми кодами ошибок
  (spec `strategy-graph` «Стратегия», «Сторона входа»). Проверить unit-тестами сценарии: «Стратегия H0001», «Нет узла
  входа», «Нет срока», «Два стопа», «Стратегия с выходом», «Вход без стороны», «Сторона без исполнения», «Двусторонняя
  стратегия»; все ошибки одного графа приходят за один раз.
- [ ] 1.3 Проверка сигнала отклоняет узлы позиции (spec `strategy-graph` «Сигнал»). Проверить unit-тестом сценарий
  «Узел входа в сигнале»; тесты `GraphValidationTests` и `SignalLibraryTests` проходят без правок ожиданий.
- [ ] 1.4 Сборка стратегии из сигнала и значений плана (design.md, решение 8). Проверить unit-тестами:
  - из сигнала H0001 и плана «шорт, `4h`» получается граф из design.md, решение 2, и он проходит проверку стратегии;
  - план со стопом и целью добавляет `stop-loss` и `take-profit` с этими значениями;
  - занятый `id` (`enter` уже есть в сигнале) получает номер;
  - граф сигнала после сборки не изменился.

- [ ] 4.2 Расчёт пары в `HypothesisRunner` и `PairEvaluation` через исполнитель стратегии и правило позиции; розыгрыш

  - `HypothesisRunTests`, `ParityThroughWorkerTests` и `WorkerTests` проходят без правок ожиданий;
  - unit-тесты сценариев «Второе событие в сроке первого», «Стоп до второго события», «Момент пропущенного события не
    берётся», «Случайный вход при открытой позиции», «План со стопом и целью».
- [ ] 4.3 Сверочный прогон считает моменты выхода циклов событий, но не их результаты (spec `hypothesis-bench` «Момент

- [ ] 4.4 Число событий, пропущенных при открытой позиции, в отчёте прогона. Проверить `RunReportTests`: сценарии
