  баллу. Задача не отмечена.
- 3.6 — сверка с макетами на dev-стенде и снимки 1440×900 в `mockups/after/`: dev-стенда из облака нет; остаётся главной
  сессии.
- 1.3 — объём покупок вживую и глубина истории: сервис данных и dev-стенд из облака недоступны; доля живых минут с
  `buy_volume` и первый месяц с ним в истории не замерены. Группа 6 сделана по плану; если вживую объём покупок есть
  меньше чем у 90 % минут со сделками, метки покупок вживую почти не будут стоять (риск 1 `design.md`).
- 7.2 — метки с узлом «OI» и с `buyVolume` на `1h` на dev-стенде: нужен стенд с живой лентой; остаётся главной сессии.
- `npm run generate:api` запускался по-настоящему: API в `Development` на локальном Postgres 17 (Docker), типы
  сгенерированы из его `/openapi/v1.json`, не правились руками.
- Решения по ходу, которых нет дословно в `design.md` (на ревью):
  - `CandleFacts` — `readonly record struct` с неявным переводом из `FundingPayment?`: прежние вызовы `Step(candle,
    payment)` в тестах не менялись; именованный аргумент `lastFunding:` в 14 тестовых файлах переименован в `facts:`
    (ожидания не тронуты). `GraphRun.Step` отклоняет точку OI со временем не раньше закрытия, как выплату позже закрытия.
  - Перенос весов при смене текста метки: строка нового текста получает веса старого, если своей у неё нет; строка
    старого текста удаляется, только если ни у одной другой метки сигнала нет этого текста (выключенная метка другого
    сигнала может носить тот же текст).
  - Балл в ответе идеи считается только в списках (`ListAsync`: «Открытые», «Журнал», идеи пары); `FindAsync` и
    `OpenAsync` сканера его не считают (0), чтобы не добавлять подзапрос на каждый проход сканера.
  - `minScore` принимается строкой и разбирается в Application, чтобы «abc» давал `422` с полем `minScore`, а не
    автоматический `400` модели.
  - `HistoryMonth` получил вид `HistoryKind` первым позиционным полем; прежний конструктор `(id, interval, start)`
    оставлен и выводит вид из `interval`, так что месяцы свечей и фандинга равны прежним.
  - Кэш предпросмотра держит историю с OI отдельной записью (ключ с признаком OI).
  - Прогрев сканера читает точки OI на глубину `Scanner:WarmupCandles` интервалов; пока OI пары «загружается», пара
    ждёт, как при загрузке фандинга.
  - На странице «Скоринг» выбор «Вид» — состояние страницы, в браузере не помнится (в спеке не требуется).
  - Ожидания, поменявшиеся вместе со спеками: `MigrationTests` (таблица `label_weights`, версия `202611270001`),
    `FilterRulesTests` (поле `score` в перечне), `NodesTests` (27 видов в каталоге сигнала), `ideas.test.tsx` (колонка
    «Балл» сдвинула ячейки), `shell.test.tsx` (шесть разделов).
- Локальная проверка вида (не замена 3.6): страница «Скоринг» и «Идеи» на локальном API с заполненной базой по виду
