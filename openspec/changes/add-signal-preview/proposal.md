# Предпросмотр событий сигнала

## Why

Сигнал сейчас можно проверить только прогоном стенда, который читает историю часами и тратит попытку. Прежде чем
отправлять сигнал на стенд, нужно видеть, где он срабатывает: на графике пары, за секунды, без вердикта и без записи в
журнал. Это шаг 2 плана «ядро → предпросмотр → конструктор → проверка из конструктора → бот»; конструктор шага 3 встроит
этот предпросмотр в себя.

## What Changes

- Новое веб-приложение стенда `ProfitFox.Bench.Api`, отдельно от бота. Пока оно запускается локально на Маке, без Docker
  и развёртывания.
- API предпросмотра:
  - список пар — те же linear USDT перпетуалы, что видит стенд;
  - список гипотез из `bench/hypotheses` с их сигналом и таймфреймом;
  - предпросмотр: граф сигнала, таймфрейм и пара → свечи разведки и события сигнала, либо ошибки графа.
- События предпросмотра считаются тем же кодом, что события прогона стенда. Для этого расчёт событий пары выносится из
  `HypothesisRunner` в общий класс.
- Предпросмотр показывает только разведку: история после `2026-05-15` не читается. Исходов сделок нет, строк в журнале
  нет, проверка чистого дерева не нужна.
- Новый фронтенд `frontend/`, стек как в profit-fox-v2: React 19, Vite, TypeScript, Tailwind, lightweight-charts.
  На одной странице:
  - выбор гипотезы, которая подставляет свой сигнал в поле JSON;
  - правка JSON и таймфрейма;
  - выбор пары;
  - график свечей с метками событий и список событий;
  - ошибки графа с указанием места.

## Capabilities

### New Capabilities

- `signal-preview`: предпросмотр событий сигнала на паре — что принимает и возвращает API, граница разведки, ошибки
  графа, совпадение событий с прогоном стенда, страница с графиком и метками.

### Modified Capabilities

Нет: требования стенда, исполнителя и чтения истории не меняются. Перенос расчёта событий из `HypothesisRunner` —
внутренняя перестройка, события прогона остаются теми же.

## Impact

- **Код:**
  - новый проект `backend/src/bench/ProfitFox.Bench.Api`;
  - общий расчёт событий пары в `ProfitFox.Bench`;
  - тесты в `ProfitFox.Tests.Unit` и `ProfitFox.Tests.Integration` (поддельный сервис данных из шага 1);
  - новая папка `frontend/`.
- **Зависимости:**
  - бэкенд — `Microsoft.AspNetCore.OpenApi`;
  - фронтенд — react, vite, typescript, tailwindcss, lightweight-charts, @tanstack/react-query, openapi-fetch,
    openapi-typescript, vitest.
- **Внешние системы:** только чтение gRPC `History` и REST каталога сервиса данных на soyo-02, как у `bench run`. Прод и
  бот не затрагиваются.
