# Tasks

Тесты бэкенда запускаются из `backend/`: `dotnet test ProfitFox.slnx`; фронтенда — из `frontend/`: `npm test`,
`npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`. Каждая группа заканчивается зелёным
прогоном всех тестов своей части. Вид сверяется с файлами `mockups/` этого изменения; поведение — со спецификациями.
Расчёт не меняется: ожидания `GraphValidationTests`, `ExecutionTests`, `TradeSimulatorTests`, `OutcomeParityTests`,
`H0001ParityTests` и файл `Tests.Integration/Fixtures/EngineVersions.json` в этом изменении не правятся.

## Открыто после применения

Сюда записывается всё, что при применении разошлось с design.md.

- 1.1. Применение шло в облачном контейнере. Docker Hub отвечал `429 Too Many Requests`, поэтому образ `postgres:17`
  взят с зеркала `mirror.gcr.io/library/postgres:17` и помечен локально как `postgres:17` (тот же образ, 17.12);
  интеграционные тесты запускались с `TESTCONTAINERS_RYUK_DISABLED=true` (образ Ryuk с Docker Hub не скачать). Код
  тестов и `BenchDatabase` не менялись.
- 2.1. Чтение называется `IStrategyRepository.UsingSignalsAsync`; сигнал без ссылок в ответе отсутствует (не пустой
  список). Порядок имён — `ORDER BY s.name` базы, как у прежнего `UsingSignalAsync`.
- 2.2. `GetSignalsQueryHandler` получил в конструкторе `IStrategyRepository`. При пустом списке сигналов репозиторий
  стратегий не вызывается совсем.
- 2.3. `GetStrategiesQueryHandler` получил в конструкторе `ISignalRepository`. Запись сигнала стратегии — новые
  `StrategySignalInternal` и `StrategySignalItem` (имя, версия ссылки, последняя версия). Ссылка на сигнал, которого нет
  в библиотеке, в `Signals` не попадает (имени нет); база такого не допускает — используемый сигнал не удаляется. Если
  в списке нет ни одной ссылки, `ReadVersionsAsync` не вызывается.
- 2.4. Чтение журнала — `ILedgerRepository.LastAsync(versions)` с новым значением `HypothesisVersion(Id, Version)`;
  из строк с одним временем отдаётся записанная последней (`time DESC, seq DESC`). Ответ запроса `GetLastRunsQuery` —
  `LastRunInternal(Active, Finished)`: задано одно из двух, гипотезы без прогонов в ответе нет. Для unit-тестов
  обработчика добавлены репозитории в памяти `MemoryRunRepository` и `MemoryLedgerRepository` (раньше их не было): они
  умеют только читать, шаги Worker'а и решения бросают `NotSupportedException`.
- 2.4. Интеграционный тест журнала (`LastRunsTests`) сначала сохраняет версии гипотез: строка `runs`, по которой
  определяется вид прогона, ссылается на версию гипотезы внешним ключом.
- 2.5. `schema.d.ts` пересобран не руками: API запущен в контейнере на Postgres в Docker, документ снят с
  `http://127.0.0.1:5240/openapi/v1.json`, файл собран `openapi-typescript` из него. `lastRun` в схеме обязателен и
  может быть `null`, а в ответе при `null` его нет — как у прежних полей (`JsonIgnoreCondition.WhenWritingNull`);
  страница читает отсутствие как «не запускалась».

- 3.1. У пакетов `@fontsource-variable` нет отдельных файлов стилей по наборам (только `index.css` и `wght.css` со всеми
  наборами), поэтому в `src/main.tsx` подключается свой `src/fonts.css`: четыре `@font-face` с файлами пакетов
  `*-latin-wght-normal.woff2` и `*-cyrillic-wght-normal.woff2` и их диапазонами `unicode-range`. В сборку попадают
  только эти четыре файла; семейства называются `Inter Variable` и `JetBrains Mono Variable`.
- 3.1. Проверка «в собранном CSS есть оба семейства и все токены» сделана и руками по `dist`, и тестом
  `src/theme.test.ts` (токены таблицы решения 2 в `index.css`, `@theme static`, файлы шрифтов). Тест читает файлы с
  диска: vitest отдаёт пустой текст вместо импортированного CSS.
- 3.2. Кроме `Button` из `shared/ui/Button.tsx` вынесена функция классов `buttonLook(variant)` — для ссылки, которая
  выглядит кнопкой («Открыть гипотезу»). Вид кнопки тесты читают по `data-variant`. У `Menu` стрелки вверх и вниз
  переводят фокус между пунктами; у `Dialog` без `onClose` Escape ничего не делает (вопрос о черновике ждёт кнопку).
- 3.2. Фон под диалогом — `app` с прозрачностью (`backdrop:bg-app/70`), отдельного токена нет.
- 3.3. Запрос очереди — общий `pages/runs/useActiveRuns.ts`; страница «Прогоны» теперь тоже переспрашивает пустую очередь
  раз в 30 с (раньше не переспрашивала совсем). Знак и имя продукта в шапке — не ссылка. Пока первый ответ не пришёл,
  на месте чисел «Загрузка…»; «Стенд не отвечает» появляется после одной повторной попытки запроса (общая настройка
  `retry: 1`), то есть примерно через секунду после отказа. В `test/routes.ts` в общие маршруты добавлен
  `GET /api/runs` с пустой очередью: его теперь спрашивает шапка на каждой странице под ней.
- 3.1 (уточнено в группе 4). Макеты набраны Inter в дисплейном начертании (ось оптического размера 32): тот же текст
  обычным начертанием на 8 % шире, и колонки макета в него не помещаются. Поэтому подключены файлы пакета с осью
