# Tasks

Новая логика идёт строго по TDD: красный тест, минимальный код, рефакторинг. Ссылки «решение N» — на design.md,
сценарии — на дельты спек этого изменения. Все числа денег и цен — `decimal`, время — UTC.

## 1. Домен: признаки рынка

## 2. Движок: расчёт признаков

- [x] 2.1 `IdeaInputs.BtcChange` и `IdeaInputs.Funding` (решение 2); `IdeaEngine` с окном `max(окно сетапов, 1 441)` и
  расчётом изменения пары по первой минуте окна. Тесты движка: сигнал после 1 441 минуты с падением 5 % получает
  «падение пары за сутки», с 1 440 минутами — нет («Нет истории»); `BtcChange −0.01` даёт «падение BTC», `Funding 0.0005`
  — «высокий funding»; живая идея получает тот же уровень, что сигнал прогона на тех же минутах.
- [x] 2.2 `IdeaOutcomes` передаёт `signal.Features` в `IdeaOutcome` (тест прохода видит новый уровень); `CalibrationCalculator`
  работает на восьми уровнях — тесты подкорзин переписаны на `DayDrop` / `HighFunding` вместо `StrongMove` /
  `HighVolume`, эталонные числа прежние.

## 3. Живые идеи и прогон

- [x] 3.1 `ScannerMarket.FundingLoaded` / `FundingOf` (решение 4), `ScannerBackfill.LoadFundingAsync` кормит память;
  `LiveIdeas` при прогреве пары читает последнюю ставку за 7 дней из `IFundingRateRepository`, когда в памяти её нет, и
  раз в минуту считает изменение BTC по `market.Minutes`. Тесты: ставка из докачки попадает во входы идей пары; без
  минут BTC за 240 минут вход `null`; spot-пара получает `Funding null` и то же изменение BTC.
- [x] 3.2 `IdeasReplay` читает на день минуты `linear` / `BTCUSDT` за `[day − 240 мин, day + 1 день)` и funding пары за
  `[day − 7 дней, day + 1 день)` и даёт `IdeaInputs` на каждую минуту (решение 5). Тесты сценариев «Признаки в прогоне»
  (ставка 10:05 не видна сигналу 10:00) и «BTC у spot-идеи» на прогоне; у `BTCUSDT` его же минуты.
