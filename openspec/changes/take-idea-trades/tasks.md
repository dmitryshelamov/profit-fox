# Tasks

Новая логика идёт строго по TDD: красный тест, минимальный код, рефакторинг. Тесты и локальные запуски ходят только в
заглушку Bybit или в подменённый транспорт. Реальные ордера ставит только задача 0.1, и только с разрешения владельца.

## 0. Проверка спота

- [ ] 0.1 С отдельного разрешения владельца — аккаунт, инструмент, сторона и сумма называются до запуска — поставить
  одну минимальную сделку на споте: вход лимитом с TP/SL. Записать, что приходит в потоки ордеров и исполнений
  (`orderLinkId`, `parentOrderLinkId`, `stopOrderType`, `ocoTriggerBy`), закрыть сделку и выбрать в design.md
  (решение 9): связь или запасной вариант. Готово, когда результат и выбор записаны в design.md.

- [x] 1.3 `IdeaTradeRefusals`: все причины из требования «Когда вход отклоняется». Готово, когда на каждую причину есть

- [x] 1.4 Сущность `IdeaTrade`: статусы и переходы, исполнение входа целиком и частично, срок входа, TP, SL, отмена,

- [x] 1.5 `Reconciliation.Check` принимает позиции сделок рядом с позициями ботов. Готово, когда тест «Бот и сделка по

## 4. Worker

- [x] 4.1 `IdeaTradeSession`: отправка входа, события входа, детей и исполнений, срок входа, отмена, закрытие reduce-only.
  Готово, когда тесты на `FakeExchange` проходят сценарии «Цель», «Откат не дождался» и «Закрыть по рынку».
- [x] 4.2 Восстановление: подъём из базы, догрузка из истории, без повторной отправки, сверка. Готово, когда тест
  «Стоп сработал, пока Worker лежал» зелёный.
- [x] 4.3 Сессия бота не считает чужими исполнения сделок и их детей. Сверка и деньги учитывают сделки. При
  расхождении сделка уходит в «Ошибка» без отмены детей. Запуск бота противоположного направления отклоняется. Готово,
  когда зелёные сценарии «Стоп сработал рядом с ботом», «Вход сделки по идее рядом с ботом», «Шорт-бот рядом с
  лонг-сделкой», «Денег не хватает с учётом сделки по идее» и «Позицию закрыли руками».
- [x] 4.4 `LiveTradingBackgroundService` берёт сделки вместе с ботами и продлевает их аренды общим циклом. Готово,
  когда интеграционный тест видит, что Worker с `Trading:Enabled` ведёт сделку, а без него — нет.
