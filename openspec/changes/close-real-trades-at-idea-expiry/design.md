# Design

## Context

- Сделку с деньгами ведёт торговый Worker: на каждую сделку своя `IdeaTradeSession`. Изменения сделок он перечитывает
  по `idea_trades.updated_at > since` (`IdeaTradeRepositoryQueries`, строка 90).
- Срок входа «Отката» уже работает по часам Worker: `IdeaTrade.EntryDeadline` пишется при создании,
  `ScheduleDeadline` будит сессию, `AdvanceAsync` снимает вход по `EntryExpired(now)`.
- «Закрыть по рынку» — `CloseRequested` → `CloseAsync` ставит reduce-only рыночный ордер роли `close`; его исполнения
  идут в ногу `Manual` (`OwnOrderAsync`), сделка становится «Закрыта вручную», `WindDownAsync` снимает стоп и цель.
- Статус «Закрыта по сроку» и нога `Expiry` уже есть, но только у учебных сделок; роль ордера ограничена
  `CK_idea_trade_orders_role CHECK (role IN ('entry', 'close'))`.
- Сканер пишет исход закрытой идеи на сделки в `IdeaRepository.SaveAsync`, нарочно не трогая `updated_at`.
- Момент конца идеи — `IdeaTrack.LifeEndsAt` (добавлен в #85); журнал читает его из идей сделок в работе.
- Решения владельца: в памяти обсуждения и в proposal.md.

## Goals / Non-Goals

**Goals:**

- Сделка с деньгами закрывается в момент конца идеи независимо от того, где сейчас сканер.
- Колонка и Worker опираются на один и тот же момент.

**Non-Goals:**

- Учебные сделки: они закрываются по сроку сканером, по цене выхода идеи, как сейчас.
- Повтор отклонённого закрытия по сроку: его закрывает владелец, как отклонённое ручное закрытие.
- Закрытие лимитным ордером по цене выхода идеи: только рынок.
- MOEX: сделок с деньгами там пока нет.

## Decisions

1. **Момент хранится на сделке (`IdeaTrade.IdeaEndsAt`, `idea_trades.idea_ends_at`).** `IdeaTrade.Create` берёт
   `idea.Track.LifeEndsAt`, если идея уже вошла. Если идея вошла позже, момент пишет сканер в той же транзакции
   `IdeaRepository.SaveAsync`, где сохраняет вход идеи: `UPDATE idea_trades SET idea_ends_at = …, updated_at = now()
   WHERE idea_id = … AND idea_ends_at IS NULL AND status IN ('awaiting_entry', 'open')`. Обновление `updated_at` нужно,
   чтобы Worker перечитал сделку и запланировал пробуждение. Альтернатива — сканер сам просит закрыть, когда идея
   истекла: проще, но закрытие отстаёт вместе со сканером, а на soyo-01 он упирается в CPU. Отвергнута владельцем.
2. **Worker будит сессию в момент конца идеи** так же, как в срок входа: `ScheduleDeadline` планирует оба момента. В
   `AdvanceAsync`, если `IdeaEndsAt <= now` и закрытие по сроку включено:
   - «Открыта» без ордера закрытия → ордер роли `expiry` (reduce-only, по рынку, как `close`);
   - «Ждёт входа» → снять вход тем же путём, что `CancelRequested`, сделка «Отменена».
   Если выключено — следующий взгляд через минуту, пока сделка открыта: так включение подхватывается в течение минуты
   без отдельного сигнала от API.
3. **Роль ордера `expiry`.** Его исполнения идут в ногу `Expiry`, и `Settled` даёт «Закрыта по сроку». Альтернатива —
   флаг на сделке и роль `close`: меньше миграции, но статус зависел бы от флага, а история ордеров не говорила бы, почему
   закрыли. `WindDownAsync` для «Закрыта по сроку» делает то же, что для «Закрыта вручную»: хранит исполнения и снимает
   стоп и цель.
4. **Одна попытка.** Ордер `expiry` ставится, только если у сделки ещё не было ордера этой роли (по
   `idea_trade_orders`, включая завершённые). Отклонённое или частично отменённое закрытие оставляет сделку «Открыта» с
   причиной, как у ручного; дальше её закрывает владелец. Повтор каждую минуту отвергнут: отказ Bybit часто постоянный
   (пара вне торгов), и он засыпал бы журнал.
5. **Настройка `CloseAtIdeaExpiry` в `IdeaTradingSettings`, колонка `close_at_idea_expiry boolean NOT NULL DEFAULT
   true`.** Сессия читает её в момент конца идеи (и раз в минуту после, если выключена), а не при входе: владелец решил,
   что переключатель действует и на открытые сделки.
6. **Миграция заполняет `idea_ends_at` только у открытых сделок с активной идеей** (`ideas.status = 'active'`):
   вход идеи + `life_candles × candle_minutes`. У сделок, чья идея уже закрыта (PIEVERSEUSDT), момент остаётся пустым, и
   выкатка не отправляет по ним ни одного ордера. `updated_at` миграция не трогает: Worker перечитывает все сделки при
   старте после деплоя.
7. **Журнал.** К `ideaEndsAt` из #85 добавляется `closesAtIdeaEnd` (`bool`): учебная — есть `ideaEndsAt`; реальная —
   есть `ideaEndsAt`, у сделки есть `IdeaEndsAt` и настройка включена. Момент для колонки по-прежнему из идеи — он равен
   сохранённому по построению.
8. **Колонка.** `ideaLeftText` возвращает остаток и, если `closesAtIdeaEnd`, вторую строку «закроется DD.MM HH:mm»
   (`formatMoment`, время владельца). При исходе идеи — «идея закрыта» вместо «закрыта». Флажок в `SettingsPanel` с
   подсказкой из спеки.

## Risks / Trade-offs

- [Рыночное закрытие хуже итога идеи на комиссию taker и проскальзывание] → принято владельцем; колонка «Сейчас»
  показывает результат по рынку.
- [Идея вошла, пока сканер лежал] → момент появится, когда сканер догонит минуты; до этого сделка не закроется по сроку.
  Окно — время простоя сканера.
- [Worker был недоступен в момент конца идеи] → при старте сессия видит прошедший момент и закрывает сразу.
- [Стоп или цель сработали в ту же секунду] → `CloseAsync`/закрытие по сроку сначала обновляет стоп и цель
  (`RefreshChildrenAsync`) и не ставит ордер, если позиции нет.
- [Первый деплой закрывает сделки по живым идеям] → только по тем, чья идея кончится после выкатки; уже пережившие идею
  не трогаются.

## Migration Plan

1. Миграция: `idea_trades.idea_ends_at timestamptz NULL` с заполнением по решению 6; `idea_trading_settings.
   close_at_idea_expiry boolean NOT NULL DEFAULT true`; `CK_idea_trade_orders_role` с `'expiry'`.
2. Деплой обычный (Approve в `production`). После него Worker сам закрывает сделки с деньгами в момент конца идеи.
3. Откат: выключить «Закрывать сделку по сроку идеи» — сразу, без деплоя; или задеплоить прошлую версию (колонки
   остаются, старый код их не читает; ордеров роли `expiry` старый код не знает, поэтому откатывать только когда их нет
   в работе).
