# Spec Delta

## MODIFIED Requirements

### Requirement: Версия — номер сборки коммита `main`

Прод SHALL запускать только образы, собранные из коммита ветки `main`. Каждая новая сборка коммита `main` SHALL получать
следующий номер версии — целое число на единицу больше наибольшего выданного (первая версия — `1`): коммит помечается
git-тегом `v<N>`, а образы API, Worker'а, сканера, веба, сервиса рыночных данных и сверки публикуются с тегом `<N>`.
Коммит MUST NOT получать два номера. Все сервисы прода на soyo-01 SHALL работать на одном номере; сервис рыночных данных
и сверка могут работать на другом. Образы MUST NOT собираться на сервере прода.

#### Scenario: Мерж в main

- **WHEN** PR смержен в `main`, для его коммита прошли проверки CI, Frontend и E2E, а наибольшая выданная версия — `6`
- **THEN** вне прода коммит получает тег `v7`, а образы API, Worker'а, сканера, веба, сервиса рыночных данных и сверки
  публикуются в реестре с тегом `7`

#### Scenario: Пересборка того же коммита

- **WHEN** сборку коммита с тегом `v7` запускают ещё раз
- **THEN** номер остаётся `7`, нового тега не появляется

#### Scenario: Проверки не прошли

- **WHEN** у коммита `main` упала хотя бы одна из проверок CI, Frontend или E2E
- **THEN** образы этого коммита не собираются, и выкатить его нельзя

## ADDED Requirements

### Requirement: Отдельная выкатка сервиса рыночных данных

Сервис рыночных данных SHALL выкатываться на свою машину только ручным запуском на номер версии и после подтверждения
владельца в отдельном окружении GitHub, только из `main`. Выкатка прода MUST NOT перезапускать сервис. Номер без тега
`v<N>` на коммите `main` или образ не из этого коммита MUST отклоняться без изменений на машине сервиса.

#### Scenario: Выкатка прода

- **WHEN** владелец выкатывает на прод версию `8`, а сервис работает на версии `7`
- **THEN** сервис не перезапускается и продолжает работать на версии `7`

#### Scenario: Выкатка сервиса

- **WHEN** владелец запускает выкатку сервиса на версию `8` и подтверждает её
- **THEN** сервис и его база на мини-ПК работают на версии `8`, собранные данные сохранены

#### Scenario: Откат сервиса

- **WHEN** сервис на версии `8`, и владелец запускает его выкатку на версию `7`
- **THEN** сервис работает на версии `7`, собранные данные сохранены

### Requirement: Секреты и доступ машины сервиса

Пароль базы сервиса SHALL храниться только на его машине в файле, доступном только её пользователю, и MUST NOT попадать в
репозиторий, образы, настройки GitHub и логи выкатки. Доступ выкатки к машине сервиса MUST ограничиваться запуском выкатки
заданной версии с машины выкатки и MUST NOT давать shell.

#### Scenario: Ключ выкатки сервиса

- **WHEN** ключом выкатки сервиса пытаются открыть shell на мини-ПК или зайти им не с машины выкатки
- **THEN** мини-ПК отказывает

### Requirement: Запуск сверки на soyo-01

Сверку SHALL запускать и останавливать владелец отдельным проектом compose на soyo-01, с номером версии, вне прод-деплоя.
Строка подключения сверки к прод-базе (роль только на чтение) SHALL храниться только на soyo-01 и MUST NOT попадать в
репозиторий. Выкатка прода MUST NOT запускать, останавливать или обновлять сверку.

#### Scenario: Выкатка прода при работающей сверке

- **WHEN** сверка работает, и владелец выкатывает на прод новую версию
- **THEN** сверка продолжает работать и после выкатки сверяет данные дальше
