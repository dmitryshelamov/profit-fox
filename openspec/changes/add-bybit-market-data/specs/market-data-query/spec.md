# Spec Delta

## Purpose

Чтение сохранённых свечей инструмента за период, чтобы проверять результат загрузки и отдавать историю потребителям — бэктесту и интерфейсу.

## ADDED Requirements

### Requirement: Чтение свечей за период
Система SHALL возвращать сохранённые свечи по категории рынка, символу, интервалу и периоду `[from, to)` по open time, упорядоченные по возрастанию open time. Каждая свеча содержит open time в UTC и значения open, high, low, close, volume, turnover.

#### Scenario: Свечи есть
- **WHEN** в хранилище есть свечи `linear` / `BTCUSDT` / `60` с open time `00:00`, `01:00`, `02:00` за `2024-01-01`, и пользователь запрашивает период `[2024-01-01T01:00:00Z, 2024-01-01T03:00:00Z)`
- **THEN** система возвращает две свечи с open time `01:00` и `02:00` в этом порядке

#### Scenario: Свечей нет
- **WHEN** пользователь запрашивает период, за который свечи не загружались
- **THEN** система возвращает пустой список

### Requirement: Точные значения в ответе
Цены, объём и оборот MUST передаваться в ответе без потери точности — как десятичные строки, в точности равные сохранённым значениям.

#### Scenario: Малый объём
- **WHEN** сохранена свеча с volume `0.000123`
- **THEN** в ответе volume равен строке `"0.000123"`

### Requirement: Ограничение размера ответа
Система SHALL возвращать не более `limit` свечей, начиная с самой ранней в периоде; `limit` по умолчанию 1000, максимум 5000. Чтобы получить следующую порцию, клиент повторяет запрос с `from`, сдвинутым за open time последней полученной свечи.

#### Scenario: Свечей больше лимита
- **WHEN** за период сохранено 1500 свечей и пользователь запрашивает их без `limit`
- **THEN** система возвращает первые 1000 свечей по возрастанию open time

#### Scenario: Лимит больше максимума
- **WHEN** пользователь передаёт `limit` = 10000
- **THEN** система отклоняет запрос с ошибкой валидации по параметру `limit`

### Requirement: Валидация параметров чтения
Система MUST отклонять запрос чтения с ошибкой валидации, если категория не `spot` и не `linear`, интервал не входит в список интервалов Bybit или `from` не меньше `to`.

#### Scenario: Некорректный период
- **WHEN** пользователь запрашивает свечи, где `from` позже `to`
- **THEN** система отклоняет запрос с ошибкой валидации по периоду
