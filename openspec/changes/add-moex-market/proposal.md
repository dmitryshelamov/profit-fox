# Proposal

## Why

profit-fox торгует и считает только на Bybit: инструмент — это `(category, symbol)` с категориями `spot` и `linear`, аккаунт
биржи — ключ и секрет Bybit, данные читаются анонимно. Владелец хочет полную интеграцию с T-Invest (акции MOEX), и это
первый из четырёх согласованных change: он вводит третий рынок в модель данных и даёт данные без заявок, чтобы
проверить на реальном токене лимиты, календарь и вид свечей до того, как на MOEX пойдут деньги. Живые боты, сканер с
идеями и сделки по идеям на MOEX идут следующими change и опираются на этот.

## What Changes

- Третья категория рынка `moex`: акции основного режима TQBR Московской биржи в рублях через T-Invest Invest API.
  Символ — тикер (`SBER`). Биржа инструмента выводится из категории на границе; `Instrument`, таблицы и маршруты
  `/{category}/{symbol}/…` не меняются. Интервалы `moex`: `1`, `3`, `5`, `15`, `30`, `60`, `120`, `240`; `D`, `W`, `M`, `360` и
  `720` отклоняются.
- Аккаунт T-Invest: токен и номер брокерского счёта. Форма принимает токен, показывает счета токена и сохраняет
  выбранный; токен хранится зашифрованным, как секрет Bybit; один счёт сохраняется один раз. Категории аккаунта —
  `moex`. Тот же токен служит и для чтения рыночных данных, и (в следующих change) для торговли.
- Источник рыночных данных MOEX: все чтения без счёта (каталог, история, график, импорт, поиск) идут токеном аккаунта
  T-Invest, который адаптер берёт из хранилища сам; пока такого аккаунта нет, всё, что связано с `moex`, отвечает
  «данные T-Invest недоступны». Порты чтения не меняют форму.
- Граница покрытия серии свечей: у пары `(category, symbol, interval)` известно, до какого момента хранилище полно;
  свечи, которых нет до границы, не торговались (ночь, выходной, тихая минута), и догрузка графика и импорт
  запрашивают у биржи только то, что за границей. Ничего не синтезируется: ни закрытий, ни плоских свечей. Для Bybit
  поведение не меняется по существу — у него и так нет дыр.
- Адаптер T-Invest в `Infrastructure/Exchanges/TInvest` на официальном пакете `Tinkoff.InvestApi` (gRPC): один канал,
  лимитер запросов по группам методов на токен с учётом `x-ratelimit-reset`, без повторов записи, корневые
  сертификаты Минцифры в образе с отпечатками в настройках, метрики запросов по группам методов, как у Bybit REST.
- Каталог, поиск и правила акций: `FindInstrument`/`Shares` c фильтром TQBR, рубли, API-торговля разрешена, лот и шаг
  цены положительны; правила инструмента — шаг количества и минимум равны лоту, шаг цены `min_price_increment`,
  минимальная сумма `0`; флаг TradFi; флаг доступности шорта сохраняется для следующих change.
- История по окнам T-Invest (`1`–`3` мин — день, `5` мин — неделя, `15`–`30` мин — три недели, часовые — 90 дней) с
  источником `Exchange`, объём в лотах переводится в акции, оборот приближается как объём × типичная цена
  `(high + low + close) / 3`; незакрытая свеча не сохраняется.
- Боты и бэктесты на `moex`: бот создаётся с инструментом `moex` (символ проверяется у T-Invest), бэктест считает по
  сохранённым свечам с лотами через правила инструмента и комиссиями в рублях из `Backtests:DefaultFees:moex`. Запуск
  живого бота на `moex` отклоняется конфликтом «торговля на MOEX ещё не поддерживается» до следующего change.
- Веб-интерфейс: выбор биржи в форме аккаунта (Bybit — ключ и секрет, T-Invest — токен и счёт из списка), `moex` в
  выборе категории бота со своим списком интервалов, страница аккаунта T-Invest с номером счёта и балансом в рублях.
- Чек-лист чтений на реальном счёте владельца (только читающие методы, с его разрешения) фиксируется в `design.md`
  результатами: сетка свечей и дневные свечи, каталог, заголовки лимитов, статусы торгов за день, `GetOrderPrice`,
  единицы `GetPositions`.

Вне объёма: заявки и живая торговля, сканер и идеи на MOEX, сделки по идеям, дневные свечи `D` для `moex`, фонды,
облигации, FORTS, песочница T-Invest.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `exchange-accounts`: аккаунт T-Invest (токен + счёт, выбор счёта по токену, уникальность счёта, категория `moex`,
  баланс в рублях), биржа аккаунта в ответах; требования о Bybit остаются для аккаунтов Bybit.
- `exchange-account-interface`: форма нового аккаунта с выбором биржи и списком счетов токена; страница аккаунта T-Invest.
- `market-data-import`: категория `moex` с её интервалами, проверка символа у T-Invest, граница покрытия: импорт не
  запрашивает заново то, что уже внутри покрытия.
- `market-data-query`: чтение свечей `moex`; догрузка графика по границе покрытия, а не по сетке интервала.
- `instrument-search`: поиск акций MOEX по тикеру и названию; данные T-Invest недоступны без аккаунта.
- `backtest-runs`: базовые ставки комиссий `moex` из настроек; правила инструмента MOEX в бэктесте.
- `bot-management`: инструмент `moex` у бота, интервалы `moex`, проверка символа у T-Invest.
- `live-trading`: запуск бота на `moex` отклоняется до поддержки торговли.
- `bot-interface`: категория `moex` в форме бота, список интервалов по категории.
- `service-metrics`: счётчик запросов к T-Invest по группе методов и исходу.

## Impact

- `ProfitFox.Domain`: `MarketCategory.Moex`; `ExchangeAccount` получает вид учётных данных (`ExchangeAccountKind`: `Bybit`,
  `TInvest`) и номер счёта T-Invest; `ValueObjects/MarketData/SeriesCoverage` (граница покрытия серии); `ListedInstrument`
  получает флаг шорта; `IExchangeAccountRepository`, `ICandleRepository` (чтение и запись покрытия).
- `ProfitFox.Application`: `MarketDataCodes` (`moex`, интервалы по категории), `Ports/MarketData/IMarketDataSource` (маршрутизация
  портов чтения по категории), `Ports/ExchangeAccounts/IBrokerAccountDirectory` (счета токена), команда создания аккаунта по виду,
  `CandleReadThrough` и `RunNextCandleImport` по покрытию, `BacktestSettings` с `moex`, `BotRequests` с интервалами категории,
  `StartBot` с отказом для `moex`.
- `ProfitFox.Infrastructure`: `Exchanges/TInvest/*` (транспорт, лимитер, сертификаты, каталог, история, цены, счета,
  баланс, метрики), маршрутизаторы портов по категории, миграция (вид и счёт у `exchange_accounts`, ослабление
  ограничений на категории, таблица `candle_coverage`), регистрация.
- `ProfitFox.Presentation`: контракты аккаунта по виду, `POST /api/exchange-accounts/tinvest/accounts` (счета токена),
  категория `moex` в существующих маршрутах.
- `frontend/`: форма и страница аккаунта, форма бота, список интервалов по категории, тип категории.
- Новая внешняя зависимость: NuGet `Tinkoff.InvestApi` (gRPC, protobuf) — вводится этим дизайном. Образы получают
  сертификаты Russian Trusted Root CA и Sub CA.
- Тесты: in-process мок gRPC-клиентов T-Invest в `Tests.Shared` (по образцу `MockTInvestApi` из ProfitGraph), unit на
  лимитер, окна истории, перевод значений и лотов, покрытие; интеграционные на миграцию, репозитории и API аккаунта;
  frontend-тесты форм. Запросов к реальному T-Invest из тестов нет.
- Настройки: секция `TInvest` (адрес, отпечатки сертификатов, лимиты групп методов), `Backtests:DefaultFees:moex`.
