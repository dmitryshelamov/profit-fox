# market-data-query Specification

## Purpose

Чтение сохранённых свечей инструмента за период, чтобы проверять результат загрузки и отдавать историю потребителям —
бэктесту и интерфейсу.

## Requirements

### Requirement: Чтение свечей за период

Система SHALL возвращать сохранённые свечи по категории рынка, символу, интервалу и периоду `[from, to)` по open time,
упорядоченные по возрастанию open time. Каждая свеча содержит open time в UTC и значения open, high, low, close, volume,
turnover.

#### Scenario: Свечи есть

- **WHEN** в хранилище есть свечи `linear` / `BTCUSDT` / `60` с open time `00:00`, `01:00`, `02:00` за `2024-01-01`, и
  пользователь запрашивает период `[2024-01-01T01:00:00Z, 2024-01-01T03:00:00Z)`
- **THEN** система возвращает две свечи с open time `01:00` и `02:00` в этом порядке

#### Scenario: Свечей нет

- **WHEN** пользователь запрашивает период, за который свечи не загружались
- **THEN** система возвращает пустой список

### Requirement: Точные значения в ответе

Цены, объём и оборот MUST передаваться в ответе без потери точности — как десятичные строки, в точности равные
сохранённым значениям.

#### Scenario: Малый объём

- **WHEN** сохранена свеча с volume `0.000123`
- **THEN** в ответе volume равен строке `"0.000123"`

### Requirement: Ограничение размера ответа

Система SHALL возвращать не более `limit` свечей, начиная с самой ранней в периоде; `limit` по умолчанию 1000,
максимум 5000. Чтобы получить следующую порцию, клиент повторяет запрос с `from`, сдвинутым за open time последней
полученной свечи.

#### Scenario: Свечей больше лимита

- **WHEN** за период сохранено 1500 свечей и пользователь запрашивает их без `limit`
- **THEN** система возвращает первые 1000 свечей по возрастанию open time

#### Scenario: Лимит больше максимума

- **WHEN** пользователь передаёт `limit` = 10000
- **THEN** система отклоняет запрос с ошибкой валидации по параметру `limit`

### Requirement: Валидация параметров чтения

Система MUST отклонять запрос чтения с ошибкой валидации, если категория не `spot`, не `linear` и не `moex`, интервал не
входит в список интервалов категории, `from` не меньше `to`, обязательный параметр не указан или пуст, либо время
указано без смещения от UTC.

#### Scenario: Некорректный период

- **WHEN** пользователь запрашивает свечи, где `from` позже `to`
- **THEN** система отклоняет запрос с ошибкой валидации по периоду

#### Scenario: Время без смещения

- **WHEN** пользователь передаёт `to` = `2024-01-02T00:00:00` без `Z` и без смещения
- **THEN** система отклоняет запрос с ошибкой валидации по параметру `to`

#### Scenario: Интервал не из списка категории

- **WHEN** пользователь запрашивает свечи `moex` / `SBER` / `720`
- **THEN** система отклоняет запрос с ошибкой валидации по интервалу

### Requirement: Догрузка при чтении истории графика

Чтение истории для графика бота SHALL сохранять полученные с биржи свечи в то же хранилище, что и задачи загрузки, так
что их читают бэктесты и чтение свечей за период. Догружаться SHALL только часть периода за границей покрытия серии;
сохраняться MUST только закрытые свечи периода, которых в хранилище нет; свечи, которых нет у самой биржи, MUST NOT
придумываться, а граница покрытия SHALL сдвигаться до конца догруженной части.

#### Scenario: Бэктест после графика

- **WHEN** владелец открыл график бота `spot` / `BTCUSDT` / `60`, и история за последние 500 часов догрузилась с Bybit
- **THEN** чтение свечей за этот период возвращает эти свечи без задачи загрузки

#### Scenario: Пропуск в истории Bybit

- **WHEN** Bybit не возвращает свечу `03:00` за период, а свечи `02:00` и `04:00` возвращает
- **THEN** в хранилище есть свечи `02:00` и `04:00`, а свечи `03:00` нет

#### Scenario: Ночь MOEX не догружается

- **WHEN** график бота `moex` / `SBER` / `60` открыт за неделю, вся внутри покрытия, в которой ночи и выходные без свечей
- **THEN** график получает сохранённые свечи, и запрос к T-Invest не уходит

### Requirement: Догрузка — не задача загрузки

Догрузка истории графика MUST NOT создавать задачу загрузки и MUST NOT ждать очереди задач загрузки. Догрузка и задача
загрузки того же периода, идущие одновременно, MUST NOT создавать дубликаты свечей.

#### Scenario: Загрузка идёт

- **WHEN** Worker выполняет задачу загрузки `spot` / `ETHUSDT` / `D`, и владелец открывает график бота на `linear` /
  `BTCUSDT` / `60`
- **THEN** график получает свечи, не дожидаясь окончания задачи, и задач загрузки не прибавилось

#### Scenario: Тот же период одновременно

- **WHEN** задача загрузки и график бота одновременно догружают одни и те же часовые свечи `BTCUSDT`
- **THEN** в хранилище ровно одна свеча на каждый час периода
