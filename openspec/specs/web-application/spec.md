# web-application Specification

## Purpose
Как веб-приложение profit-fox доступно в браузере: интерфейс и API отвечают с одного адреса, прямые ссылки на экраны
открываются, а новая версия приложения подхватывается без ручной очистки кэша.

## Requirements

### Requirement: Один адрес для интерфейса и API

Веб-приложение SHALL отдавать интерфейс и HTTP API с одного адреса: запросы с путём `/api` SHALL доходить до API без
изменений, остальные — до интерфейса. Браузеру MUST NOT требоваться обращаться к другому адресу.

#### Scenario: Запрос к API через адрес приложения

- **WHEN** браузер запрашивает `/api/strategies` с адреса приложения
- **THEN** ответ — список стратегий от API

### Requirement: Прямые ссылки на экраны

Любой путь интерфейса, кроме `/api`, SHALL открывать приложение, которое показывает экран этого пути, в том числе при
прямом заходе и обновлении страницы.

#### Scenario: Обновление страницы редактора

- **WHEN** владелец обновляет страницу редактора стратегии по её адресу
- **THEN** открывается редактор той же стратегии, а не ошибка «не найдено»

### Requirement: Кэширование статики

Файлы сборки с хешем в имени SHALL кэшироваться браузером надолго, а страница приложения MUST NOT кэшироваться, чтобы
новая версия загружалась при следующем открытии.

#### Scenario: Новая версия

- **WHEN** выложена новая сборка интерфейса, и владелец заново открывает приложение
- **THEN** загружается новая сборка без ручной очистки кэша
