# market-data-import Specification

## Purpose

Загрузка исторических свечей инструментов Bybit по запросу пользователя в хранилище проекта, чтобы бэктест и другие
функции работали на реальной истории биржи.

## Requirements

### Requirement: Создание задачи загрузки

Система SHALL принимать запрос на загрузку свечей с параметрами: категория рынка (`spot` или `linear`), символ, интервал
Bybit (`1`, `3`, `5`, `15`, `30`, `60`, `120`, `240`, `360`, `720`, `D`, `W`, `M`), начало периода `from` и
необязательный конец периода `to`. На корректный запрос система SHALL создать задачу загрузки в статусе `Pending`,
вернуть её идентификатор и выполнять загрузку в фоне.

#### Scenario: Корректный запрос

- **WHEN** пользователь отправляет запрос на загрузку `linear` / `BTCUSDT` / `60` с `from` = `2024-01-01T00:00:00Z` и
  `to` = `2024-02-01T00:00:00Z`
- **THEN** система отвечает, что задача принята, и возвращает идентификатор задачи в статусе `Pending`

#### Scenario: Конец периода не указан

- **WHEN** пользователь отправляет запрос без `to`
- **THEN** система создаёт задачу, в которой конец периода равен моменту создания задачи

### Requirement: Валидация параметров загрузки

Система MUST отклонять запрос до создания задачи, если категория рынка не `spot` и не `linear`, интервал не входит в
список интервалов Bybit, `from` не меньше `to`, `from` позже текущего момента, обязательный параметр не указан или пуст,
либо время указано без смещения от UTC. Ответ MUST указывать, какой параметр некорректен.

#### Scenario: Неподдерживаемая категория

- **WHEN** пользователь отправляет запрос с категорией `inverse`
- **THEN** система отклоняет запрос с ошибкой валидации по параметру категории, задача не создаётся

#### Scenario: Неподдерживаемый интервал

- **WHEN** пользователь отправляет запрос с интервалом `2`
- **THEN** система отклоняет запрос с ошибкой валидации по параметру интервала, задача не создаётся

#### Scenario: Пустой период

- **WHEN** пользователь отправляет запрос, где `from` равен `to`
- **THEN** система отклоняет запрос с ошибкой валидации по периоду, задача не создаётся

#### Scenario: Время без смещения

- **WHEN** пользователь отправляет `from` = `2024-01-01T00:00:00` без `Z` и без смещения
- **THEN** система отклоняет запрос с ошибкой валидации по параметру `from`, задача не создаётся

#### Scenario: Пропущен обязательный параметр

- **WHEN** пользователь отправляет запрос без символа или с пустым символом
- **THEN** система отклоняет запрос с ошибкой валидации по параметру символа, задача не создаётся

### Requirement: Проверка символа на бирже

Перед созданием задачи система MUST проверить, что символ существует на Bybit в указанной категории. Неизвестный символ
MUST отклоняться с ошибкой валидации. Если Bybit недоступен для проверки, система MUST отклонить запрос с ошибкой
недоступности внешнего сервиса, не создавая задачу.

#### Scenario: Неизвестный символ

- **WHEN** пользователь отправляет запрос на `spot` / `NOSUCHUSDT`, которого Bybit не знает
- **THEN** система отклоняет запрос с ошибкой валидации по символу, задача не создаётся

#### Scenario: Bybit недоступен при проверке

- **WHEN** пользователь отправляет запрос, а Bybit не отвечает на проверку символа
- **THEN** система отклоняет запрос с ошибкой недоступности внешнего сервиса, задача не создаётся

### Requirement: Жизненный цикл задачи загрузки

Задача загрузки SHALL проходить статусы `Pending` → `Running` → `Succeeded` или `Failed`. Задача `Running` возвращается
в `Pending` при возобновлении после перезапуска сервиса, задача `Failed` — при ручном повторе. Пользователь SHALL иметь
возможность получить по идентификатору статус задачи, её параметры, число сохранённых свечей и, для `Failed`, причину
ошибки.

#### Scenario: Успешное завершение

- **WHEN** задача загрузила все свечи периода
- **THEN** её статус `Succeeded`, а число сохранённых свечей равно числу закрытых свечей периода, полученных с Bybit,
  которых не было в хранилище

#### Scenario: Ошибка биржи

- **WHEN** Bybit возвращает ошибку, которая не исчезает после повторных попыток
- **THEN** задача получает статус `Failed` с причиной ошибки; свечи, сохранённые до ошибки, остаются в хранилище

#### Scenario: Неизвестная задача

- **WHEN** пользователь запрашивает статус по несуществующему идентификатору
- **THEN** система отвечает, что задача не найдена

### Requirement: Прерванные задачи

При запуске сервиса, до приёма запросов, система MUST снова поставить в очередь все задачи в статусах `Pending` и
`Running` в порядке их создания; задача `Running` получает статус `Pending`. Возобновлённая задача загружает только
недостающие свечи. Задачу `Running`, которая прерывается перезапуском третий раз подряд, не сохранив между прерываниями ни
одной свечи, система MUST перевести в `Failed` с причиной «прервана перезапуском сервиса». Ручной повтор начинает отсчёт
прерываний заново.

#### Scenario: Перезапуск во время загрузки

- **WHEN** сервис перезапускается, пока задача в статусе `Running`
- **THEN** после запуска задача продолжается, загружает только недостающие свечи периода и завершается `Succeeded`

#### Scenario: Задача в очереди при перезапуске

- **WHEN** сервис перезапускается, пока задача в статусе `Pending`
- **THEN** после запуска задача выполняется, как если бы перезапуска не было

#### Scenario: Порядок возобновления

- **WHEN** сервис перезапускается, когда задача `A`, созданная раньше, в статусе `Pending`, а задача `B`, созданная
  позже, в статусе `Running`
- **THEN** после запуска сначала выполняется задача `A`, затем `B`

#### Scenario: Задача без продвижения

- **WHEN** задача `Running` прерывается перезапуском сервиса три раза подряд и ни разу не сохранила между ними ни одной
  свечи
- **THEN** после третьего запуска задача имеет статус `Failed` с причиной «прервана перезапуском сервиса» и не выполняется

#### Scenario: Задача с продвижением

- **WHEN** задача прерывается перезапуском сервиса больше трёх раз, но между каждыми двумя прерываниями сохраняет хотя бы
  одну свечу
- **THEN** после каждого запуска задача продолжается

#### Scenario: Ручной повтор сбрасывает отсчёт прерываний

- **WHEN** задача дважды прервана перезапуском без сохранённых свечей, затем упала с ошибкой биржи и повторена вручную, а
  после повтора снова прерывается перезапуском без сохранённых свечей
- **THEN** после этого запуска задача продолжается, а не переводится в `Failed`

### Requirement: Сохранение только закрытых свечей

Система MUST сохранять только закрытые свечи — те, у которых конец интервала (open time + длительность интервала; для
`W` — 7 суток, для `M` — начало следующего календарного месяца UTC) не позже момента загрузки. Незакрытую текущую свечу,
которую возвращает Bybit, система MUST отбрасывать.

#### Scenario: Период включает текущий момент

- **WHEN** задача загружает интервал `60` за период, конец которого — текущий момент `2024-03-10T12:30:00Z`
- **THEN** последняя сохранённая свеча имеет open time `2024-03-10T11:00:00Z`, а свеча с open time
  `2024-03-10T12:00:00Z` не сохраняется

### Requirement: Состав сохраняемой свечи

Система SHALL сохранять для каждой свечи инструмент, интервал, open time в UTC и значения open, high, low, close,
volume, turnover в точности как их вернул Bybit, без округления. В хранилище попадают свечи с open time в `[from, to)`.

#### Scenario: Точность значений

- **WHEN** Bybit возвращает свечу с close `"42123.45"` и volume `"0.000123"`
- **THEN** сохранённая свеча имеет close ровно `42123.45` и volume ровно `0.000123`

#### Scenario: Границы периода

- **WHEN** задача загружает интервал `60` за `[2024-01-01T00:00:00Z, 2024-01-01T03:00:00Z)`
- **THEN** сохраняются ровно три свечи с open time `00:00`, `01:00` и `02:00`

### Requirement: Идемпотентность загрузки

Свеча однозначно определяется инструментом, интервалом и open time. Повторная загрузка того же или пересекающегося
периода MUST NOT создавать дубликаты и MUST NOT изменять уже сохранённые свечи.

#### Scenario: Повторная загрузка

- **WHEN** пользователь дважды загружает `spot` / `ETHUSDT` / `D` за один и тот же период
- **THEN** в хранилище ровно по одной свече на каждый день периода, и значения свечей после второй загрузки те же, что
  после первой

#### Scenario: Один символ в разных категориях

- **WHEN** пользователь загружает `BTCUSDT` / `60` за один период в `spot` и в `linear`
- **THEN** хранилище содержит два независимых набора свечей, по одному на каждую категорию

### Requirement: Период до листинга

Если часть периода предшествует началу торгов инструментом, система SHALL сохранить свечи, которые есть на бирже, и
завершить задачу как `Succeeded`.

#### Scenario: Нет данных за весь период

- **WHEN** задача загружает период, целиком предшествующий листингу символа
- **THEN** задача имеет статус `Succeeded` и ноль сохранённых свечей

### Requirement: Соблюдение лимитов биржи

При ответе Bybit об превышении лимита запросов или временной ошибке сервера система MUST повторять запрос с нарастающей
паузой ограниченное число раз и только затем считать биржу недоступной. Если ошибки биржи идут подряд, система MAY
временно прекращать запросы к ней, пока пауза не истечёт; это тоже недоступность биржи. При недоступности биржи задача
повторяется по правилу автоматического повтора.

#### Scenario: Временное превышение лимита

- **WHEN** Bybit один раз отвечает превышением лимита, а следующий запрос выполняется успешно
- **THEN** задача завершается со статусом `Succeeded`, все свечи периода сохранены

#### Scenario: Биржа недоступна продолжительно

- **WHEN** запросы к Bybit подряд завершаются временными ошибками и защита от перегрузки срабатывает
- **THEN** задачи не обращаются к Bybit до окончания паузы защиты и повторяются по правилу автоматического повтора, а
  после исчерпания всех повторов получают статус `Failed` с причиной ошибки

### Requirement: Загрузка только недостающих свечей

Задача загрузки MUST запрашивать у биржи только те диапазоны периода `[from, to)`, для которых в хранилище нет свечей
инструмента и интервала. Диапазоны, уже покрытые сохранёнными свечами, система MUST NOT запрашивать у биржи, независимо
от того, какая задача их сохранила. Число сохранённых свечей задачи — это число свечей, которые сохранила эта задача.

#### Scenario: Период уже загружен целиком

- **WHEN** в хранилище есть все свечи `linear` / `BTCUSDT` / `60` с open time `00:00` … `23:00` за `2024-01-01`, и
  пользователь создаёт задачу на `[2024-01-01T00:00:00Z, 2024-01-02T00:00:00Z)`
- **THEN** задача получает статус `Succeeded` с нулём сохранённых свечей и не обращается к Bybit за свечами

#### Scenario: Незакрытая свеча в конце периода

- **WHEN** в хранилище есть все закрытые свечи `60` периода, конец которого — текущий момент `2024-03-10T12:30:00Z`, а
  последняя сохранённая свеча имеет open time `2024-03-10T11:00:00Z`
- **THEN** задача запрашивает у Bybit только диапазон `[2024-03-10T12:00:00Z, 2024-03-10T12:30:00Z)`, не сохраняет
  незакрытую свечу и получает статус `Succeeded` с нулём сохранённых свечей

#### Scenario: Период загружен частично другой задачей

- **WHEN** в хранилище есть свечи `linear` / `BTCUSDT` / `60` за январь 2024, и пользователь создаёт задачу на
  `[2023-12-01T00:00:00Z, 2024-03-01T00:00:00Z)`
- **THEN** задача запрашивает у Bybit только декабрь 2023 и февраль 2024, сохраняет все их закрытые свечи, а число
  сохранённых свечей равно числу свечей декабря и февраля

#### Scenario: Пропуски внутри периода

- **WHEN** в хранилище за период задачи есть свечи с пропусками внутри
- **THEN** задача запрашивает у Bybit только пропущенные диапазоны, и после её завершения хранилище содержит все закрытые
  свечи периода, которые есть на Bybit

#### Scenario: Календарный интервал

- **WHEN** в хранилище есть месячные свечи `M` с open time `2024-01-01T00:00:00Z` и `2024-03-01T00:00:00Z`, и задача
  загружает `[2024-01-01T00:00:00Z, 2024-04-01T00:00:00Z)`
- **THEN** задача запрашивает у Bybit только свечу с open time `2024-02-01T00:00:00Z`

### Requirement: Автоматический повтор при недоступности биржи

Если биржа недоступна — повторы запроса при превышении лимита, ошибке сервера, таймауте или отсутствии соединения
исчерпаны, либо запросы к бирже временно прекращены защитой от перегрузки, — система MUST повторить выполнение задачи
после паузы 1, 5, 15, 30 и 60 с, каждый раз загружая только недостающие свечи. После страницы хотя бы с одной сохранённой
свечой паузы начинаются заново. Задача остаётся `Running`. Остальные ошибки MUST сразу переводить задачу в `Failed`.

#### Scenario: Биржа восстановилась в пределах пауз

- **WHEN** во время задачи Bybit недоступен 60 с — дольше повторов одного запроса, — а затем снова отвечает
- **THEN** задача завершается со статусом `Succeeded`, все свечи периода сохранены, а свечи, сохранённые до сбоя, повторно
  у Bybit не запрашиваются

#### Scenario: Разрозненные сбои

- **WHEN** за время задачи Bybit становится недоступен больше пяти раз, и между каждыми двумя сбоями задача сохраняет
  хотя бы одну свечу
- **THEN** задача завершается со статусом `Succeeded`

#### Scenario: Биржа недоступна дольше всех пауз

- **WHEN** Bybit недоступен на протяжении всех пяти повторов задачи
- **THEN** задача получает статус `Failed` с причиной ошибки; свечи, сохранённые до ошибки, остаются в хранилище

#### Scenario: Окончательный отказ биржи

- **WHEN** Bybit отвечает ошибкой, которая не относится к недоступности биржи
- **THEN** задача сразу получает статус `Failed` с причиной ошибки, без повторов

### Requirement: Ручной повтор задачи

Пользователь SHALL иметь возможность повторить задачу в статусе `Failed` по её идентификатору. Задача с тем же
идентификатором и параметрами снова получает статус `Pending`, теряет причину ошибки и время завершения и выполняется в
фоне, загружая только недостающие свечи. Повтор задачи в другом статусе MUST отклоняться как конфликт без изменения
задачи; повтор несуществующей задачи — как «не найдено».

#### Scenario: Повтор упавшей задачи

- **WHEN** пользователь повторяет задачу в статусе `Failed`, а Bybit доступен
- **THEN** система отвечает, что задача принята, задача снова выполняется и завершается `Succeeded`, а свечи, сохранённые
  до сбоя, повторно у Bybit не запрашиваются

#### Scenario: Повтор незавершённой или успешной задачи

- **WHEN** пользователь повторяет задачу в статусе `Pending`, `Running` или `Succeeded`
- **THEN** система отклоняет запрос как конфликт, задача не меняется

#### Scenario: Повтор неизвестной задачи

- **WHEN** пользователь повторяет задачу по несуществующему идентификатору
- **THEN** система отвечает, что задача не найдена
