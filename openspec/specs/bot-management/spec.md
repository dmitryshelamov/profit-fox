# bot-management Specification

## Purpose
Бот — стратегия, настроенная для торговли: значения параметров, инструмент, интервал и баланс бота. На боте запускаются
бэктесты, позже — реальная торговля.

## Requirements

### Requirement: Создание бота

Система SHALL принимать бота из имени, идентификатора стратегии, значений параметров стратегии, инструмента (категория
рынка и символ), интервала и баланса бота в валюте котировки. Валидного бота система SHALL сохранить и вернуть его
идентификатор; бота с ошибками проверки MUST отклонить со всеми ошибками, ничего не сохраняя.

#### Scenario: Валидный бот

- **WHEN** пользователь создаёт бота на стратегии EMA с `fast` = `10`, инструментом `spot` / `BTCUSDT`, интервалом `60`
  и балансом `1000`
- **THEN** система сохраняет бота и возвращает его идентификатор

#### Scenario: Пустое имя

- **WHEN** пользователь создаёт бота с пустым именем
- **THEN** система отклоняет запрос с ошибкой по имени

### Requirement: Проверка бота

Бот MUST отклоняться, если: стратегии нет; значение задано для параметра, которого стратегия не объявляет, или нарушает
тип, минимум, максимум или признак целого; категория инструмента не поддерживается направлением стратегии; интервал не
из списка интервалов Bybit; баланс не больше нуля; символа нет на бирже в этой категории.

#### Scenario: Значение вне ограничений

- **WHEN** пользователь создаёт бота на стратегии EMA со значением `fast` = `1` при минимуме `2`
- **THEN** система отклоняет запрос с ошибкой по параметру `fast`

#### Scenario: Шорт на споте

- **WHEN** пользователь создаёт бота на стратегии EMA Short с инструментом категории `spot`
- **THEN** система отклоняет запрос с ошибкой по категории инструмента

#### Scenario: Неизвестная стратегия

- **WHEN** пользователь создаёт бота со стратегией, которой нет
- **THEN** система отклоняет запрос с ошибкой по стратегии

#### Scenario: Символа нет на бирже

- **WHEN** пользователь создаёт бота с символом `NOPEUSDT`, которого Bybit не знает в категории `spot`
- **THEN** система отклоняет запрос с ошибкой по символу

#### Scenario: Нулевой баланс

- **WHEN** пользователь создаёт бота с балансом `0`
- **THEN** система отклоняет запрос с ошибкой по балансу

### Requirement: Значения параметров бота

Бот SHALL хранить только заданные ему значения параметров. Для параметра без значения у бота SHALL использоваться
значение по умолчанию последней версии стратегии.

#### Scenario: Значение по умолчанию

- **WHEN** у бота на стратегии EMA не задан `slow`, а в стратегии значение `slow` по умолчанию изменили с `26` на `30`
- **THEN** бот использует `slow` = `30`

### Requirement: Чтение ботов

Система SHALL возвращать бота по идентификатору: имя, стратегию, заданные значения параметров, инструмент, интервал,
баланс и аккаунт биржи, если он задан: идентификатор и имя. Список ботов SHALL содержать идентификатор, имя,
стратегию, инструмент, интервал, баланс и аккаунт каждого в том же виде, а также его последний бэктест: идентификатор,
статус и прогресс; у бота без бэктестов последнего бэктеста нет. Неизвестный идентификатор SHALL давать ответ «не
найдено».

#### Scenario: Чтение сохранённого бота

- **WHEN** пользователь запрашивает сохранённого бота
- **THEN** система возвращает те же значения параметров, инструмент, интервал и баланс, что были сохранены

#### Scenario: Неизвестный бот

- **WHEN** пользователь запрашивает бота по идентификатору, которого нет
- **THEN** система отвечает «не найдено»

#### Scenario: Последний бэктест в списке

- **WHEN** у бота созданы бэктесты `A`, затем `B`, и `B` посчитал 5 комбинаций из 12
- **THEN** список ботов возвращает у этого бота баланс и последний бэктест `B` в статусе `Running` с прогрессом `5` из
  `12`

#### Scenario: Бот без бэктестов в списке

- **WHEN** у бота нет бэктестов
- **THEN** список ботов возвращает его баланс и не возвращает последний бэктест

#### Scenario: Аккаунт в списке

- **WHEN** у бота аккаунт «Основной»
- **THEN** список ботов и чтение бота возвращают у него аккаунт «Основной»

### Requirement: Изменение бота

Система SHALL заменять имя, значения параметров, инструмент, интервал, баланс и аккаунт бота новыми валидными
значениями по тем же правилам, что при создании. Стратегию бота изменить MUST быть нельзя. Изменение с ошибками MUST
отклоняться, и бот MUST оставаться прежним.

#### Scenario: Смена инструмента

- **WHEN** пользователь меняет у бота инструмент с `spot` / `BTCUSDT` на `spot` / `ETHUSDT`
- **THEN** чтение бота возвращает `ETHUSDT`

#### Scenario: Изменение с ошибкой

- **WHEN** пользователь меняет у бота значение `fast` на `1` при минимуме `2`
- **THEN** система отклоняет изменение с ошибкой по `fast`, и бот остаётся прежним

#### Scenario: Смена категории при аккаунте только для спота

- **WHEN** у бота аккаунт, ключ которого торгует только на споте, и пользователь меняет инструмент на `linear` /
  `BTCUSDT`
- **THEN** система отклоняет изменение с ошибкой по аккаунту, и бот остаётся прежним

### Requirement: Удаление бота

Система SHALL удалять остановленного бота без открытой позиции по идентификатору вместе со всеми его бэктестами, их
результатами и позициями бота. Бота в другом статусе или с открытой позицией MUST NOT удаляться: система SHALL отвечать
конфликтом с причиной.

#### Scenario: Бот с бэктестами

- **WHEN** у остановленного бота без позиции два бэктеста, и пользователь удаляет бота
- **THEN** чтение бота и обоих бэктестов отвечает «не найдено»

#### Scenario: Запущенный бот

- **WHEN** пользователь удаляет запущенного бота
- **THEN** система отвечает конфликтом, и бот продолжает работу

#### Scenario: Остановленный бот с позицией

- **WHEN** у остановленного бота открытая позиция `0.5`, и пользователь удаляет бота
- **THEN** система отвечает конфликтом с причиной «у бота открытая позиция», и бот остаётся

### Requirement: Бот всегда валиден

В любой момент каждый сохранённый бот SHALL проходить проверку против последней версии своей стратегии. Одновременное
изменение бота и его стратегии MUST NOT приводить к сохранённому невалидному боту.

#### Scenario: Конкурирующие сохранения

- **WHEN** одно сохранение задаёт боту значение параметра `fast`, а другое одновременно удаляет `fast` из стратегии
- **THEN** сохраняется не больше одного из изменений, а второе отклоняется, и бот остаётся валидным

### Requirement: Аккаунт бота

Бот SHALL принимать необязательный идентификатор аккаунта биржи при создании и изменении; без него бот остаётся без
аккаунта. Аккаунт бота SHALL меняться и сниматься изменением бота. Торговать бот SHALL только с аккаунтом.

#### Scenario: Бот с аккаунтом

- **WHEN** пользователь создаёт бота с инструментом `spot` / `BTCUSDT` и аккаунтом, ключ которого торгует на споте
- **THEN** система сохраняет бота, и чтение бота возвращает этот аккаунт

#### Scenario: Снять аккаунт

- **WHEN** пользователь изменяет бота с аккаунтом без идентификатора аккаунта
- **THEN** чтение бота возвращает бота без аккаунта

#### Scenario: Бот без аккаунта

- **WHEN** пользователь создаёт бота без идентификатора аккаунта
- **THEN** система сохраняет бота без аккаунта

### Requirement: Проверка аккаунта бота

Бот MUST отклоняться с ошибкой по аккаунту, если аккаунта нет или если ключ аккаунта не торгует в категории инструмента
бота. Удаление аккаунта одновременно с сохранением бота MUST NOT приводить к сохранённому боту с несуществующим
аккаунтом.

#### Scenario: Неизвестный аккаунт

- **WHEN** пользователь создаёт бота с идентификатором аккаунта, которого нет
- **THEN** система отклоняет запрос с ошибкой по аккаунту

#### Scenario: Ключ не торгует в категории бота

- **WHEN** пользователь создаёт бота с инструментом `linear` / `BTCUSDT` и аккаунтом, ключ которого торгует только на
  споте
- **THEN** система отклоняет запрос с ошибкой по аккаунту

### Requirement: Изменение работающего бота

Изменение бота в статусе «запущен», «пауза» или «останавливается» MUST отклоняться конфликтом, и бот MUST оставаться
прежним.

#### Scenario: Правка запущенного бота

- **WHEN** пользователь меняет баланс запущенного бота
- **THEN** система отвечает конфликтом, и баланс прежний

### Requirement: Аккаунт и инструмент при открытой позиции

Изменение аккаунта, инструмента или интервала у бота с открытой позицией MUST отклоняться с ошибкой по этому полю.
Имя, значения параметров и баланс такого остановленного бота SHALL меняться.

#### Scenario: Смена инструмента с позицией

- **WHEN** у остановленного бота открытая позиция на `spot` / `BTCUSDT`, и пользователь меняет инструмент на `ETHUSDT`
- **THEN** система отклоняет изменение с ошибкой по инструменту

#### Scenario: Смена баланса с позицией

- **WHEN** у остановленного бота открытая позиция, и пользователь меняет баланс с `1000` на `1500`
- **THEN** чтение бота возвращает баланс `1500`
