# exchange-accounts Specification

## Purpose
Аккаунт биржи — ключи Bybit, от имени которых бот будет торговать: их хранение в зашифрованном виде, проверка у
биржи, чтение, переименование, удаление и баланс аккаунта.

## Requirements

### Requirement: Категории торговли аккаунта

Система SHALL сохранять категории рынка, в которых аккаунт может торговать: для аккаунта Bybit — UID и категории
(`spot`, `linear`) по сведениям Bybit на момент создания; для аккаунта T-Invest — категория `moex`.

#### Scenario: Ключ только для спота

- **WHEN** пользователь создаёт аккаунт с ключом, у которого есть право на торговлю только на споте
- **THEN** чтение аккаунта возвращает категории `spot` без `linear`

#### Scenario: Аккаунт T-Invest

- **WHEN** пользователь создаёт аккаунт T-Invest
- **THEN** чтение аккаунта возвращает категорию `moex`

### Requirement: Bybit недоступен

Если Bybit не отвечает при проверке ключа или чтении баланса, система SHALL отвечать «биржа недоступна» и MUST NOT
сохранять аккаунт.

#### Scenario: Bybit не отвечает при создании

- **WHEN** пользователь создаёт аккаунт, а Bybit не отвечает
- **THEN** система отвечает «биржа недоступна», и аккаунт не сохраняется

### Requirement: Secret не выдаётся

Система MUST NOT возвращать secret Bybit или токен T-Invest ни в одном ответе и MUST NOT писать их в журнал. В базе
secret и токен SHALL храниться только в зашифрованном виде. API key Bybit и номер счёта T-Invest SHALL возвращаться
целиком.

#### Scenario: Чтение аккаунта без secret

- **WHEN** пользователь читает сохранённый аккаунт
- **THEN** ответ содержит API key целиком и не содержит secret ни в каком виде

#### Scenario: Secret в базе зашифрован

- **WHEN** аккаунт сохранён
- **THEN** в строке аккаунта в базе нет значения secret в открытом виде

#### Scenario: Токен в базе зашифрован

- **WHEN** аккаунт T-Invest сохранён
- **THEN** в строке аккаунта в базе нет значения токена в открытом виде, а чтение аккаунта возвращает номер счёта и не
  возвращает токен

### Requirement: Мастер-ключ

Secret SHALL шифроваться мастер-ключом из настроек сервиса. Мастер-ключ по умолчанию SHALL задаваться только для
окружений разработки и тестов. В остальных окружениях API без мастер-ключа или с мастер-ключом неверной длины MUST NOT
стартовать и SHALL сообщить причину в журнал.

#### Scenario: Прод без мастер-ключа

- **WHEN** API запускается в окружении `Production` без мастер-ключа в настройках
- **THEN** API не стартует и пишет в журнал, что мастер-ключ не задан

#### Scenario: Разработка без переопределения

- **WHEN** API запускается в окружении `Development` без мастер-ключа в переменных окружения
- **THEN** API стартует с мастер-ключом разработки

### Requirement: Чтение аккаунтов

Система SHALL возвращать аккаунт по идентификатору: биржу, имя, категории торговли, время создания, привязанных к нему
ботов (идентификатор и имя) и поля биржи: для Bybit — API key и UID, для T-Invest — номер счёта. Список аккаунтов SHALL
содержать те же поля каждого аккаунта, кроме ботов. Неизвестный идентификатор SHALL давать ответ «не найдено».

#### Scenario: Чтение сохранённого аккаунта

- **WHEN** пользователь запрашивает сохранённый аккаунт, к которому привязан бот «BTC EMA час»
- **THEN** система возвращает его имя, API key, UID, категории торговли и бота «BTC EMA час»

#### Scenario: Неизвестный аккаунт

- **WHEN** пользователь запрашивает аккаунт по идентификатору, которого нет
- **THEN** система отвечает «не найдено»

### Requirement: Переименование аккаунта

Система SHALL менять имя аккаунта; биржа, ключи, UID, номер счёта и категории торговли MUST оставаться прежними. Пустое
имя MUST отклоняться с ошибкой по имени.

#### Scenario: Новое имя

- **WHEN** пользователь переименовывает аккаунт «Основной» в «Торговый»
- **THEN** чтение аккаунта возвращает имя «Торговый» и тот же API key

### Requirement: Удаление аккаунта

Система SHALL удалять аккаунт по идентификатору вместе с его ключами. Аккаунт, к которому привязан хотя бы один бот, MUST
NOT удаляться: система SHALL отвечать конфликтом с именами этих ботов.

#### Scenario: Аккаунт без ботов

- **WHEN** пользователь удаляет аккаунт, к которому не привязан ни один бот
- **THEN** чтение аккаунта отвечает «не найдено»

#### Scenario: Аккаунт с ботом

- **WHEN** к аккаунту привязан бот «BTC EMA час», и пользователь удаляет аккаунт
- **THEN** система отвечает конфликтом с именем «BTC EMA час», и аккаунт остаётся

### Requirement: Баланс аккаунта

Система SHALL по запросу читать с Bybit баланс единого торгового аккаунта: общий капитал в USD и по каждой монете с
ненулевым балансом её баланс и стоимость в USD. Баланс MUST NOT храниться. Если Bybit больше не принимает ключ, система
SHALL отвечать конфликтом с причиной.

#### Scenario: Баланс аккаунта

- **WHEN** на аккаунте `1000` USDT и `0.01` BTC, и пользователь запрашивает баланс
- **THEN** система возвращает строки `USDT` и `BTC` с их балансами и стоимостью в USD и общий капитал

#### Scenario: Ключ отозван

- **WHEN** ключ аккаунта удалили на Bybit, и пользователь запрашивает баланс
- **THEN** система отвечает конфликтом с причиной «Bybit не принял ключ»

### Requirement: Создание аккаунта основной сети

Система SHALL принимать аккаунт Bybit из имени, API key и secret основной сети Bybit. Валидный аккаунт, ключ которого
прошёл проверку у Bybit, система SHALL сохранить и вернуть его идентификатор. Аккаунт с ошибками MUST отклоняться со
всеми ошибками, ничего не сохраняя. Пустое имя, пустой API key или пустой secret MUST быть ошибками по своим полям; ключ
у Bybit проверяется, только когда всё остальное валидно. Аккаунт без биржи SHALL считаться аккаунтом Bybit.

#### Scenario: Валидный аккаунт

- **WHEN** пользователь создаёт аккаунт «Основной» с ключом, который Bybit принимает, у которого есть право на торговлю
  и нет права на вывод средств
- **THEN** система сохраняет аккаунт и возвращает его идентификатор

#### Scenario: Пустое имя

- **WHEN** пользователь создаёт аккаунт с пустым именем
- **THEN** система отклоняет запрос с ошибкой по имени и не обращается к Bybit

### Requirement: Проверка ключа в основной сети Bybit

При создании аккаунта система SHALL запросить у основной сети Bybit сведения о ключе. Ключ MUST отклоняться с ошибкой по
API key, если Bybit его не принимает, если ключ только для чтения, если у него нет права на торговлю ни на споте, ни в
`linear`, если у него есть право на вывод средств или если он не от единого торгового аккаунта (UTA).

#### Scenario: Bybit не принимает ключ

- **WHEN** пользователь создаёт аккаунт с ключом, который Bybit отклоняет как неверный
- **THEN** система отклоняет запрос с ошибкой по API key, и аккаунт не сохраняется

#### Scenario: Ключ только для чтения

- **WHEN** пользователь создаёт аккаунт с ключом только для чтения
- **THEN** система отклоняет запрос с ошибкой по API key

#### Scenario: Ключ с правом на вывод средств

- **WHEN** пользователь создаёт аккаунт с ключом, у которого есть право `Withdraw`
- **THEN** система отклоняет запрос с ошибкой по API key

#### Scenario: Ключ не единого торгового аккаунта

- **WHEN** пользователь создаёт аккаунт с ключом классического аккаунта Bybit
- **THEN** система отклоняет запрос с ошибкой по API key

### Requirement: UID Bybit уникален

Аккаунт с тем же UID Bybit, что у сохранённого аккаунта, MUST отклоняться с ошибкой по API key.

#### Scenario: Повторный ключ того же аккаунта

- **WHEN** аккаунт с UID `100` уже сохранён, и пользователь создаёт аккаунт с другим ключом того же UID
- **THEN** система отклоняет запрос с ошибкой по API key

### Requirement: Биржа аккаунта

Аккаунт SHALL принадлежать одной бирже: `bybit` (ключ и секрет единого торгового аккаунта) или `tinvest` (токен Invest
API и номер брокерского счёта). Биржа SHALL возвращаться в каждом чтении аккаунта и MUST NOT меняться после создания.

#### Scenario: Биржа в ответе

- **WHEN** пользователь читает аккаунт, созданный с токеном T-Invest
- **THEN** ответ содержит биржу `tinvest`, номер счёта и не содержит API key и UID Bybit

### Requirement: Счета токена T-Invest

Система SHALL по токену T-Invest возвращать счета, которые он открывает: номер, название, тип, статус и доступ токена,
и для каждого — можно ли его сохранить. Сохранить SHALL можно только открытый брокерский счёт или ИИС с полным
доступом токена. Токен MUST NOT сохраняться и MUST NOT писаться в журнал при этом чтении. Токен, который T-Invest не
принимает, SHALL давать ошибку по токену.

#### Scenario: Два счёта токена

- **WHEN** пользователь запрашивает счета токена, у которого брокерский счёт с полным доступом и закрытый ИИС
- **THEN** ответ содержит оба счёта, брокерский отмечен как доступный, ИИС — как недоступный с причиной «закрыт»

#### Scenario: Токен отклонён

- **WHEN** пользователь запрашивает счета токена, который T-Invest не принимает
- **THEN** система отвечает ошибкой по токену

### Requirement: Создание аккаунта T-Invest

Система SHALL принимать аккаунт T-Invest из имени, токена и номера счёта. Перед сохранением система SHALL снова
прочитать счета токена и принять только открытый счёт с полным доступом, иначе отклонить с ошибкой по счёту. Токен
SHALL храниться только зашифрованным; категория торговли такого аккаунта — `moex`. Пустое имя, пустой токен или пустой
номер счёта MUST быть ошибками по своим полям; счета у T-Invest читаются, только когда всё остальное валидно.

#### Scenario: Валидный аккаунт T-Invest

- **WHEN** пользователь создаёт аккаунт «Брокерский» с токеном, который T-Invest принимает, и номером открытого счёта с
  полным доступом
- **THEN** система сохраняет аккаунт с категорией `moex` и возвращает его идентификатор

#### Scenario: Доступ отозван между выбором и сохранением

- **WHEN** пользователь выбрал счёт из списка, а при сохранении T-Invest сообщает, что у токена к нему только чтение
- **THEN** система отклоняет запрос с ошибкой по счёту и ничего не сохраняет

#### Scenario: T-Invest не отвечает при создании

- **WHEN** пользователь создаёт аккаунт T-Invest, а T-Invest не отвечает
- **THEN** система отвечает «биржа недоступна», и аккаунт не сохраняется

### Requirement: Счёт T-Invest уникален

Аккаунт с тем же номером счёта T-Invest, что у сохранённого аккаунта, MUST отклоняться с ошибкой по счёту, даже если
токен другой.

#### Scenario: Второй токен того же счёта

- **WHEN** аккаунт со счётом `2000000001` уже сохранён, и пользователь создаёт аккаунт с другим токеном того же счёта
- **THEN** система отклоняет запрос с ошибкой по счёту

### Requirement: Аккаунт T-Invest как источник данных MOEX

Рыночные данные `moex` — каталог акций, история свечей, поиск инструментов, правила инструмента и цены — система SHALL
читать токеном сохранённого аккаунта T-Invest. Пока такого аккаунта нет, каждое чтение данных `moex` SHALL отвечать
«данные T-Invest недоступны», ничего не запрашивая. Удалённый аккаунт MUST перестать использоваться для чтений не
позже чем через пять минут.

#### Scenario: Нет аккаунта T-Invest

- **WHEN** аккаунтов T-Invest нет, и пользователь ищет инструмент в категории `moex`
- **THEN** система отвечает «данные T-Invest недоступны», и запрос к T-Invest не уходит

#### Scenario: Аккаунт появился

- **WHEN** пользователь сохранил аккаунт T-Invest и ищет `SBER` в категории `moex`
- **THEN** система возвращает акцию `SBER`, прочитанную токеном этого аккаунта

### Requirement: Баланс аккаунта T-Invest

Система SHALL по запросу читать с T-Invest портфель счёта: общую стоимость в рублях, рубли на счёте и по каждой бумаге с
ненулевой позицией её тикер, количество в штуках и стоимость в рублях. Баланс MUST NOT храниться. Если T-Invest больше
не принимает токен или доступ к счёту отозван, система SHALL отвечать конфликтом с причиной.

#### Scenario: Портфель со стоимостью

- **WHEN** на счёте `50 000` ₽ и `10` акций `SBER` по `300` ₽, и пользователь запрашивает баланс
- **THEN** система возвращает строку `RUB` на `50 000`, строку `SBER` на `10` штук стоимостью `3 000` и общую стоимость
  `53 000` ₽
