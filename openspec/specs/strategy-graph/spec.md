# strategy-graph Specification

## Purpose
Формат составного узла и сигнала в JSON и правила его корректности, чтобы сигнал можно было записать в файл гипотезы,
проверить до расчёта и однозначно исполнить на стенде и в боте.

## Requirements

### Requirement: Версия формата

Определение составного узла SHALL содержать `formatVersion`. Чтение SHALL принимать только версию `1` и MUST отклонять
определение с другой или отсутствующей версией.

#### Scenario: Неизвестная версия формата

- **WHEN** читается определение с `formatVersion` = `2`
- **THEN** чтение возвращает ошибку по `formatVersion`, и определения нет

#### Scenario: Версия не указана

- **WHEN** читается определение без `formatVersion`
- **THEN** чтение возвращает ошибку по `formatVersion`

### Requirement: Поля определения

Определение SHALL состоять из полей `formatVersion`, `outputs`, `nodes` и `wires`; у узла — `id`, `kind` и
необязательные `settings` и `inputs`; у провода — `from` и `to`. Неизвестное поле на любом уровне и текст, который не
является JSON, MUST давать ошибку, а не пропускаться.

#### Scenario: Неизвестное поле узла

- **WHEN** у узла `now` есть поле `layout`
- **THEN** чтение возвращает ошибку неизвестного поля `layout` узла `now`

#### Scenario: Не JSON

- **WHEN** читается текст, который не является JSON
- **THEN** чтение возвращает ошибку разбора, и определения нет

### Requirement: Узлы графа

Граф SHALL состоять из узлов с идентификатором, уникальным в пределах графа, и видом узла из библиотеки. Идентификатор
SHALL начинаться с латинской буквы и содержать только латинские буквы, цифры и `-`. Повторяющийся или недопустимый
идентификатор и неизвестный вид MUST делать граф невалидным.

#### Scenario: Повторяющийся идентификатор узла

- **WHEN** в графе два узла с идентификатором `rate`
- **THEN** проверка сообщает об ошибке повторяющегося идентификатора `rate`

#### Scenario: Неизвестный вид узла

- **WHEN** в графе есть узел вида `ema`, которого нет в библиотеке
- **THEN** проверка сообщает об ошибке неизвестного вида узла с идентификатором этого узла

#### Scenario: Точка в идентификаторе

- **WHEN** в графе есть узел с идентификатором `a.b`
- **THEN** проверка сообщает об ошибке недопустимого идентификатора `a.b`

### Requirement: Настройки узла

Узел SHALL принимать только настройки, объявленные его видом, и только с допустимыми значениями. Настройка, у которой
вид не задаёт значения по умолчанию, обязательна. Неизвестная настройка, недопустимое значение и пропущенная
обязательная настройка MUST делать граф невалидным.

#### Scenario: Пропущенная операция сравнения

- **WHEN** у узла `compare` нет настройки `operation`
- **THEN** проверка сообщает об ошибке незаданной настройки `operation` этого узла

#### Scenario: Недопустимая операция

- **WHEN** у узла `compare` настройка `operation` = `between`
- **THEN** проверка сообщает об ошибке значения настройки `operation` с перечнем допустимых значений

### Requirement: Типы пинов

Каждый вход и выход узла SHALL иметь один тип: число или логическое значение. Числа SHALL представляться десятичными
значениями без потери точности.

#### Scenario: Точность числа

- **WHEN** на неподключённом входе задано значение `0.0005`
- **THEN** узел получает ровно `0.0005`, а не ближайшее двоичное число

### Requirement: Провода данных

Провод SHALL соединять выход одного узла со входом другого узла того же типа; конец провода записывается как
`узел.пин`. Вход SHALL принимать не больше одного провода. Провод к несуществующему узлу или пину, провод между пинами
разных типов и второй провод на вход MUST делать граф невалидным.

#### Scenario: Несовместимые типы

- **WHEN** логический выход `result` узла `first` соединён с числовым входом `a` узла `now`
- **THEN** проверка сообщает об ошибке несовместимых типов с указанием обоих пинов

#### Scenario: Два провода на один вход

- **WHEN** на вход `a` узла `first` приходят два провода
- **THEN** проверка сообщает об ошибке по входу `a` узла `first`

#### Scenario: Провод к несуществующему пину

- **WHEN** провод ведёт к входу `c` узла `compare`, у которого нет входа `c`
- **THEN** проверка сообщает об ошибке неизвестного пина `c`

### Requirement: Значение неподключённого входа

Вход без провода SHALL брать значение, заданное у узла в `inputs`, того же типа, что и вход. Вход без провода и без
значения, значение у входа с проводом, значение другого типа и значение неизвестного входа MUST делать граф невалидным.

#### Scenario: Порог на входе

- **WHEN** вход `b` узла `compare` не подключён и у узла задано `inputs` = `{ "b": 0.0005 }`
- **THEN** граф валиден, и узел сравнивает со значением `0.0005`

#### Scenario: Вход без провода и без значения

- **WHEN** вход `b` узла `compare` не подключён и значения у него нет
- **THEN** проверка сообщает об ошибке незаданного входа `b`

#### Scenario: Значение у подключённого входа

- **WHEN** вход `a` узла `compare` подключён проводом и у узла задано значение `a`
- **THEN** проверка сообщает об ошибке по входу `a`: значение и провод одновременно

### Requirement: Граф без циклов

Провода данных MUST NOT образовывать цикл. Граф, в котором значение узла зависит от самого себя через провода, MUST
быть невалидным.

#### Scenario: Цикл через два узла

- **WHEN** выход узла `x` подключён ко входу `y`, а выход `y` — ко входу `x`
- **THEN** проверка сообщает об ошибке цикла с перечислением узлов цикла

### Requirement: Выходы составного узла

Составной узел SHALL объявлять выходы с именами и типами, уникальными по имени. Внутри графа SHALL быть ровно один узел
вида `outputs`, входы которого — объявленные выходы. Объявленный выход без провода внутри MUST делать составной узел
невалидным.

#### Scenario: Выход без источника

- **WHEN** составной узел объявляет выход `entry`, а к входу `entry` узла `outputs` не подключён провод
- **THEN** проверка сообщает об ошибке неподключённого выхода `entry`

#### Scenario: Нет узла выходов

- **WHEN** в графе составного узла нет узла вида `outputs`
- **THEN** проверка сообщает об ошибке отсутствующего узла выходов

### Requirement: Сигнал

Сигнал SHALL быть составным узлом ровно с одним объявленным выходом логического типа — «вход сейчас». Составной узел с
другим числом выходов или с выходом другого типа MUST отклоняться при чтении как сигнал.

#### Scenario: Сигнал H0001

- **WHEN** как сигнал читается граф: последняя выплата фандинга ≥ `0.0005`, а её значение на прошлом закрытии < `0.0005`,
  оба условия через `and` — в выход `entry` логического типа
- **THEN** чтение возвращает сигнал без ошибок

#### Scenario: Числовой выход

- **WHEN** как сигнал читается составной узел с единственным выходом числового типа
- **THEN** чтение возвращает ошибку: у сигнала ровно один логический выход

#### Scenario: Два выхода

- **WHEN** как сигнал читается составной узел с выходами `long` и `short`
- **THEN** чтение возвращает ошибку: у сигнала ровно один логический выход

### Requirement: Отчёт об ошибках проверки

Проверка SHALL возвращать все найденные ошибки сразу, а не только первую. Каждая ошибка SHALL содержать узел, пин,
настройку или поле, если они есть, и причину.

#### Scenario: Несколько ошибок

- **WHEN** в графе одновременно есть несовместимый провод и вход без значения
- **THEN** проверка возвращает обе ошибки, каждую со своим узлом и пином
