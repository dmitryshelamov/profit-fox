# 0010. Изменения — через OpenSpec, решения — в ADR

Дата: 2026-11-17. Решил владелец (запустил OpenSpec в репозитории). Заменяет ADR 0009 репозитория `profit-fox-bench`
(«процесс без OpenSpec»).

## Обстоятельства

Python-стенд обходился без OpenSpec: маленький инструмент, план по этапам. В этом репозитории живёт продукт, и изменения
поведения в нём, как в `profit-fox-market-data`, нужно описывать требованиями и сценариями.

## Решение

- Изменение поведения — изменение OpenSpec в `openspec/changes/`: предложение, спецификации, дизайн, задачи. После слияния
  оно архивируется, а его требования переходят в `openspec/specs/`.
- Решение об архитектуре или методе стенда — ADR в `docs/adr/`. Изменённое решение — новый ADR, который заменяет старый;
  старый не правится.
- Гипотеза стенда — не изменение OpenSpec: это файл в `bench/hypotheses/` и запись в журнале.

## Почему

- Требования со сценариями — то, по чему проверяется продукт и пишутся тесты.
- ADR отвечает на «почему так», которого спецификация не хранит.

## Следствия

- Документы OpenSpec — на русском, код и идентификаторы в них — на английском (`openspec/config.yaml`).
