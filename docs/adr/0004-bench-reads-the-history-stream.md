# 0004. Стенд читает историю потоком из сервиса данных

Дата: 2026-11-17. Решил владелец («история не меняется», «читаем от и до по границам дат»). Заменяет ADR 0002, 0006 и 0010
репозитория `profit-fox-bench` (снимок в Parquet, доступ к базе по SSH и через `docker exec`).

## Обстоятельства

Python-стенд копировал данные сервиса в свой снимок Parquet, читая базу через `ssh` и `docker exec`. Сервис данных получил
потоковое чтение истории по gRPC (`profit-fox-market-data`, спецификация `history-stream`): покрытие инструментов, затем
строки только из покрытых окон, в постоянном порядке.

## Решение

Стенд читает историю на каждом прогоне через поток `History` сервиса данных. Снимка нет.

- Стенд считает только по полностью покрытым окнам периода; неполное покрытие даёт вердикт «данных мало».
- Журнал прогонов хранит хэш прочитанного и список пар; повторный прогон сверяет хэш.
- Даты периодов задаёт код стенда; читатель отказывает в чтении за конец периода. Отложенный период читается только
  командой, которая его открывает и записывается в журнал.
- Сигнал считается на свечах интервала гипотезы, которые сервис собирает сам; минутные свечи читаются только в окнах
  сделок событий и их случайных входов.

## Почему

- Свеча покрытой минуты не меняется, поэтому повторный прогон читает то же; хэш это проверяет.
- Стенду не нужен доступ к базе сервиса, а бэктест бота читает историю тем же потоком.
- Объём умеренный: свечей 4 ч за три года по 500 парам около 3,3 млн; минут в окнах сделок — порядка десятка миллионов.

## Следствия

- Расхождение хэша при повторе — сигнал, что история покрытого окна изменилась; разбирается до следующего вердикта.
- Если перебор сеток станет тяжёлым для soyo-02, стенд добавит локальный кэш окон с ключом «пара, интервал, окно».
