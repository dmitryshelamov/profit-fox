# 0012. Исход плана считает симулятор заявок; рыночная заявка исполняется по первой сделке после неё

Дата: 2026-11-18. Решил владелец (выбрал симулятор заявок вместо отдельного расчёта исхода и одно правило для рыночных
заявок). Агент рекомендовал отдельный расчёт исхода по правилам `outcome.py`. Заменяет в ADR 0009 правило «выход по
сроку — по закрытию последней минуты со сделками»; остальное в ADR 0009 в силе.

## Обстоятельства

Стенду нужен исход сделки по плану (ADR 0006), бэктесту бота — симулятор биржи с заявками и исполнениями. Эталон стенда
на Python (`outcome.py`) считает исход отдельной формулой, и цену в нём вход и выход берут по-разному: вход по открытию
следующей минуты, выход по сроку по закрытию последней минуты срока.

## Решение

- Исход плана считается симулятором заявок `ProfitFox.Engine.Simulation`: план — набор заявок, исход — итог их
  исполнений, комиссий и фандинга. Тот же симулятор потом служит бэктесту бота.
- Рыночная заявка, поставленная в момент T, исполняется целиком по открытию первой минуты со сделками, которая начинается
  не раньше T, с проскальзыванием против стороны заявки. Так исполняются и вход, и выход по сроку.
- Фандинг платится за выплаты в моменты `исполнение входа < t ≤ исполнение выхода` по закрытию минуты перед выплатой.
- Первым в симулятор входит только то, что нужно H0001: рыночная заявка, комиссия тейкера, проскальзывание, фандинг.
  Лимитная и стоп-заявка, а с ними стоп и цель плана, входят вместе с первой гипотезой, где они есть.

## Почему

- Одни правила исполнения у стенда и бота: правило, прошедшее стенд, бэктест исполняет так же.
- У рыночной заявки одно правило цены, и оно не смотрит назад: до момента заявки исполнения нет.

## Отвергнуто

- Отдельный расчёт исхода по формуле `outcome.py`: второе описание исполнения рядом с симулятором бота.
- Выход по сроку по закрытию последней минуты срока, как в Python: у рыночной заявки было бы два правила цены.

## Следствия

- На реальных минутах исход отличается от `outcome.py` на разницу между открытием минуты T и закрытием минуты перед ней.
  Сверка с Python идёт на синтетических путях, где открытие минуты равно закрытию предыдущей.
- Сделке нужна покрытая минута со сделками не раньше конца срока; сделка, у которой её нет, исключается.
- Расхождения Python и симулятора v2 для стопа и цели (порядок внутри минуты, гэп через цель) решаются вместе со стопом и
  целью.
